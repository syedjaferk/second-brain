<p class="wp-block-paragraph"></p><h2 class="wp-block-heading has-large-font-size">Introduction</h2><p class="wp-block-paragraph">Load testing is essential to evaluate how a system behaves under expected and peak loads. Traditionally, we rely on metrics like requests per second (RPS), response time, and error rates. However, an insightful approach called <strong>Average Load Testing</strong> has been discussed recently. This blog explores that concept in detail, providing practical examples to help you apply it effectively.</p><p class="wp-block-paragraph"></p><h2 class="wp-block-heading has-large-font-size">Understanding Average Load Testing</h2><p class="wp-block-paragraph">Average Load Testing focuses on simulating real-world load patterns rather than traditional peak load tests. Instead of sending a fixed number of requests per second, this approach</p><ul class="wp-block-list"><li>Generates requests based on the average concurrency over time.</li><li>More accurately reflects real-world traffic patterns.</li><li>Helps identify performance bottlenecks in a realistic manner.</li></ul><p class="wp-block-paragraph"></p><h2 class="wp-block-heading has-large-font-size">Setting Up Load Testing with K6</h2><p class="wp-block-paragraph">K6 is an excellent tool for implementing Average Load Testing. Let’s go through practical examples of setting up such tests.</p><p class="wp-block-paragraph"></p><h3 class="wp-block-heading has-medium-font-size">Install K6</h3><pre class="wp-block-syntaxhighlighter-code">brew install k6  # macOSsudo apt install k6  # Ubuntu/Debiandocker pull grafana/k6  # Using Docker</pre><p class="wp-block-paragraph"></p><h3 class="wp-block-heading has-medium-font-size">Example 1: Basic K6 Script for Average Load Testing</h3><pre class="wp-block-syntaxhighlighter-code">import http from 'k6/http';import { sleep } from 'k6';export let options = {  scenarios: {    avg_load: {      executor: 'constant-arrival-rate',      rate: 10, // 10 requests per second      timeUnit: '1s',      duration: '2m',      preAllocatedVUs: 20,      maxVUs: 50,    },  },};export default function () {  let res = http.get('https://test-api.example.com');  console.log(`Response time: ${res.timings.duration}ms`);  sleep(1);}</pre><p class="wp-block-paragraph"></p><h3 class="wp-block-heading has-medium-font-size">Explanation</h3><ul class="wp-block-list"><li>The <code>constant-arrival-rate</code> executor ensures a steady request rate.</li><li><code>rate: 10</code> sends 10 requests per second.</li><li><code>duration: '2m'</code> runs the test for 2 minutes.</li><li><code>preAllocatedVUs: 20</code> and <code>maxVUs: 50</code> define virtual users needed to sustain the load.</li><li>The script logs response times to the console.</li></ul><p class="wp-block-paragraph"></p><h2 class="wp-block-heading has-medium-font-size">Example 2: Testing with Varying Load</h2><p class="wp-block-paragraph">To better reflect real-world scenarios, we can use <strong>ramping arrival rate</strong> to simulate gradual increases in traffic</p><p class="wp-block-paragraph"></p><pre class="wp-block-syntaxhighlighter-code">import http from 'k6/http';import { sleep } from 'k6';export let options = {  scenarios: {    ramping_load: {      executor: 'ramping-arrival-rate',      startRate: 5, // Start with 5 requests/sec      timeUnit: '1s',      preAllocatedVUs: 50,      maxVUs: 100,      stages: [        { duration: '1m', target: 20 },        { duration: '2m', target: 50 },        { duration: '3m', target: 100 },      ],    },  },};export default function () {  let res = http.get('https://test-api.example.com');  console.log(`Response time: ${res.timings.duration}ms`);  sleep(1);}</pre><p class="wp-block-paragraph"></p><h3 class="wp-block-heading has-medium-font-size">Explanation</h3><ul class="wp-block-list"><li>The <code>ramping-arrival-rate</code> gradually increases requests per second over time.</li><li>The <code>stages</code> array defines a progression from 5 to 100 requests/sec over 6 minutes.</li><li>Logs response times to help analyze system performance.</li></ul><p class="wp-block-paragraph"></p><h2 class="wp-block-heading has-large-font-size">Example 3: Load Testing with Multiple Endpoints</h2><p class="wp-block-paragraph">In real applications, multiple endpoints are often tested simultaneously. Here’s how to test different API routes</p><p class="wp-block-paragraph"></p><pre class="wp-block-syntaxhighlighter-code">import http from 'k6/http';import { check, sleep } from 'k6';export let options = {  scenarios: {    multiple_endpoints: {      executor: 'constant-arrival-rate',      rate: 15, // 15 requests per second      timeUnit: '1s',      duration: '2m',      preAllocatedVUs: 30,      maxVUs: 60,    },  },};export default function () {  let urls = [    'https://test-api.example.com/users',    'https://test-api.example.com/orders',    'https://test-api.example.com/products'  ];    let res = http.get(urls[Math.floor(Math.random() * urls.length)]);  check(res, {    'is status 200': (r) =&gt; r.status === 200,  });  console.log(`Response time: ${res.timings.duration}ms`);  sleep(1);}</pre><p class="wp-block-paragraph"></p><h3 class="wp-block-heading has-medium-font-size">Explanation</h3><ul class="wp-block-list"><li>The script randomly selects an API endpoint to test different routes.</li><li>Uses <code>check</code> to ensure status codes are 200.</li><li>Logs response times for deeper insights.</li></ul><p class="wp-block-paragraph"></p><h2 class="wp-block-heading has-large-font-size">Analyzing Results</h2><p class="wp-block-paragraph">To analyze test results, you can store logs or metrics in a database or monitoring tool and visualize trends over time. Some popular options include</p><ul class="wp-block-list"><li><strong>Prometheus</strong> for time-series data storage.</li><li><strong>InfluxDB</strong> for handling large-scale performance metrics.</li><li><strong>ELK Stack</strong> (Elasticsearch, Logstash, Kibana) for log-based analysis.</li></ul><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">Average Load Testing provides a more realistic way to measure system performance. By leveraging <strong>K6</strong>, you can create flexible, real-world simulations to optimize your applications effectively.</p><p class="wp-block-paragraph"></p>
