<p class="wp-block-paragraph"></p><p class="wp-block-paragraph">In our previous blog on K6, we ran a script.js to test an api. As an output we received some metrics in the cli.</p><figure class="wp-block-image size-large"><img alt="" class="wp-image-3484" data-recalc-dims="1" decoding="async" height="573" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2025/02/image-10.png?resize=1023%2C573&amp;ssl=1" width="1023"/></figure><p class="wp-block-paragraph">In this blog we are going to delve deep in to understanding metrics in K6. </p><p class="wp-block-paragraph"></p><h2 class="wp-block-heading"><strong>1. HTTP Request Metrics</strong></h2><h3 class="wp-block-heading has-medium-font-size"><strong>http_reqs</strong></h3><ul class="wp-block-list"><li><strong>Description:</strong> Total number of HTTP requests initiated during the test.</li><li><strong>Usage:</strong> Indicates the volume of traffic generated. A high number of requests can simulate real-world usage patterns.</li></ul><h3 class="wp-block-heading has-medium-font-size"><strong>http_req_duration</strong></h3><ul class="wp-block-list"><li><strong>Description:</strong> Time taken for a request to receive a response (in milliseconds).</li><li><strong>Components:</strong><ul class="wp-block-list"><li><strong>http_req_connecting</strong>: Time spent establishing a TCP connection.</li><li><strong>http_req_tls_handshaking</strong>: Time for completing the TLS handshake.</li><li><strong>http_req_waiting (TTFB)</strong>: Time spent waiting for the first byte from the server.</li><li><strong>http_req_sending</strong>: Time taken to send the HTTP request.</li><li><strong>http_req_receiving</strong>: Time spent receiving the response data.</li></ul></li><li><strong>Usage:</strong> Identifies performance bottlenecks like slow server responses or network latency.</li></ul><h3 class="wp-block-heading has-medium-font-size"><strong>http_req_failed</strong></h3><ul class="wp-block-list"><li><strong>Description:</strong> Proportion of failed HTTP requests (ratio between 0 and 1).</li><li><strong>Usage:</strong> Highlights reliability issues. A high failure rate indicates problems with server stability or network errors.</li></ul><p class="wp-block-paragraph"></p><h2 class="wp-block-heading"><strong>2. VU (Virtual User) Metrics</strong></h2><h3 class="wp-block-heading has-medium-font-size"><strong>vus</strong></h3><ul class="wp-block-list"><li><strong>Description:</strong> Number of active Virtual Users at any given time.</li><li><strong>Usage:</strong> Reflects concurrency level. Helps analyze how the system performs under varying loads.</li></ul><h3 class="wp-block-heading has-medium-font-size"><strong>vus_max</strong></h3><ul class="wp-block-list"><li><strong>Description:</strong> Maximum number of Virtual Users during the test.</li><li><strong>Usage:</strong> Defines the peak load. Useful for stress testing and capacity planning.</li></ul><p class="wp-block-paragraph"></p><h2 class="wp-block-heading"><strong>3. Iteration Metrics</strong></h2><h3 class="wp-block-heading has-medium-font-size"><strong>iterations</strong></h3><ul class="wp-block-list"><li><strong>Description:</strong> Total number of script iterations executed.</li><li><strong>Usage:</strong> Measures the test’s progress and workload. Useful in endurance (soak) testing to observe long-term stability.</li></ul><h3 class="wp-block-heading has-medium-font-size"><strong>iteration_duration</strong></h3><ul class="wp-block-list"><li><strong>Description:</strong> Time taken to complete one iteration of the script.</li><li><strong>Usage:</strong> Helps identify performance degradation over time, especially under sustained load.</li></ul><p class="wp-block-paragraph"></p><h2 class="wp-block-heading"><strong>4. Data Transfer Metrics</strong></h2><h3 class="wp-block-heading has-medium-font-size"><strong>data_sent</strong></h3><ul class="wp-block-list"><li><strong>Description:</strong> Total amount of data sent over the network (in bytes).</li><li><strong>Usage:</strong> Monitors network usage. High data volumes might indicate inefficient request payloads.</li></ul><h3 class="wp-block-heading has-medium-font-size"><strong>data_received</strong></h3><ul class="wp-block-list"><li><strong>Description:</strong> Total data received from the server (in bytes).</li><li><strong>Usage:</strong> Detects bandwidth usage and helps identify heavy response payloads.</li></ul><h2 class="wp-block-heading"><strong>5. Custom Metrics (Optional)</strong></h2><p class="wp-block-paragraph">While K6 provides default metrics, you can define custom metrics like <strong>Counters</strong>, <strong>Gauges</strong>, <strong>Rates</strong>, and <strong>Trends</strong> for specific business logic or technical KPIs.</p><h3 class="wp-block-heading"><strong>Example</strong></h3><pre class="wp-block-syntaxhighlighter-code">import { Counter } from 'k6/metrics';let myCounter = new Counter('my_custom_metric');export default function () {  myCounter.add(1); // Increment the custom metric}</pre><p class="wp-block-paragraph"></p><h2 class="wp-block-heading"><strong>Interpreting Metrics for Performance Optimization</strong></h2><ul class="wp-block-list"><li>Low <code>http_req_duration</code> + High <code>http_reqs</code> = Good scalability.</li><li>High <code>http_req_failed</code> = Investigate server errors or timeouts.</li><li>High <code>data_sent</code> / <code>data_received</code> = Optimize payloads.</li><li>Increasing <code>iteration_duration</code> over time = Possible memory leaks or resource exhaustion.</li></ul><p class="wp-block-paragraph"></p>
