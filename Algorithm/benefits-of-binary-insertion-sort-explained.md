<p class="wp-block-paragraph"></p><h2 class="wp-block-heading has-large-font-size" id="heading-introduction">Introduction</h2><p class="wp-block-paragraph">Binary insertion sort is a sorting algorithm similar to insertion sort, but instead of using linear search to find the position where the element should be inserted, we use binary search.</p><p class="wp-block-paragraph">Thus, we reduce the number of comparisons for inserting one element from O(N) (Time complexity in Insertion Sort) to O(log N).</p><p class="wp-block-paragraph"></p><h2 class="wp-block-heading has-large-font-size" id="heading-best-of-two-worlds">Best of two worlds</h2><p class="wp-block-paragraph">Binary insertion sort is a combination of insertion sort and binary search.</p><p class="wp-block-paragraph">Insertion sort is sorting technique that works by finding the correct position of the element in the array and then inserting it into its correct position. Binary search is searching technique that works by finding the middle of the array for finding the element.</p><p class="wp-block-paragraph">As the complexity of binary search is of <em>logarithmic order, the searching algorithm’s time complexity will also decrease to of logarithmic order</em>. Implementation of binary Insertion sort. this program is a simple Insertion sort program but instead of the standard searching technique binary search is used.</p><p class="wp-block-paragraph"></p><h2 class="wp-block-heading has-large-font-size" id="heading-how-binary-insertion-sort-works">How Binary Insertion Sort works ?</h2><h4 class="wp-block-heading" id="heading-process-flow"><a href="https://syedjaferk.hashnode.dev/binary-insertion-sort#heading-process-flow"></a></h4><h3 class="wp-block-heading has-medium-font-size" id="heading-process-flow">Process flow</h3><p class="wp-block-paragraph">In binary insertion sort, we divide the array into <strong>two</strong> subarrays — <strong>sorted and unsorted</strong>. The first element of the array is in the sorted subarray, and the rest of the elements are in the unsorted one.</p><p class="wp-block-paragraph">We then iterate from the second element to the last element. For the i-th iteration, we make the current element our “key.” This key is the element that we have to add to our existing sorted subarray.</p><h4 class="wp-block-heading" id="heading-example"><a href="https://syedjaferk.hashnode.dev/binary-insertion-sort#heading-example"></a></h4><h3 class="wp-block-heading has-medium-font-size" id="heading-example">Example</h3><p class="wp-block-paragraph">Consider the array 29, 10, 14, 37, 14</p><figure class="wp-block-image size-large"><img alt="" class="wp-image-3665" data-recalc-dims="1" decoding="async" height="39" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2025/02/image-20.png?resize=535%2C39&amp;ssl=1" width="535"/></figure><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"><strong>First Pass</strong></p><p class="wp-block-paragraph">Key = 1</p><p class="wp-block-paragraph">Since we consider the first element is in the sorted array, we will be starting from the second element. Then we apply the binary search on the sorted array.</p><figure class="wp-block-image size-large"><img alt="" class="wp-image-3666" data-recalc-dims="1" decoding="async" height="272" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2025/02/image-21.png?resize=577%2C272&amp;ssl=1" width="577"/></figure><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">In this scenario, we can see that the middle element in sorted array (29) is greater than the key element 10. We will apply binary search in the sorted array to find the position of the key element.</p><figure class="wp-block-image size-large"><img alt="" class="wp-image-3672" data-recalc-dims="1" decoding="async" height="156" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2025/02/image-27.png?resize=558%2C156&amp;ssl=1" width="558"/></figure><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">In this scenario, by applying binary search, we can see key element to be placed at index 2 (between 14 and 29). Then we can shift the remaining elements by 1 position.</p><figure class="wp-block-image size-large"><img alt="" class="wp-image-3673" data-recalc-dims="1" decoding="async" height="208" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2025/02/image-28.png?resize=572%2C208&amp;ssl=1" width="572"/></figure><p class="wp-block-paragraph">Now we can see all the elements are sorted.</p><p class="wp-block-paragraph"></p><pre class="wp-block-syntaxhighlighter-code">def binary_search(arr, key, start, end):    if start == end:        if arr[start] &gt; key:            return start        else:            return start+1     if start &gt; end:        return start     mid = (start+end)//2    if arr[mid] &lt; key:        return binary_search(arr, key, mid+1, end)    elif arr[mid] &gt; key:        return binary_search(arr, key, start, mid-1)    else:        return mid def insertion_sort(arr):    total_num = len(arr)    for i in range(1, total_num):        key = arr[i]        j = binary_search(arr, key, 0, i-1)        arr = arr[:j] + [key] + arr[j:i] + arr[i+1:]    return arr sorted_array = insertion_sort([29, 10, 14, 37, 14])print("Sorted Array : ", sorted_array)</pre><p class="wp-block-paragraph"></p><h2 class="wp-block-heading has-large-font-size" id="heading-binary-insertion-sort-algorithm">Psuedocode</h2><p class="wp-block-paragraph">Consider the array <strong>Arr</strong>,</p><ol class="wp-block-list"><li>Iterate the array from the second element to the last element.</li><li>Store the current element Arr[i] in a variable key.</li><li>Find the position of the element just greater than Arr[i] in the subarray from Arr[0] to Arr[i-1] using binary search. Say this element is at index pos.</li><li>Shift all the elements from index pos to i-1 towards the right.</li><li>Arr[pos] = key.</li></ol><h3 class="wp-block-heading" id="heading-complexity-analysis"><a href="https://syedjaferk.hashnode.dev/binary-insertion-sort#heading-complexity-analysis"></a></h3><h2 class="wp-block-heading has-large-font-size" id="heading-complexity-analysis">Complexity Analysis</h2><h4 class="wp-block-heading" id="heading-worst-case"><a href="https://syedjaferk.hashnode.dev/binary-insertion-sort#heading-worst-case"></a></h4><h3 class="wp-block-heading has-medium-font-size" id="heading-worst-case">Worst Case</h3><p class="wp-block-paragraph">For inserting the i-th element in its correct position in the sorted, finding the position (pos) will take O(log i) steps. However, to insert the element, we need to shift all the elements from pos to i-1. This will take i steps in the worst case (when we have to insert at the starting position).</p><p class="wp-block-paragraph">We make a total of N insertions. so, the worst-case time complexity of binary insertion sort is <strong>O(N^2)</strong>.</p><p class="wp-block-paragraph">This occurs when the array is initially sorted in descending order.</p><h4 class="wp-block-heading" id="heading-best-case"><a href="https://syedjaferk.hashnode.dev/binary-insertion-sort#heading-best-case"></a></h4><h3 class="wp-block-heading has-medium-font-size" id="heading-best-case">Best Case</h3><p class="wp-block-paragraph">The best case will be when the element is already in its sorted position. In this case, we don’t have to shift any of the elements; we can insert the element in O(1).</p><p class="wp-block-paragraph">But we are using binary search to find the position where we need to insert. If the element is already in its sorted position, binary search will take (log i) steps. Thus, for the i-th element, we make (log i) operations, so its best-case time complexity is <strong>O(N log N).</strong></p><p class="wp-block-paragraph">This occurs when the array is initially sorted in ascending order.</p><h4 class="wp-block-heading" id="heading-average-case"><a href="https://syedjaferk.hashnode.dev/binary-insertion-sort#heading-average-case"></a></h4><h3 class="wp-block-heading has-medium-font-size" id="heading-average-case">Average Case</h3><p class="wp-block-paragraph">For average-case time complexity, we assume that the elements of the array are jumbled. Thus, on average, we will need O(i /2) steps for inserting the i-th element, so the average time complexity of binary insertion sort is <strong>O(N^2).</strong></p><figure class="wp-block-image size-large"><img alt="" class="wp-image-3676" data-recalc-dims="1" decoding="async" height="98" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2025/02/image-29.png?resize=597%2C98&amp;ssl=1" width="597"/></figure><p class="wp-block-paragraph"></p><h2 class="wp-block-heading has-large-font-size" id="heading-space-complexity-analysis">Space Complexity Analysis</h2><p class="wp-block-paragraph">Binary insertion sort is an in-place sorting algorithm. This means that it only requires a constant amount of additional space. We sort the given array by shifting and inserting the elements.</p><p class="wp-block-paragraph">Therefore, the space complexity of this algorithm is O(1) if we use iterative binary search. It will be O(logN) if we use recursive binary search because of O(log N) recursive calls.</p><h3 class="wp-block-heading" id="heading-is-binary-insertion-sort-a-stable-algorithm"><a href="https://syedjaferk.hashnode.dev/binary-insertion-sort#heading-is-binary-insertion-sort-a-stable-algorithm"></a></h3><h2 class="wp-block-heading has-large-font-size" id="heading-is-binary-insertion-sort-a-stable-algorithm">Is Binary Insertion Sort a stable algorithm</h2><p class="wp-block-paragraph">It is a stable sorting algorithm, the elements with the same values appear in the same order in the final array as they were in the initial array.</p><h3 class="wp-block-heading" id="heading-cons-and-pros"><a href="https://syedjaferk.hashnode.dev/binary-insertion-sort#heading-cons-and-pros"></a></h3><h2 class="wp-block-heading has-large-font-size" id="heading-cons-and-pros">Cons and Pros</h2><ol class="wp-block-list"><li>Binary insertion sort works efficiently for smaller arrays.</li><li>This algorithm also works well for almost-sorted arrays, where the elements are near their position in the sorted array.</li><li>However, when the size of the array is large, the binary insertion sort doesn’t perform well. We can use other sorting algorithms like merge sort or quicksort in such cases.</li><li>Making fewer comparisons is also one of the strengths of this sorting algorithm; therefore, it is efficient to use it when the cost of comparison is high.</li><li>Its efficient when the cost of comparison between keys is sufficiently high. For example, if we want to sort an array of strings, the comparison operation of two strings will be high.</li></ol><h3 class="wp-block-heading" id="heading-bonus-section"><a href="https://syedjaferk.hashnode.dev/binary-insertion-sort#heading-bonus-section"></a></h3><h2 class="wp-block-heading has-large-font-size" id="heading-bonus-section">Bonus Section</h2><p class="wp-block-paragraph">Binary Insertion Sort has a quadratic time complexity just as Insertion Sort. Still, it is usually faster than Insertion Sort in practice, which is apparent when comparison takes significantly more time than swapping two elements.</p>
