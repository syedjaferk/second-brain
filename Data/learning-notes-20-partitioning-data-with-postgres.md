<p class="wp-block-paragraph"></p><p class="wp-block-paragraph">Early Morning today, i watched a video on partitioning and sharding. In that video, Arpit explained the limitation of Vertical Scaling and ways to infinite scale DB with Sharding and Partitioning.  In this blog, i jot down notes on partioining with single node implementation with postgres for my future self. </p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">As the volume of data grows, managing databases efficiently becomes critical and when we understood that vertical scaling has its limits, we have two common strategies to handle large datasets are <strong>partitioning</strong> and <strong>sharding</strong>. While they may sound similar, these techniques serve different purposes and are implemented differently. Let’s explore these concepts in detail.</p><p class="wp-block-paragraph"></p><h2 class="wp-block-heading"><strong>What is Partitioning?</strong></h2><p class="wp-block-paragraph">Partitioning involves dividing a large dataset into smaller, manageable segments, known as partitions. Each partition is stored separately but remains part of a single database instance. Partitioning is typically used to improve query performance and manageability.</p><figure class="wp-block-image aligncenter size-large"><img alt="" class="wp-image-2035" data-recalc-dims="1" decoding="async" height="885" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/12/image-40.png?resize=1400%2C885&amp;ssl=1" width="1400"/></figure><p class="wp-block-paragraph"></p><h2 class="wp-block-heading"><strong><em>Types of Partitioning</em></strong></h2><h3 class="wp-block-heading">1. <strong>Range Partitioning</strong></h3><ul class="wp-block-list"><li>Data is divided based on ranges of a column’s values.</li><li>Example: A table storing customer orders might partition data by order date: January orders in one partition, February orders in another.</li></ul><figure class="wp-block-image aligncenter size-large"><img alt="" class="wp-image-2038" data-recalc-dims="1" decoding="async" height="190" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/12/image-41.png?resize=499%2C190&amp;ssl=1" width="499"/></figure><p class="wp-block-paragraph">PostgreSQL Example</p><pre class="wp-block-syntaxhighlighter-code">CREATE TABLE orders (    id SERIAL,    customer_id INT,    order_date DATE NOT NULL,    PRIMARY KEY (id, order_date) -- Include the partition key) PARTITION BY RANGE (order_date);CREATE TABLE orders_jan PARTITION OF orders    FOR VALUES FROM ('2024-01-01') TO ('2024-02-01');CREATE TABLE orders_feb PARTITION OF orders    FOR VALUES FROM ('2024-02-01') TO ('2024-03-01');</pre><p class="wp-block-paragraph"></p><h3 class="wp-block-heading">2. <strong>Hash Partitioning</strong></h3><ul class="wp-block-list"><li>A hash function determines the partition where a record will be stored.</li><li>Example: Orders can be distributed across partitions based on the hash of the customer ID.</li></ul><figure class="wp-block-image size-large"><img alt="" class="wp-image-2042" data-recalc-dims="1" decoding="async" height="664" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/12/image-42.png?resize=1624%2C664&amp;ssl=1" width="1624"/></figure><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"><strong>Postgres Example</strong></p><pre class="wp-block-syntaxhighlighter-code">CREATE TABLE orders (    id SERIAL ,    customer_id INT,    order_date DATE NOT NULL,    PRIMARY KEY (id, customer_id)) PARTITION BY HASH (customer_id, id);CREATE TABLE orders_part_1 PARTITION OF orders    FOR VALUES WITH (MODULUS 2, REMAINDER 0);CREATE TABLE orders_part_2 PARTITION OF orders    FOR VALUES WITH (MODULUS 2, REMAINDER 1);</pre><p class="wp-block-paragraph"></p><h3 class="wp-block-heading">3. List Partitioning</h3><ul class="wp-block-list"><li>Data is divided based on a predefined list of values.</li><li>Example: A table storing sales data could partition based on regions: North, South, East, and West</li></ul><figure class="wp-block-image size-large"><img alt="" class="wp-image-2046" data-recalc-dims="1" decoding="async" height="622" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/12/image-43.png?resize=1160%2C622&amp;ssl=1" width="1160"/></figure><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"><strong>Postgres Example</strong></p><pre class="wp-block-syntaxhighlighter-code">CREATE TABLE sales (    id SERIAL ,    region TEXT NOT NULL,    amount NUMERIC,    PRIMARY KEY (id, region)) PARTITION BY LIST (region);CREATE TABLE sales_north PARTITION OF sales    FOR VALUES IN ('North');CREATE TABLE sales_south PARTITION OF sales    FOR VALUES IN ('South');</pre><p class="wp-block-paragraph"></p><h3 class="wp-block-heading">4. <strong>Composite Partitioning</strong></h3><ul class="wp-block-list"><li>Combines two or more partitioning strategies, such as range and list partitioning.</li><li><em>Example:</em> A table partitioned by range on order date and sub-partitioned by list on region.</li></ul><p class="wp-block-paragraph"></p><figure class="wp-block-image aligncenter size-large"><img alt="" class="wp-image-2050" data-recalc-dims="1" decoding="async" height="508" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/12/image-44.png?resize=862%2C508&amp;ssl=1" width="862"/></figure><p class="wp-block-paragraph"><strong>Postgres Example</strong></p><pre class="wp-block-syntaxhighlighter-code">CREATE TABLE orders (    id SERIAL,    customer_id INT,    order_date DATE NOT NULL,    region TEXT NOT NULL,    PRIMARY KEY (id, order_date, region)) PARTITION BY RANGE (order_date);CREATE TABLE orders_2024 PARTITION OF orders    FOR VALUES FROM ('2024-01-01') TO ('2025-01-01')    PARTITION BY LIST (region);CREATE TABLE orders_2024_north PARTITION OF orders_2024    FOR VALUES IN ('North');CREATE TABLE orders_2024_south PARTITION OF orders_2024    FOR VALUES IN ('South');</pre><p class="wp-block-paragraph"></p>
