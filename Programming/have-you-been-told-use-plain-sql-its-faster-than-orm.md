<p class="wp-block-paragraph"></p><p class="wp-block-paragraph">You might have heard this advice before,</p><blockquote class="wp-block-quote is-layout-flow wp-block-quote-is-layout-flow"><p class="wp-block-paragraph">Just use SQL; no need for ORMs.</p></blockquote><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">At first glance, that sounds elegant. SQL is expressive, close to the metal, and avoids the “magic” of an ORM.</p><p class="wp-block-paragraph">But as systems grow, <em>accidental complexity</em> sneaks in, the kind that comes not from business logic, but from all the supporting structure you build around “just SQL.”</p><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">The Simple Case SQL Feels Easy Peasy</h2><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">Let’s say you want to fetch all users, </p><pre class="wp-block-syntaxhighlighter-code">import sqlite3conn = sqlite3.connect("users.db")cursor = conn.cursor()cursor.execute("SELECT username, email FROM users")rows = cursor.fetchall()for row in rows:    print(row)</pre><p class="wp-block-paragraph">Simple and clear just SQL, no magic.</p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">Now, you add a filter</p><pre class="wp-block-syntaxhighlighter-code">email = "contact.syedjafer@gmail.com"cursor.execute(f"SELECT username, email FROM users WHERE email = '{email}'")rows = cursor.fetchall()</pre><p class="wp-block-paragraph">Still fine, right?</p><p class="wp-block-paragraph"><br/>Well… not really.</p><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">SQL Injection Appears<br/></h2><p class="wp-block-paragraph">Let’s imagine a malicious user enters this input,</p><pre class="wp-block-syntaxhighlighter-code">email = "'; DROP TABLE users; --"</pre><p class="wp-block-paragraph">That innocent-looking string would destroy your table.</p><p class="wp-block-paragraph"><br/>So you switch to <strong>parameterized queries</strong>,</p><p class="wp-block-paragraph"></p><pre class="wp-block-syntaxhighlighter-code">email = "'; DROP TABLE users; --"cursor.execute("SELECT username, email FROM users WHERE email = ?", (email,))rows = cursor.fetchall()</pre><p class="wp-block-paragraph">Now you’re safe</p><p class="wp-block-paragraph"><br/>But as soon as you add more optional filters like <code>username</code>, <code>created_at</code>, <code>age</code>, etc. your SQL builder starts to look… less simple.</p><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">The Complexity Creeps In</h2><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">You now need to dynamically build WHERE clauses,</p><pre class="wp-block-syntaxhighlighter-code">filters = {"username": "syed", "age": 28}query = "SELECT username, email, age FROM users WHERE 1=1"params = []for key, value in filters.items():    query += f" AND {key} = ?"    params.append(value)cursor.execute(query, params)rows = cursor.fetchall()</pre><p class="wp-block-paragraph">You just wrote your own <em>mini ORM</em>.</p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">Tomorrow, you’ll add support for <code>LIKE</code>, <code>&gt;</code>, <code>&lt;</code>, <code>BETWEEN</code>, and pagination.</p><p class="wp-block-paragraph"><br/>You’ll refactor it into a helper class.<br/></p><p class="wp-block-paragraph">You’ll test it.</p><p class="wp-block-paragraph"><br/>And slowly… you’ll realize, It’s no longer “just SQL.”</p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">Accidental Complexity Explained</h2><p class="wp-block-paragraph">In other words plain SQL is perfect <em>until</em> your usecase stops being trivial.</p><p class="wp-block-paragraph"><br/>When filters, sorting, joins, and pagination start piling up, you end up  re-implementing features ORMs already solved years ago. </p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">That’s called <strong>accidental complexity</strong> complexity born out of solving infrastructure problems, not business problems</p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">Take is , Use SQL for complex queries and ORM for the rest. </p><pre class="wp-block-syntaxhighlighter-code">from sqlalchemy import create_engine, Column, Integer, Stringfrom sqlalchemy.orm import declarative_base, Sessionengine = create_engine("sqlite:///users.db")Base = declarative_base()class User(Base):    __tablename__ = "users"    id = Column(Integer, primary_key=True)    username = Column(String)    email = Column(String)    age = Column(Integer)# Querying with ORMwith Session(engine) as session:    users = session.query(User).filter(User.email == "syed@example.com").all()    for user in users:        print(user.username, user.email)</pre><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">No manual query strings.</p><p class="wp-block-paragraph"><br/>Automatic escaping.</p><p class="wp-block-paragraph"><br/>Refactor-friendly.</p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">Of course, you pay with abstraction overhead the ORM hides the SQL layer from you.</p><p class="wp-block-paragraph"><br/>But when your system grows, this tradeoff often becomes worth it.</p><p class="wp-block-paragraph"></p><figure class="wp-block-table"><table class="has-fixed-layout"><thead><tr><th>When to Use Plain SQL</th><th>When to Use ORM</th></tr></thead><tbody><tr><td>Small scripts or one-off tools</td><td>Large apps with many models</td></tr><tr><td>Static queries</td><td>Complex, dynamic filtering</td></tr><tr><td>You need total control over performance</td><td>You want fast iteration and less boilerplate</td></tr><tr><td>Database skills are strong</td><td>You’re working in a team with mixed expertise</td></tr><tr><td>Schema changes are rare</td><td>Schema evolves frequently<br/><br/><br/><br/></td></tr></tbody></table></figure><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">SQL is fine. ORMs are fine. </p><p class="wp-block-paragraph">The question is, What’s the right tool for your current context?</p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">So next time someone says <em>“Just use SQL</em>“, smile and ask , “Sure, but for how long?”</p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"></p>
