<p class="wp-block-paragraph"></p><p class="wp-block-paragraph">K6 is an awesome, simple load testing tool. There are many CLI options available to K6. In this blog i jot down notes on some of the nice options available for testing. </p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">1. You can use the <code>k6 run --vus=10 --duration=30s script.js</code> command to specify the number of virtual users (VUs) and the duration of the test. This can be useful for running tests with different levels of concurrency and for controlling the length of the test.</p><pre class="wp-block-syntaxhighlighter-code">k6 run --vus=10 --duration=30s script.js</pre><ol class="wp-block-list"></ol><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"><em>script.js</em></p><pre class="wp-block-syntaxhighlighter-code">import http from 'k6/http';import { check, sleep } from 'k6'; export let options = {  vus: 10, // Number of virtual users  duration: '10s', // Test duration}; export default function () {  let res = http.get('https://api.restful-api.dev/objects');  check(res, {    'is status 200': (r) =&gt; r.status === 200,  });  sleep(1); // Simulate user wait time}</pre><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"><strong>Explanation</strong></p><ul class="wp-block-list"><li>Runs the test for <strong>30 seconds</strong> with <strong>10 virtual users (VUs)</strong>.</li><li>Simulates concurrent users making requests within the specified time frame.</li></ul><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">2. The <code>k6 run --no-throttle</code> flag can be used to disable the automatic rate limiting that K6 applies to test requests. This can be useful if you want to test the maximum possible load that your system can handle.</p><pre class="wp-block-syntaxhighlighter-code">k6 run --no-throttle script.js</pre><p class="wp-block-paragraph"><strong>Explanation</strong></p><ul class="wp-block-list"><li>The <code>--no-throttle</code> flag disables automatic rate limiting.</li><li>This allows the test to generate as many requests as possible, simulating <strong>peak load conditions</strong>.</li></ul><p class="wp-block-paragraph">By default, k6 applies automatic rate limiting based on system resource constraints, configured VUs, and iteration pacing.</p><p class="wp-block-paragraph">It ensures requests do not exceed defined limits, such as <code>rps</code>, and prevents overloading. The <code>--no-throttle</code> flag disables these internal checks, allowing execution as fast as possible, constrained only by hardware and network capacity.</p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">3. The <code>k6 run --iterations=1000</code> command can be used to specify the number of iterations that K6 should perform during a test. This can be useful if you want to run a fixed number of requests rather than running the test for a fixed duration.</p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">4. The <code>k6 run --no-connection-reuse</code> flag can be used to disable connection reuse during a test. This can be useful for simulating the behavior of real users who are opening new connections for each request. The <code>--no-connection-reuse</code> flag forces k6 to <strong>open a new connection for every request</strong>.</p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">5. The <code>k6 run --rps=1000</code> command can be used to specify the number of requests per second that K6 should send during the test. This can be useful for running tests with a fixed request rate.</p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">6. You can use the <code>--compatibility</code> flag to specify the version of the HTTP/1.1 protocol that K6 should use when making requests. This can be useful if you need to test a system that only supports a specific version of the protocol.</p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">7. The <code>k6 stats</code> command can be used to collect and analyze performance metrics during a test. This can be useful for identifying performance bottlenecks and for understanding how your system is behaving under load.</p><pre class="wp-block-syntaxhighlighter-code">http_reqs......................: 500   100/shttp_req_duration..............: avg=250ms min=100ms max=500ms p(95)=400ms</pre><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">8. K6 has a built-in graphical user interface (GUI) that can be used to visualize the results of a test. You can access the GUI by running the <code>k6 run --ui</code> command and then visiting the URL displayed in the output.</p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"></p>
