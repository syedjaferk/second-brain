<p class="wp-block-paragraph"></p><p class="wp-block-paragraph">Today, i learnt about Expand Contract Pattern from Raul Junco on a <a href="https://www.linkedin.com/posts/raul-junco_refactoring-databases-is-a-different-animal-activity-7282395282170863616-9E54?utm_source=share&amp;utm_medium=member_desktop">linkedin post</a>. This pattern is particularly useful during system migrations, feature rollouts, or refactoring of large systems. It ensures that new functionality can coexist with existing functionality temporarily, allowing for seamless transitions and safe rollbacks if needed.</p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">In this blog, i jot down notes on Expand Contract Pattern, for better understanding. </p><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">What Is the Expand-Contract Pattern?</h2><p class="wp-block-paragraph">The <strong>Expand-Contract Pattern</strong> is a two-phase approach to making changes in software systems. </p><p class="wp-block-paragraph">1. <strong>Expand Phase</strong>: Introduce new functionality alongside the existing functionality without removing the old implementation. This ensures backward compatibility and allows the system to adapt to the new functionality gradually.</p><p class="wp-block-paragraph">2. C<strong>ontract Phase</strong>: Once the new functionality is validated and deemed stable, deprecate and remove the old implementation to streamline the system and reduce technical debt.</p><ol class="wp-block-list"></ol><p class="wp-block-paragraph">The pattern is often used in environments where downtime, disruptions, or complete rewrites are not acceptable, such as production systems, APIs, and distributed architectures.</p><figure class="wp-block-image aligncenter size-large is-resized"><img alt="" class="wp-image-2529" data-recalc-dims="1" decoding="async" height="842" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2025/01/image-70.png?resize=1400%2C842&amp;ssl=1" style="width:742px;height:auto" width="1400"/></figure><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">Key Benefits</h2><ul class="wp-block-list"><li><strong>Backward Compatibility</strong>: Ensures that existing functionality continues to work during the transition.</li><li><strong>Reduced Risk</strong>: Allows for testing and validation of new functionality in a real-world setting without fully committing.</li><li><strong>Safe Rollbacks</strong>: Enables quick reversion to the old functionality in case of issues with the new implementation.</li><li><strong>Incremental Changes</strong>: Encourages smaller, manageable changes instead of large, risky overhauls.</li><li><strong>Improved Collaboration</strong>: Facilitates smoother handoffs between teams during feature rollouts.</li></ul><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">Workflow of the Expand-Contract Pattern</h2><p class="wp-block-paragraph">The Expand-Contract Pattern typically follows these steps, </p><figure class="wp-block-image size-large"><img alt="" class="wp-image-2531" data-recalc-dims="1" decoding="async" height="234" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2025/01/image-71.png?resize=607%2C234&amp;ssl=1" width="607"/></figure><h3 class="wp-block-heading"><strong>1. Expand Phase</strong></h3><p class="wp-block-paragraph">In this phase, the focus is on introducing the new functionality without disrupting the existing system.</p><ul class="wp-block-list"><li><strong>Add New Code</strong>: Implement the new functionality in parallel with the old functionality.</li><li><strong>Feature Flags</strong>: Use feature toggles to control the activation of the new functionality.</li><li><strong>Shadow Testing</strong>: Run the new implementation in the background to compare its outputs with the old implementation (if possible).</li><li><strong>Data Duplication</strong>: If changes involve data, ensure both the old and new data models are updated in sync.</li></ul><h3 class="wp-block-heading"><strong>2. Validation and Monitoring</strong></h3><p class="wp-block-paragraph">During the transition, monitor the system to ensure the new implementation works as expected.</p><ul class="wp-block-list"><li><strong>A/B Testing</strong>: Gradually route a portion of traffic to the new implementation.</li><li><strong>Metrics Collection</strong>: Track performance, error rates, and user feedback for both implementations.</li><li><strong>Iterative Fixes</strong>: Address issues in the new implementation while keeping the old one operational.</li></ul><h3 class="wp-block-heading"><strong>3. Contract Phase</strong></h3><p class="wp-block-paragraph">Once confidence in the new functionality is established, the old implementation is phased out.</p><ul class="wp-block-list"><li><strong>Deprecate Old Code</strong>: Mark the old implementation as deprecated.</li><li><strong>Remove Legacy Code</strong>: Clean up and remove the old implementation after sufficient validation.</li><li><strong>Optimize New Implementation</strong>: Refactor and optimize the new implementation, reducing complexity.</li></ul><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">Practical Example: Using the Expand-Contract Pattern</h2><p class="wp-block-paragraph">Let’s look at an example of applying this pattern to a <strong>database schema migration</strong>, </p><h3 class="wp-block-heading">Scenario</h3><p class="wp-block-paragraph">You need to rename a column <code><em>username</em></code> to <code><em>user_name</em></code> in a production database without downtime.</p><h3 class="wp-block-heading">Step-by-Step Implementation</h3><h4 class="wp-block-heading"><strong><span style="text-decoration: underline">Expand Phase</span></strong></h4><ol class="wp-block-list"><li>Add the new column <code>user_name</code> to the table.</li><li>Update application code to write to both <code>username</code> and <code>user_name</code>.</li><li>Read from <code>username</code> for backward compatibility.</li></ol><h4 class="wp-block-heading"><strong><span style="text-decoration: underline">Validation Phase</span></strong></h4><ol class="wp-block-list"><li>Backfill existing data from <code>username</code> to <code>user_name</code>.</li><li>Shadow test the application to ensure it reads correctly from <code>user_name</code>.</li><li>Monitor logs, metrics, and user feedback for anomalies.</li></ol><h4 class="wp-block-heading"><strong><span style="text-decoration: underline">Contract Phase</span></strong></h4><ol class="wp-block-list"><li>Update application code to read from <code>user_name</code> only.</li><li>Remove references to <code>username</code> in the codebase.</li><li>Drop the <code>username</code> column from the database.</li></ol><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">References</h2><ol class="wp-block-list"><li><a
