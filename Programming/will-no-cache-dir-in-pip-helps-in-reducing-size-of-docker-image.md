<h3 class="wp-block-heading" id="heading-problem-faced">Problem Faced:</h3><p class="wp-block-paragraph">I was trying to reduce the docker size of a python application. In those one of the methods, i was struck by an idea of remove pip caching. So was trying to reduce the size of the docker image in total.</p><h3 class="wp-block-heading" id="heading-what-is-pip-caching"><a href="https://parottasalna.hashnode.dev/will-no-cache-dir-in-pip-helps-in-reducing-size-of-docker-image#heading-what-is-pip-caching"></a>What is pip caching ?</h3><p class="wp-block-paragraph">As per <a href="https://pip.pypa.io/en/stable/topics/caching/" rel="noreferrer noopener" target="_blank">docs</a>,</p><p class="wp-block-paragraph"><mark>When making any HTTP request, pip will first check its local cache to determine if it has a suitable response stored for that request which has not expired. If it does then it returns that response and doesn’t re-download the content.</mark></p><p class="wp-block-paragraph"><mark>If it has a response stored but it has expired, then it will attempt to make a conditional request to refresh the cache which will either return an empty response telling pip to simply use the cached item (and refresh the expiration timer) or it will return a whole new response which pip can then store in the cache.</mark></p><p class="wp-block-paragraph"><mark>While this cache attempts to minimize network activity, it does not prevent network access altogether. If you want a local install solution that circumvents accessing PyPI, see </mark><a href="https://pip.pypa.io/en/stable/user_guide/#installing-from-local-packages" rel="noreferrer noopener" target="_blank"><mark>Installing from local packages</mark></a><mark>.</mark></p><p class="wp-block-paragraph"><em><mark>Changed in version 23.3: </mark></em><mark>A new cache format is now used, stored in a directory called </mark><code>http-v2</code> <mark>(see below for this directory’s location). Previously this cache was stored in a directory called </mark><code>http</code> <mark>in the main cache directory. If you have completely switched to newer versions of </mark><code>pip</code><mark>, you may wish to delete the old directory.</mark></p><p class="wp-block-paragraph">These files will get stored inside</p><ol class="wp-block-list"><li><code>%LocalAppData%\pip\Cache</code> – on Windows</li><li><code>~/Library/Caches/pip</code> – on Mac</li><li><code>~/.cache/pip</code> – on Linux</li></ol><h3 class="wp-block-heading" id="heading-do-we-need-these-cache-inside-a-docker-image"><a href="https://parottasalna.hashnode.dev/will-no-cache-dir-in-pip-helps-in-reducing-size-of-docker-image#heading-do-we-need-these-cache-inside-a-docker-image"></a>Do we need these cache inside a docker image ?</h3><p class="wp-block-paragraph">These caches are stored, such that for future installations, instead of going to hit the network, we can get it from local (to reduce network calls). But as we know, <code>Docker container is a short lived, immutable box</code> where we wont be installing it often. So we don’t need it. We can remove it and lets see whether it reduces the size.</p><h3 class="wp-block-heading" id="heading-how-to-remove-the-cache-during-the-installation"><a href="https://parottasalna.hashnode.dev/will-no-cache-dir-in-pip-helps-in-reducing-size-of-docker-image#heading-how-to-remove-the-cache-during-the-installation"></a>How to remove the cache during the installation ?</h3><p class="wp-block-paragraph">In PIP, we can provide <code>--no-cache-dir</code> flag to avoid storing the files in the image/container.</p><p class="wp-block-paragraph">Lets see with an example,</p><p class="wp-block-paragraph"><strong>requirements.txt</strong></p><pre class="wp-block-syntaxhighlighter-code">Flask==2.0.1gunicorn==20.1.0</pre><p class="wp-block-paragraph"><strong>Dockerfile</strong></p><pre class="wp-block-syntaxhighlighter-code"># Use a minimal base imageFROM python:3.8-slim# Set the working directoryWORKDIR /app# Copy the requirements fileCOPY requirements.txt .# Install dependenciesRUN pip install --no-cache-dir -r requirements.txtCMD ["hostname"]</pre><p class="wp-block-paragraph">ensures that the <code>--no-cache-dir</code> option is passed to <code>pip</code> during the installation of the Python dependencies listed in <code>requirements.txt</code>.</p><h3 class="wp-block-heading" id="heading-comparison-with-and-without-no-cache-dir"><a href="https://parottasalna.hashnode.dev/will-no-cache-dir-in-pip-helps-in-reducing-size-of-docker-image#heading-comparison-with-and-without-no-cache-dir"></a>Comparison: with and without –no-cache-dir</h3><p class="wp-block-paragraph">Tried building the image with and without –no-cache-dir. On checking the below comparison,</p><figure class="wp-block-image"><img alt="" data-recalc-dims="1" decoding="async" src="https://i0.wp.com/cdn.hashnode.com/res/hashnode/image/upload/v1701157974087/694cc317-abeb-42c5-805d-5681e25d380d.png?ssl=1"/></figure><p class="wp-block-paragraph">It seems, we don’t have any drastic reduction in the image size. It adds a minimum support to lean docker image.</p><p class="wp-block-paragraph">But, by using <code>--no-cache-dir</code>, you instruct <code>pip</code> not to use or create a cache directory, which can be useful in the context of Docker builds to avoid potential issues related to cached packages and ensure a more reproducible build.</p><h3 class="wp-block-heading" id="heading-final-thoughts"><a href="https://parottasalna.hashnode.dev/will-no-cache-dir-in-pip-helps-in-reducing-size-of-docker-image#heading-final-thoughts"></a>Final Thoughts</h3><ol class="wp-block-list"><li>By using –no-cache-dir helps a little in image size.</li><li>Its helpful in producing more reproducible builds, helps in resolving one of the <a href="https://iamfullstackdeveloper.hashnode.dev/antipatterns-while-using-docker-containers" rel="noreferrer noopener" target="_blank">anti-pattern</a>.</li></ol>
