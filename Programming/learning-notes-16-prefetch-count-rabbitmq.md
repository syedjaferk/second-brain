<p class="wp-block-paragraph"></p><p class="wp-block-paragraph">Today, i learnt about prefetch count and how it saves consumer from overwhelming of messages. Messages in RabbitMQ are pushed from the broker to the consumers. The RabbitMQ default prefetch setting gives clients an unlimited buffer, meaning that RabbitMQ, by default, sends as many messages as it can to any consumer that appears ready to accept them. It is, therefore, possible to have more than one message “in-flight” on a channel at any given moment.</p><figure class="wp-block-image aligncenter size-large"><img alt="" class="wp-image-1950" data-recalc-dims="1" decoding="async" height="149" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/12/image-23.png?resize=788%2C149&amp;ssl=1" width="788"/></figure><p class="wp-block-paragraph">In this blog, i have curated notes on how prefetch works ,</p><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">What is Prefetch in RabbitMQ?</h2><p class="wp-block-paragraph">Prefetch is a mechanism that defines how many messages can be delivered to a consumer at a time before the consumer sends an acknowledgment back to the broker. This ensures that the consumer does not get overwhelmed with too many unprocessed messages, which could lead to high memory usage and potential performance issues.</p><p class="wp-block-paragraph">By default, RabbitMQ does not limit the number of unacknowledged messages a consumer can receive. While this default behavior works for certain scenarios, it can create bottlenecks in systems where consumers process messages at varying speeds.</p><p class="wp-block-paragraph"></p><h3 class="wp-block-heading">Why is Prefetch Important?</h3><p class="wp-block-paragraph">The prefetch setting directly impacts how efficiently messages are processed in RabbitMQ. Here are some reasons why configuring prefetch is critical:</p><ol class="wp-block-list" start="1"><li><strong>Avoid Overloading Consumers:</strong> Setting an appropriate prefetch value prevents consumers from being overloaded with too many messages, which could degrade performance or even crash the consumer application.</li><li><strong>Fair Message Distribution:</strong> Prefetch helps distribute messages fairly among consumers in a competing-consumer scenario. Without it, faster consumers might hog more messages, leaving slower ones underutilized.</li><li><strong>Improved Throughput:</strong> Properly tuning prefetch can balance the load between consumers and ensure optimal throughput for the system.</li><li><strong>Memory Efficiency:</strong> Limiting the number of unacknowledged messages reduces the risk of excessive memory usage on both the consumer and the broker.</li></ol><h2 class="wp-block-heading">How Prefetch Works</h2><p class="wp-block-paragraph">Prefetch can be set at two levels – Channel Level , Consumer Level</p><h2 class="wp-block-heading">Channel Level</h2><p class="wp-block-paragraph"><strong>Channel Level:</strong> Applies to all consumers on the channel. Setting the prefetch value at this level ensures that the total number of unacknowledged messages across all consumers sharing the same channel does not exceed the specified limit. </p><p class="wp-block-paragraph">The channel prefetch value defines the maximum number of unacknowledged deliveries that are permitted on a channel. Setting a limit on this buffer caps the number of received messages before the broker waits for an acknowledgment.</p><p class="wp-block-paragraph"> Because a single channel may consume from multiple queues, coordination between them is required to ensure that they don’t pass the limit. This can be a slow process especially when consuming across a cluster, and it is not the recommended approach.</p><ol class="wp-block-list" start="1"></ol><pre class="wp-block-syntaxhighlighter-code">import pika# Establish a connection and a channelconnection = pika.BlockingConnection(pika.ConnectionParameters('localhost'))channel = connection.channel()# Set channel-level prefetchchannel.basic_qos(prefetch_count=5, global=True)# Declare and consume from multiple queueschannel.queue_declare(queue='queue1')channel.queue_declare(queue='queue2')def callback(ch, method, properties, body):    print(f"Received: {body}")    ch.basic_ack(delivery_tag=method.delivery_tag)channel.basic_consume(queue='queue1', on_message_callback=callback)channel.basic_consume(queue='queue2', on_message_callback=callback)print("Waiting for messages...")channel.start_consuming()</pre><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">Consumer Level</h2><p class="wp-block-paragraph">Applies to individual consumers. This provides granular control over message delivery to each consumer. The best practice is to set a consumer prefetch by setting a limit on the number of unacked messages at the client.</p><pre class="wp-block-syntaxhighlighter-code">import pika# Establish a connection and a channelconnection = pika.BlockingConnection(pika.ConnectionParameters('localhost'))channel = connection.channel()# Declare a queuechannel.queue_declare(queue='task_queue', durable=True)# Set consumer-level prefetchchannel.basic_qos(prefetch_count=1, global=False)# Define a callback function for message processingdef callback(ch, method, properties, body):    print(f"Received {body}")    # Simulate message processing    time.sleep(1)    print("Done")    ch.basic_ack(delivery_tag=method.delivery_tag)# Consume messageschannel.basic_consume(queue='task_queue', on_message_callback=callback)print("Waiting for messages. To exit press CTRL+C")channel.start_consuming()</pre><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">The key difference in this example is the <code>global=False</code> parameter, which ensures the prefetch count applies only to the individual consumer.</p><h2 class="wp-block-heading">Best Practices for Setting Prefetch</h2><ol class="wp-block-list" start="1"><li><strong>Analyze Consumer Speed:</strong> Determine the average time it takes for a consumer to process a message and set the prefetch value accordingly.</li><li><strong>Monitor System Metrics:</strong> Use RabbitMQ’s management interface or monitoring tools to track unacknowledged messages and adjust the prefetch setting as needed.</li><li><strong>Test and Iterate:</strong> Experiment with different prefetch values to find the optimal configuration for your workload.</li><li><strong>Combine with Acknowledgments:</strong> Always use manual acknowledgments (<code>basic_ack</code>) to ensure that messages are processed successfully before the consumer receives new ones.</li></ol><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">References</h2><ol class="wp-block-list"><li>Rabbitmq Prefetch – <a href="https://www.rabbitmq.com/docs/consumer-prefetch">https://www.rabbitmq.com/docs/consumer-prefetch</a></li><li><a href="https://training.cloudamqp.com/course/37">https://training.cloudamqp.com/course/37</a></li></ol><p class="wp-block-paragraph"></p>
