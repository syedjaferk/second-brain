<p class="wp-block-paragraph"></p><p class="wp-block-paragraph">Today, i learnt about claim check pattern, which tells how to handle a big message into the queue. Every message broker has a defined message size limit. If our message size exceeds the size, it wont work. </p><p class="wp-block-paragraph">The Claim Check Pattern emerges as a pivotal architectural design to address challenges in managing large payloads in a decoupled and efficient manner. In this blog, i jot down notes on my learning for my future self. </p><p class="wp-block-paragraph"></p><h2 class="wp-block-heading"><strong>What is the Claim Check Pattern?</strong></h2><p class="wp-block-paragraph">The Claim Check Pattern is a messaging pattern used in distributed systems to manage large messages efficiently. Instead of transmitting bulky data directly between services, this pattern extracts and stores the payload in a dedicated storage system (e.g., object storage or a database). </p><p class="wp-block-paragraph">A lightweight reference or “claim check” is then sent through the message queue, which the receiving service can use to retrieve the full data from the storage.</p><p class="wp-block-paragraph">This pattern is inspired by the physical process of checking in luggage at an airport: you hand over your luggage, receive a claim check (a token), and later use it to retrieve your belongings.</p><p class="wp-block-paragraph"></p><h2 class="wp-block-heading"><strong>How Does the Claim Check Pattern Work?</strong></h2><figure class="wp-block-image size-large"><img alt="" class="wp-image-2072" data-recalc-dims="1" decoding="async" height="369" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/12/image-47.png?resize=1216%2C369&amp;ssl=1" width="1216"/></figure><p class="wp-block-paragraph">The process typically involves the following steps</p><ol class="wp-block-list" start="1"><li><strong>Data Submission</strong> The sender service splits a message into two parts:<ul class="wp-block-list"><li><strong>Metadata</strong>: A small piece of information that provides context about the data.</li><li><strong>Payload</strong>: The main body of data that is too large or sensitive to send through the message queue.</li></ul></li><li><strong>Storing the Payload</strong><ul class="wp-block-list"><li>The sender uploads the payload to a storage service (e.g., AWS S3, Azure Blob Storage, or Google Cloud Storage).</li><li>The storage service returns a unique identifier (e.g., a URL or object key).</li></ul></li><li><strong>Sending the Claim Check</strong><ul class="wp-block-list"><li>The sender service places the metadata and the unique identifier (claim check) onto the message queue.</li></ul></li><li><strong>Receiving the Claim Check</strong><ul class="wp-block-list"><li>The receiver service consumes the message from the queue, extracts the claim check, and retrieves the payload from the storage system.</li></ul></li><li><strong>Processing</strong><ul class="wp-block-list"><li>The receiver processes the payload alongside the metadata as required.</li></ul></li></ol><p class="wp-block-paragraph"></p><h2 class="wp-block-heading"><strong>Use Cases</strong></h2><p class="wp-block-paragraph"><strong>1. Media Processing Pipelines</strong> In video transcoding systems, raw video files can be uploaded to storage while metadata (e.g., video format and length) is passed through the message queue.</p><p class="wp-block-paragraph"><strong>2. IoT Systems</strong> – IoT devices generate large datasets. Using the Claim Check Pattern ensures efficient transmission and processing of these data chunks.</p><p class="wp-block-paragraph"><strong>3. Data Processing Workflows</strong> – In big data systems, datasets can be stored in object storage while processing metadata flows through orchestration tools like Apache Airflow.</p><p class="wp-block-paragraph"><strong>4. Event-Driven Architectures</strong> – For systems using event-driven models, large event payloads can be offloaded to storage to avoid overloading the messaging layer.</p><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">Example with RabbitMQ</h2><p class="wp-block-paragraph">1.Sender Service</p><pre class="wp-block-syntaxhighlighter-code">import boto3import pikas3 = boto3.client('s3')bucket_name = 'my-bucket'object_key = 'data/large-file.txt'response = s3.upload_file('large-file.txt', bucket_name, object_key)claim_check = f's3://{bucket_name}/{object_key}'# Connect to RabbitMQconnection = pika.BlockingConnection(pika.ConnectionParameters('localhost'))channel = connection.channel()# Declare a queuechannel.queue_declare(queue='claim_check_queue')# Send the claim checkmessage = {    'metadata': 'Some metadata',    'claim_check': claim_check}channel.basic_publish(exchange='', routing_key='claim_check_queue', body=str(message))connection.close()</pre><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">2. Consumer</p><pre class="wp-block-syntaxhighlighter-code">import boto3import pikas3 = boto3.client('s3')# Connect to RabbitMQconnection = pika.BlockingConnection(pika.ConnectionParameters('localhost'))channel = connection.channel()# Declare a queuechannel.queue_declare(queue='claim_check_queue')# Callback function to process messagesdef callback(ch, method, properties, body):    message = eval(body)    claim_check = message['claim_check']    bucket_name, object_key = claim_check.replace('s3://', '').split('/', 1)    s3.download_file(bucket_name, object_key, 'retrieved-large-file.txt')    print("Payload retrieved and processed.")# Consume messageschannel.basic_consume(queue='claim_check_queue', on_message_callback=callback, auto_ack=True)print('Waiting for messages. To exit press CTRL+C')channel.start_consuming()</pre><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">References</h2><ol class="wp-block-list"><li><a href="https://learn.microsoft.com/en-us/azure/architecture/patterns/claim-check">https://learn.microsoft.com/en-us/azure/architecture/patterns/claim-check</a></li><li><a href="https://medium.com/@dmosyan/claim-check-design-pattern-603dc1f3796d">https://medium.com/@dmosyan/claim-check-design-pattern-603dc1f3796d</a></li><li></li></ol>
