<p class="wp-block-paragraph">If you work in web development, you likely use <strong>NPM</strong> (Node PM or New PM) all the time. It is a free public software registry – the largest in the world that is accessible at the type of <code>npm install</code> in your command prompt so long as you have node.js installed already. </p><p class="wp-block-paragraph">Whenever we try to create a new project we will see a <code>package.json</code> file will be created. Whenever we install any packages <code>package-lock.json</code> file and <code>node_modules</code> folder will be created. In this blog post, we will see on <strong><a href="https://semver.org/">SemVer</a></strong>, the purpose of package.json and package-lock.json and the internal functioning of npm install.</p><h3 class="wp-block-heading" id="heading-what-is-versioning">What is versioning?</h3><p class="wp-block-paragraph">The Node.js ecosystem uses <strong>SemVer</strong>, which is not mandatory but is strongly encouraged. This feature isn’t necessary for an unpublished package. Maintaining the version field of a package used as a dependency is critical to ensuring that others use the correct version of a package.</p><p class="wp-block-paragraph">There are three elements to a version:</p><ul class="wp-block-list"><li>major (significant changes in the version)</li><li>minor (adding new features )</li><li>patch (a bug fix)</li></ul><figure class="wp-block-image aligncenter size-large"><img alt="" class="wp-image-172" data-recalc-dims="1" decoding="async" height="373" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/06/image-15.png?resize=725%2C373&amp;ssl=1" width="725"/></figure><p class="wp-block-paragraph">There also two prefix symbols present in the semver. It’s the deciding factor what release to be updated ( either patch, minor ). </p><ol class="wp-block-list"><li>Caret (^) – Allow npm to upgrade minor and patch versions if they are available.</li><li>Tilde (~) – Allow npm to upgrade only patch versions if they are available.</li></ol><p class="wp-block-paragraph">For Example,</p><p class="wp-block-paragraph">Consider the package express, with version-&gt; ^4.17.1 -&gt; If there are any minor versions available say 4.18.0 then npm is allowed to update to 4.18.0.</p><figure class="wp-block-image aligncenter size-large"><img alt="" class="wp-image-174" data-recalc-dims="1" decoding="async" height="370" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/06/image-16.png?resize=628%2C370&amp;ssl=1" width="628"/></figure><p class="wp-block-paragraph">But in the case of ~, even if the 4.18.0 version is available, npm won’t upgrade to 4.18.0.</p><figure class="wp-block-image aligncenter size-large"><img alt="" class="wp-image-176" data-recalc-dims="1" decoding="async" height="360" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/06/image-17.png?resize=669%2C360&amp;ssl=1" width="669"/></figure><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">Now let’s come to our topic package.json and package-lock.json. </p><h3 class="wp-block-heading">Package.json</h3><p class="wp-block-paragraph">package.json is an important file, which is been used to install the packages required for the node projects.</p><h4 class="wp-block-heading" id="heading-how-it-is-created">How it is created?</h4><p class="wp-block-paragraph"><code>package.json</code> is a file that gets generated when we are initializing the npm project (<code>npm init -y</code>)</p><figure class="wp-block-image size-large"><img alt="" class="wp-image-178" data-recalc-dims="1" decoding="async" height="638" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/06/image-18.png?resize=568%2C638&amp;ssl=1" width="568"/></figure><p class="wp-block-paragraph">It contains, </p><pre class="wp-block-syntaxhighlighter-code">{  "name": "node-projects",  "version": "1.0.0",  "description": "",  "main": "index.js",  "scripts": {    "test": "echo \"Error: no test specified\" &amp;&amp; exit 1"  },  "keywords": [],  "author": "",  "license": "ISC",  "dependencies": {    "express": "^4.18.1"  }}</pre><ol class="wp-block-list"><li>Package.json is a list of all the dependencies of a project. This includes version info (with upgradation feasibility caret ^ and tilde ~ ) for what needs to be downloaded.</li><li>It keeps the minimum version an application needs.</li><li>It also contains details on project properties, description, author &amp; license information, scripts to run via npm, etc.</li></ol><p class="wp-block-paragraph"><strong>Properties inside package.json</strong></p><p class="wp-block-paragraph"><strong>1. name</strong> property: Name of the module.<br/><strong>2. version</strong> property: Current version of the module.<br/><strong>3. license</strong> property: Licence of the project (eg. MIT, GPL-3.0, BSD-3).<br/><strong>4. description</strong> property: Description of the module given by the developer.<br/><strong>5. keywords</strong> property: Related keywords of the module.<br/><strong>6. main</strong> property: specify the direction to the entry point to the module package.json is describing.<br/><strong>7. repository</strong> property (optional): Details about the cloud repository (eg: git)<br/><strong>8. scripts</strong> property: It takes an object with as many key (category)/value (commands) pairs.</p><p class="wp-block-paragraph"><strong>9. dependencies</strong> property: The other modules that this module uses – are defined. The dependencies property takes an object that has the name and version at which each dependency should be used. Do note that you’ll frequently find carets (^) and tildes (~) included with package versions. (It’s for production).<br/><strong>10. devDependencies</strong> property: Used to define dependencies to run in development.</p><h3 class="wp-block-heading" id="heading-package-lockjson-exact-version-of-the-installed-package">package-lock.json (Exact version of the installed package)</h3><p class="wp-block-paragraph">package-lock.json is an auto-generated document during installation. It looks a lot like the package.json dependencies but with more information when you open it.</p><figure class="wp-block-image size-large"><img alt="" class="wp-image-182" data-recalc-dims="1" decoding="async" height="248" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/06/image-19.png?resize=831%2C248&amp;ssl=1" width="831"/></figure><p class="wp-block-paragraph">package-lock.json describes the <strong>exact tree</strong> that was generated, such that subsequent installs are able to generate identical trees, regardless of intermediate dependency updates.</p><p class="wp-block-paragraph">As you can see in the below image, package-lock.json won’t contain ^ or ~. It will have the exact version of the installed package. While package.json will have the minimum version needed to run the project.</p><figure class="wp-block-image size-large"><img alt="" class="wp-image-183" data-recalc-dims="1" decoding="async" height="273" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/06/image-20.png?resize=897%2C273&amp;ssl=1" width="897"/></figure><h4 class="wp-block-heading" id="heading-how-it-is-created">How it is created?</h4><p class="wp-block-paragraph"><code>package-lock.json</code> is automatically generated for any operations where npm modifies either the node_modules tree or package.json. Eg. during npm install.</p><figure class="wp-block-image size-large"><img alt="" class="wp-image-184" data-recalc-dims="1" decoding="async" height="248" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/06/image-21.png?resize=831%2C248&amp;ssl=1" width="831"/></figure><h4 class="wp-block-heading" id="heading-what-it-contains">What it contains?</h4><p class="wp-block-paragraph">Let’s take a look,</p><figure class="wp-block-image size-large"><img alt="" class="wp-image-185" data-recalc-dims="1" decoding="async" height="306" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/06/image-22.png?resize=665%2C306&amp;ssl=1" width="665"/></figure><ol class="wp-block-list"><li>package-lock.json is used to avoid differences in installed dependencies on different environments and generate the same results in every environment.</li><li>NPM installs exact versions of the package as saved in package-lock.json and ignores the symbol ^ and ~ from package.json so as to avoid installing the latest/updated version of the package which might break the application if the application codebase is not compatible with the updated version of packages.</li><li>It contains other meta information of packages to save the time of fetching that data from npm when installing any package using npm install.</li><li>It allows npm to skip repeated metadata resolutions for previously installed packages and hence optimizes the installation process.</li></ol><p class="wp-block-paragraph"><strong>Properties inside package-lock.json</strong></p><p class="wp-block-paragraph"><strong>1. name</strong> property: name of the module. It will match the name property in package.json.<br/><strong>2. version</strong> property: The version of the package this is a package-lock for. This will match what’s in package.json.<br/><strong>3. lockfileVersion</strong> property: It’s an integer value. Either 1, 2, or 3.</p><ul class="wp-block-list"><li>1: The lockfile version used by npm v5 and v6.</li><li>2: The lockfile version used by npm v7, which is backward compatible with v1 lock files.</li><li>3: The lockfile version used by npm v7, without backward compatibility affordances. This is used for the hidden lockfile at node_modules/.package-lock.json, and will likely be used in a future version of npm, once support for npm v6 is no longer relevant.</li></ul><p class="wp-block-paragraph"><strong>4. packages</strong> property: It is an object that maps package locations to an object containing the information about that package.</p><p class="wp-block-paragraph">Eg:</p><pre class="wp-block-preformatted">     "node_modules/etag": {      "version": "1.8.1",      "resolved": "<a href="https://registry.npmjs.org/etag/-/etag-1.8.1.tgz" rel="noreferrer noopener" target="_blank">registry.npmjs.org/etag/-/etag-1.8.1.tgz</a>",      "integrity": "sha512-aIL5Fx7mawVa300al2BnEE4iNvo1qETxLrPI/o05L7z6go7fCw1J6EQmbK4FmJ2AS7kgVF/KEZWufBfdClMcPg==",      "engines": {        "node": "&gt;= 0.6"      }    },</pre><p class="wp-block-paragraph"><strong>5. dependencies</strong> property: Its a mapping of package names to dependency objects</p><h3 class="wp-block-heading"></h3>
