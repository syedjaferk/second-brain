<p class="wp-block-paragraph">Its an Application level caching, where the application checks whether the data is present in the cache (In our case redis). If data is present it returns the data. Else checks from the database and stores it in Cache and then returns the data to client.</p><figure class="wp-block-image size-large"><img alt="" class="wp-image-56" data-recalc-dims="1" decoding="async" height="603" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/06/image-2.png?resize=1005%2C603&amp;ssl=1" width="1005"/></figure><h3 class="wp-block-heading" id="heading-steps"><a href="https://parottasalna.com/redis-cache-aside-pattern#heading-steps"></a>Steps:</h3><ol class="wp-block-list"><li>The Application (Fast API), checks whether the requested data is present in the cache (redis).</li><li>If the data present in the cache (redis) it gets the data and returns the value.</li><li>If the data is not present in the cache (cache miss), it will check the details from the primary database (mongodb).</li><li>If the data is available it returns the data to the application.</li><li>The application now sets the data to Cache for future hits (cache hit).</li></ol><blockquote class="wp-block-quote is-layout-flow wp-block-quote-is-layout-flow"><p class="wp-block-paragraph">Cache Hit: If the requested data is present in the cache.</p><p class="wp-block-paragraph">Cache Miss: If the requested data is not present in the cache.</p></blockquote><p class="wp-block-paragraph"></p><h3 class="wp-block-heading" id="heading-implementation">Implementation</h3><blockquote class="wp-block-quote is-layout-flow wp-block-quote-is-layout-flow"><p class="wp-block-paragraph">Github: <a href="https://github.com/syedjaferk/redis-cache" rel="noreferrer noopener" target="_blank">https://github.com/syedjaferk/redis-cache</a></p></blockquote><p class="wp-block-paragraph">We are going to create a mock todo application. href="https://parottasalna.com/redis-cache-aside-pattern#heading-drawbacks"></a>Drawbacks</h3><ol class="wp-block-list"><li>For every request there is a cache miss. If the requested items aren’t repeating in a good percentage, then this will create latency.</li><li>What happens if the record been updated in the database, but not in redis. Do we need to write on every update ?</li><li>In a distributed system, if a node fails, it will be replaced by a new empty node. This will increase the latency. (<em>this can be overcomed with replication of the data).</em></li><li>If your application is a <strong>write-heavy</strong> workload, then this will add a good latency.</li></ol><h3 class="wp-block-heading" id="heading-when-to-use"><a href="https://parottasalna.com/redis-cache-aside-pattern#heading-when-to-use"></a>When to use ?</h3><ol class="wp-block-list"><li>If your application is read heavy, then you can go with this approach.</li><li>If your application is not having any dynamic change of data, then this approach will be a good one.</li></ol>
