<p class="wp-block-paragraph">Its an Application level caching, where the application reads the data from cache. If the data not present in the cache it will read from database and updates the cache and sends the result to the application.</p><figure class="wp-block-image size-large is-resized"><img alt="" class="wp-image-26" data-recalc-dims="1" decoding="async" height="559" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/06/image.png?resize=983%2C559&amp;ssl=1" style="width:814px;height:auto" width="983"/></figure><p class="wp-block-paragraph"></p><h3 class="wp-block-heading" id="heading-steps">Steps:</h3><ol class="wp-block-list"><li>The Application (fastapi) checks whether the key is present in redis.</li><li>If the key is existing in redis, then it will return the value.</li><li>If the key is not present then redis will communicate to primary database (here mongodb) to get the value.</li><li>Then the result will be set into the redis.</li><li>And then it will be returned to the application.</li></ol><h3 class="wp-block-heading" id="heading-implementation">Implementation</h3><blockquote class="wp-block-quote is-layout-flow wp-block-quote-is-layout-flow"><p class="wp-block-paragraph">Github: <a href="https://github.com/syedjaferk/redis-cache" rel="noreferrer noopener" target="_blank">https://github.com/syedjaferk/redis-cache</a></p></blockquote><p class="wp-block-paragraph">We are going to create a mock todo application. Let’s spin redis and mongo db using dockers,</p><h4 class="wp-block-heading" id="heading-for-redis">For Redis,</h4><pre class="wp-block-syntaxhighlighter-code">docker run -p 6379:6379 --name redis-container --rm redislabs/redismod:latest</pre><h4 class="wp-block-heading" id="heading-for-mongodb"><a href="https://parottasalna.com/redis-read-through-cache#heading-for-mongodb"></a>For mongodb,</h4><pre class="wp-block-syntaxhighlighter-code">docker run --name mongo_container --rm mongo</pre><p class="wp-block-paragraph">To load the data into mongo, either you can use the below script, or restore from the dump file.</p><pre class="wp-block-syntaxhighlighter-code">from pymongo.mongo_client import MongoClientfrom faker import Faker  fake = Faker()  # Mongo Db ConnectionMONGO_CONN_STR = "mongodb://localhost:27017"mongo_client = MongoClient(MONGO_CONN_STR)database = mongo_client['test']collection = database["todos"]for itr in range(1, 1000000):    data = {        "id": str(itr),        "name": fake.name(),        "description": fake.text(100)    }    collection.insert_one(data)    print(data)</pre><p class="wp-block-paragraph">or </p><pre class="wp-block-syntaxhighlighter-code">docker exec -i mongo_container sh -c 'mongorestore --archive' &lt; 2l_data.dump</pre><p class="wp-block-paragraph">In the redis docker image used, we have the support for redis-gears. So we have to write a python script or a module to be triggered when some commands hit.</p><p class="wp-block-paragraph">For eg: If <code>GET</code> is been hit then it will call a particular python function.</p><blockquote class="wp-block-quote is-layout-flow wp-block-quote-is-layout-flow"><p class="wp-block-paragraph">As of now there is a support for python and java modules. <a href="https://oss.redis.com/redisgears/configuration.html#plugin" rel="noreferrer noopener" target="_blank">https://oss.redis.com/redisgears/configuration.html#plugin</a></p></blockquote><p class="wp-block-paragraph">Below is the python script (read_script.py) to be triggered when JSON.GET hits,</p><pre class="wp-block-syntaxhighlighter-code">from pymongo.mongo_client import MongoClientimport jsondef find_data(key):    MONGO_CONN_STR = "mongodb://host.docker.internal:27017"    mongo_client = MongoClient(MONGO_CONN_STR)    database = mongo_client['test']    collection = database["todos"]    db_data = collection.find_one({'id': key}, {"_id": 0})    return db_datadef read_cache(event):    key = event['key']    data = execute('JSON.GET', key)    if data:        return data    data = find_data(key)    json_str = json.dumps(data)    execute('JSON.SET', key, '.', json_str)    override_reply(json_str)    return json_strGB('KeysReader').map(read_cache).register(commands=['JSON.GET'], mode='sync')</pre><p class="wp-block-paragraph">Now the script is ready so we need to send the script in <code>RG.PYEXECUTE</code> (<a href="https://oss.redis.com/redisgears/commands.html#rgpyexecute" rel="noreferrer noopener" target="_blank">https://oss.redis.com/redisgears/commands.html#rgpyexecute</a>) to the redis-server. We can acheive this using node.</p><p class="wp-block-paragraph">Below is the node script (script.js) to send to redis-cli,</p><pre class="wp-block-syntaxhighlighter-code">import fs from "fs";import { createClient } from "redis";const redisConnectionUrl = "redis://127.0.0.1:6379";const pythonFilePath = "./read_script.py";const runReadThroughRecipe = async () =&gt; {    const requirements = ["pymongo==3.12.0"];    const readThroughCode = fs.readFileSync(pythonFilePath).toString();    const client = createClient({ url: redisConnectionUrl });    await client.connect();    const params = ["RG.PYEXECUTE", readThroughCode,    "REQUIREMENTS", ...requirements];    try {        await client.sendCommand(params);        console.log("RedisGears ReadThrough set up completed.");    }    catch (err) {        console.error("RedisGears ReadThrough setup failed !");        console.error(JSON.stringify(err, Object.getOwnPropertyNames(err), 4));    }    process.exit();};runReadThroughRecipe();</pre><p class="wp-block-paragraph">Run it using, </p><pre class="wp-block-syntaxhighlighter-code">node script.js</pre><p class="wp-block-paragraph">Now let’s design the app,</p><pre class="wp-block-syntaxhighlighter-code">from fastapi import FastAPI, HTTPExceptionfrom pydantic import BaseModelfrom pymongo.mongo_client import MongoClientimport redisr = redis.Redis(host='localhost', port=6379, decode_responses=True)app = FastAPI()# Mongo Db ConnectionMONGO_CONN_STR = "mongodb://localhost:27017"mongo_client = MongoClient(MONGO_CONN_STR)database = mongo_client['test']collection = database["todos"]class Todo(BaseModel):    id: str    name: str    description: str = None@app.post("/todos/")def create_todo(todo: Todo):    collection.insert_one(todo.dict())    return {} @app.get("/todos/{todo_id}", response_model=Todo)def read_item(todo_id: str):    res = r.json().get(todo_id)    if res:        return res    raise HTTPException(status_code=404, detail="Item not found")</pre><p class="wp-block-paragraph">The flow will be like this,</p><figure class="wp-block-image size-large"><img alt="" class="wp-image-34" data-recalc-dims="1" decoding="async" height="559" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/06/image-1.png?resize=983%2C559&amp;ssl=1" width="983"/></figure><h3 class="wp-block-heading" id="heading-drawbacks">Drawbacks</h3><ol class="wp-block-list"><li>For initial every request there is a cache miss. If the requested items aren’t repeating in a good percentage, then this will create latency.</li><li>What happens if the record been updated in the database, but not in redis. Do we need to write on every update ?</li><li>In a distributed system, if a node fails, it will be replaced by a new empty node. This will increase the latency. (<em>this can be overcomed with replication of the data).</em></li><li>All drawbacks of cache aside also follows here.</li></ol><h3 class="wp-block-heading" id="heading-when-to-use"><a href="https://parottasalna.com/redis-read-through-cache#heading-when-to-use"></a>When to use ?</h3><ol class="wp-block-list"><li>If your application has a read heavy workloads.</li><li>If you not have a highly dynamic data.</li></ol><p class="wp-block-paragraph"></p>
