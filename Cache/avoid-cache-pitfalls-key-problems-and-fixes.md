has-large-font-size" id="thundering-herd-problem">Thundering Herd Problem</h2><p class="wp-block-paragraph"></p><h3 class="wp-block-heading has-medium-font-size" id="what-is-it"><strong>What is it?</strong></h3><p class="wp-block-paragraph">The <strong>Thundering Herd Problem</strong> occurs when a large number of keys in the cache expire at the same time. When this happens, all requests bypass the cache and hit the database simultaneously, overwhelming it and causing performance degradation or even a system crash.</p><figure class="wp-block-image size-large"><img alt="" class="wp-image-3603" data-recalc-dims="1" decoding="async" height="656" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2025/02/image-15.png?resize=1173%2C656&amp;ssl=1" width="1173"/></figure><h3 class="wp-block-heading has-medium-font-size" id="example-scenario"><strong>Example Scenario</strong></h3><p class="wp-block-paragraph">Imagine an e-commerce website where product details are cached for 10 minutes. If all the products’ cache expires at the same time, thousands of users sending requests will cause an overwhelming load on the database.</p><p class="wp-block-paragraph"></p><h3 class="wp-block-heading has-medium-font-size" id="solutions"><strong>Solutions</strong></h3><ol class="wp-block-list" start="1"><li><strong>Staggered Expiration</strong>: Instead of setting a fixed expiration time for all keys, introduce a random expiry variation.</li><li><strong>Allow Only Core Business Queries</strong>: Limit direct database access only to core business data, while returning stale data or temporary placeholders for less critical data.</li><li><strong>Lazy Rebuild Strategy</strong>: Instead of all requests querying the database, the first request fetches data and updates the cache while others wait.</li><li><strong>Batch Processing</strong>: Queue multiple requests and process them in batches to reduce database load.</li></ol><p class="wp-block-paragraph"></p><h2 class="wp-block-heading has-large-font-size" id="cache-penetration">Cache Penetration</h2><h3 class="wp-block-heading has-medium-font-size" id="what-is-it-1"><strong>What is it?</strong></h3><p class="wp-block-paragraph">Cache Penetration occurs when requests are made for keys that neither exist in the cache nor in the database. Since these requests always hit the database, they put excessive pressure on the system.</p><figure class="wp-block-image size-large"><img alt="" class="wp-image-3606" data-recalc-dims="1" decoding="async" height="689" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2025/02/image-16.png?resize=1475%2C689&amp;ssl=1" width="1475"/></figure><h3 class="wp-block-heading has-medium-font-size" id="example-scenario-1"><strong>Example Scenario</strong></h3><p class="wp-block-paragraph">A malicious user could attempt to query random user IDs that do not exist, forcing the system to repeatedly query the database and skip the cache.</p><p class="wp-block-paragraph"></p><h3 class="wp-block-heading has-medium-font-size" id="solutions-1"><strong>Solutions</strong></h3><ol class="wp-block-list" start="1"><li><strong>Cache Null Values</strong>: If a key does not exist in the database, store a null value in the cache to prevent unnecessary database queries.</li><li><strong>Use a Bloom Filter</strong>: A Bloom filter helps check whether a key exists before querying the database. If the Bloom filter does not contain the key, the request is discarded immediately.</li><li><strong>Rate Limiting</strong>: Implement request throttling to prevent excessive access to non-existent keys.</li><li><strong>Data Prefetching</strong>: Predict and load commonly accessed data into the cache before it is needed.</li></ol><p class="wp-block-paragraph"></p><h2 class="wp-block-heading has-large-font-size" id="cache-breakdown">Cache Breakdown</h2><h3 class="wp-block-heading has-medium-font-size" id="what-is-it-2"><strong>What is it?</strong></h3><p class="wp-block-paragraph">Cache Breakdown is similar to the <strong>Thundering Herd Problem</strong>, but it occurs specifically when a single hot key (a frequently accessed key) expires. This results in a surge of database queries as all users try to retrieve the same data.</p><figure class="wp-block-image size-large"><img alt="" class="wp-image-3609" data-recalc-dims="1" decoding="async" height="796" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2025/02/image-17.png?resize=1478%2C796&amp;ssl=1" width="1478"/></figure><h3 class="wp-block-heading has-medium-font-size" id="example-scenario-2"><strong>Example Scenario</strong></h3><p class="wp-block-paragraph">A social media platform caches trending hashtags. If the cache expires, millions of users will query the same hashtag at once, hitting the database hard.</p><p class="wp-block-paragraph"></p><h3 class="wp-block-heading has-medium-font-size" id="solutions-2"><strong>Solutions</strong></h3><ol class="wp-block-list" start="1"><li><strong>Never Expire Hot Keys</strong>: Keep hot keys permanently in the cache unless an update is required.</li><li><strong>Preload the Cache</strong>: Refresh the cache asynchronously before expiration by setting a background task to update the cache regularly.</li><li><strong>Mutex Locking</strong>: Ensure only one request updates the cache, while others wait for the update to complete.</li><li><strong>Double Buffering</strong>: Maintain a secondary cache layer to serve requests while the primary cache is being refreshed.</li></ol><p class="wp-block-paragraph"></p><h2 class="wp-block-heading has-large-font-size" id="cache-crash">Cache Crash</h2><h3 class="wp-block-heading has-medium-font-size" id="what-is-it-3"><strong>What is it?</strong></h3><p class="wp-block-paragraph">A Cache Crash occurs when the cache service itself goes down. When this happens, all requests fall back to the database, overloading it and causing severe performance issues.</p><figure class="wp-block-image size-large"><img alt="" class="wp-image-3612" data-recalc-dims="1" decoding="async" height="796" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2025/02/image-18.png?resize=1478%2C796&amp;ssl=1" width="1478"/></figure><h3 class="wp-block-heading has-medium-font-size" id="example-scenario-3"><strong>Example Scenario</strong></h3><p class="wp-block-paragraph">If a Redis instance storing session data for a web application crashes, all authentication requests will be forced to hit the database, leading to a potential outage.</p><h3 class="wp-block-heading has-medium-font-size" id="solutions-3"><strong>Solutions</strong></h3><p class="wp-block-paragraph"></p><ol class="wp-block-list" start="1"><li><strong>Cache Clustering</strong>: Use a cluster of cache nodes instead of a single instance to ensure high availability.</li><li><strong>Persistent Storage for Cache</strong>: Enable persistence modes like Redis RDB or AOF to recover data quickly after a crash.</li><li><strong>Automatic Failover</strong>: Configure automated failover with tools like Redis Sentinel to ensure availability even if a node fails.</li><li><strong>Circuit Breaker Mechanism</strong>: Prevent the application from directly accessing the database if the cache is unavailable, reducing the impact of a crash.</li></ol><pre call(self, func, *args, **kwargs):        if self.failure_count &gt;= self.failure_threshold:            return "Service unavailable"        try:            return func(*args, **kwargs)        except Exception:            self.failure_count += 1            return "Error"</pre><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">Caching is a powerful mechanism to improve application performance, but improper strategies can lead to severe bottlenecks. Problems like <strong>Thundering Herd, Cache Penetration, Cache Breakdown, and Cache Crash</strong> can significantly degrade system reliability if not handled properly.</p>
