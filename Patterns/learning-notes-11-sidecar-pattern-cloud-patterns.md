<p class="wp-block-paragraph"></p><p class="wp-block-paragraph">Today, I learnt about Sidecar Pattern. Its seems like offloading the common functionalities (logging, networking, …) aside  within a pod to be used by other apps within the pod.</p><p class="wp-block-paragraph">Its just not only about pods, but other deployments aswell. In this blog, i am going to curate the items i have learnt for my future self. Its a pattern, not an strict rule. </p><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">What is a Sidecar?</h2><p class="wp-block-paragraph">Imagine you’re riding a motorbike, and you attach a little sidecar to carry your friend or groceries. The sidecar isn’t part of the motorbike’s engine or core mechanism, but it helps you achieve your goals—whether it’s carrying more stuff or having a buddy ride along.</p><figure class="wp-block-image aligncenter size-large"><img alt="" class="wp-image-1840" data-recalc-dims="1" decoding="async" height="464" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/12/image-12.png?resize=640%2C464&amp;ssl=1" width="640"/></figure><p class="wp-block-paragraph">In the software world, a sidecar is a similar concept. It’s a separate process or container that runs alongside a primary application. Like the motorbike’s sidecar, it supports the main application by offloading or enhancing certain tasks without interfering with its core functionality. </p><figure class="wp-block-image aligncenter size-large"><img alt="" class="wp-image-1842" data-recalc-dims="1" decoding="async" height="335" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/12/image-13.png?resize=705%2C335&amp;ssl=1" width="705"/></figure><p class="wp-block-paragraph"></p><h3 class="wp-block-heading">Why Use a Sidecar?</h3><p class="wp-block-paragraph">In traditional applications, all responsibilities (logging, communication, monitoring, etc.) are bundled into the main application. This approach can make the application complex and harder to manage. Sidecars address this by handling auxiliary tasks separately, so the main application can focus on its primary purpose.</p><p class="wp-block-paragraph">Here are some key reasons to use a sidecar</p><ol class="wp-block-list" start="1"><li><strong>Modularity</strong>: Sidecars separate responsibilities, making the system easier to develop, test, and maintain.</li><li><strong>Reusability</strong>: The same sidecar can be used across multiple services. And its language agnostic. </li><li><strong>Scalability</strong>: You can scale the sidecar independently from the main application.</li><li><strong>Isolation</strong>: Sidecars provide a level of isolation, reducing the risk of one part affecting the other.</li></ol><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">Real-Life Analogies</h2><p class="wp-block-paragraph">To make the concept clearer, here are some real-world analogies:</p><ol class="wp-block-list" start="1"><li><strong>Coffee Maker with a Milk Frother</strong>:<ul class="wp-block-list"><li>The coffee maker (main application) brews coffee.</li><li>The milk frother (sidecar) prepares frothed milk for your latte.</li><li>Both work independently but combine their outputs for a better experience.</li></ul></li><li><strong>Movie Subtitles</strong>:<ul class="wp-block-list"><li>The movie (main application) provides the visuals and sound.</li><li>The subtitles (sidecar) add clarity for those who need them.</li><li>You can watch the movie with or without subtitles—they’re optional but enhance the experience.</li></ul></li><li><strong>A School with a Sports Coach</strong>:<ul class="wp-block-list"><li>The school (main application) handles education.</li><li>The sports coach (sidecar) focuses on physical training.</li><li>Both have distinct roles but contribute to the overall development of students.</li></ul></li></ol><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">Some Random Sidecar Ideas in Software</h2><p class="wp-block-paragraph">Let’s look at how sidecars are used in actual software scenarios</p><ol class="wp-block-list" start="1"><li><strong>Service Meshes (e.g., Istio, Linkerd)</strong>:<ul class="wp-block-list"><li>A service mesh helps microservices communicate with each other reliably and securely.</li><li>The sidecar (proxy like Envoy) handles tasks like load balancing, encryption, and monitoring, so the main application doesn’t have to.</li></ul></li><li><strong>Logging and Monitoring</strong>:<ul class="wp-block-list"><li>Instead of the main application generating and managing logs, a sidecar can collect, format, and send logs to a centralized system like Elasticsearch or Splunk.</li></ul></li><li><strong>Authentication and Security</strong>:<ul class="wp-block-list"><li>A sidecar can act as a gatekeeper, handling user authentication and ensuring that only authorized requests reach the main application.</li></ul></li><li><strong>Data Caching</strong>:<ul class="wp-block-list"><li>If an application frequently queries a database, a sidecar can serve as a local cache, reducing database load and speeding up responses.</li></ul></li><li><strong>Service Discovery</strong>:<ul class="wp-block-list"><li>Sidecars can aid in service discovery by automatically registering the main application with a registry service or load balancer, ensuring seamless communication in dynamic environments.</li></ul></li></ol><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">How Sidecars Work</h2><p class="wp-block-paragraph">In modern environments like Kubernetes, sidecars are often deployed as separate containers within the same pod as the main application. They share the same network and storage, making communication between the two seamless. </p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">Here’s a simplified workflow</p><ol class="wp-block-list" start="1"><li>The main application focuses on its core tasks (e.g., serving a web page).</li><li>The sidecar handles auxiliary tasks (e.g., compressing and encrypting logs).</li><li>The two communicate over local connections within the pod.</li></ol><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">Pros and Cons of Sidecars</h2><h4 class="wp-block-heading">Pros:</h4><ul class="wp-block-list"><li>Simplifies the main application.</li><li>Encourages reusability and modular design.</li><li>Improves scalability and flexibility.</li><li>Enhances observability with centralized logging and metrics.</li><li>Facilitates experimentation—you can deploy or update sidecars independently.</li></ul><h4 class="wp-block-heading">Cons:</h4><ul class="wp-block-list"><li>Adds complexity to deployment and orchestration.</li><li>Consumes additional resources (CPU, memory).</li><li>Requires careful design to avoid tight coupling between the sidecar and the main application.</li><li>Latency (You are adding an another hop).</li></ul><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">Do we always need to use sidecars</h2><p class="wp-block-paragraph">No. Not at all. </p><p class="wp-block-paragraph">a. When there is a latency between the parent application and sidecar, then Reconsider. </p><p class="wp-block-paragraph">b. If your application is small, then reconsider.</p><p class="wp-block-paragraph">c. When you are scaling differently or independently from the parent application, then Reconsider.</p><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">Some other examples</h2><p class="wp-block-paragraph"></p><h3 class="wp-block-heading">1. Adding HTTPS to a Legacy Application</h3><p class="wp-block-paragraph">Consider a legacy web service which services requests over unencrypted HTTP. We have a requirement to enhance the same legacy system to service requests with HTTPS in future.</p><figure class="wp-block-image size-large"><img alt="" class="wp-image-1848" data-recalc-dims="1" decoding="async" height="570" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/12/image-14.png?resize=677%2C570&amp;ssl=1" width="677"/></figure><p class="wp-block-paragraph">The legacy app is configured to serve request exclusively on localhost, which means that only services that share the local network with the server able to access legacy application. In addition to the main container (legacy app) we can add Nginx Sidecar container which runs in the same network namespace as the main container so that it can access the service running on localhost.</p><p class="wp-block-paragraph"></p><h3 class="wp-block-heading">2. For Logging (Image from ByteByteGo)</h3><figure class="wp-block-image size-large"><img alt="" class="wp-image-1850" data-recalc-dims="1" decoding="async" height="929" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/12/image-15.png?resize=1600%2C929&amp;ssl=1" width="1600"/></figure><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">Sidecars are not just technical solutions; they embody the principle of collaboration and specialization. By dividing responsibilities, they empower the main application to shine while ensuring auxiliary tasks are handled efficiently. Next time you hear about sidecars, you’ll know they’re more than just cool attachments for motorcycle they’re an essential part of scalable, maintainable software systems.</p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"><strong>Also, do you feel its closely related to Adapter and Ambassador Pattern ?
