<p class="wp-block-paragraph"></p><p class="wp-block-paragraph">Today, i started learning more on EDA (Event Driven Architecture). As a first step i asked this question on What is an Event ? . Is this same as messages that i put in Worker Queue, consumed by workers or is it different ? If different what does it contains ? In this blog i jot down my notes on Event and its composition.</p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">In the ever-evolving world of software architecture, <strong>event-driven architecture (EDA)</strong> has emerged as a powerful paradigm for building scalable, responsive, and decoupled systems. At the heart of this architecture lies the concept of an <strong>event</strong>.</p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">As event is the rigid concept that travels through the EDA. Let’s explore more on EDA. </p><p class="wp-block-paragraph"></p><figure class="wp-block-image size-large"><img alt="" class="wp-image-2816" data-recalc-dims="1" decoding="async" height="687" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2025/01/image-81.png?resize=1792%2C687&amp;ssl=1" width="1792"/></figure><p class="wp-block-paragraph"></p><h2 class="wp-block-heading"><strong>Defining an Event</strong></h2><p class="wp-block-paragraph">An <strong>event</strong> is a record of a significant occurrence or <strong>change in the state</strong> of a system. It <strong>encapsulates</strong> information about something that has happened and serves as a trigger for further actions or workflows in an event-driven system.</p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">Events are <strong>immutable</strong>, meaning they represent something that has already occurred and cannot be altered retroactively.</p><p class="wp-block-paragraph"></p><h2 class="wp-block-heading"><strong>Examples of Events</strong></h2><ul class="wp-block-list"><li>A customer places an order in an e-commerce application.</li><li>A payment is successfully processed.</li><li>A temperature sensor reports a change in temperature.</li><li>A user clicks a button on a web page.</li></ul><p class="wp-block-paragraph"></p><h2 class="wp-block-heading"><strong>Core Characteristics of an Event</strong> (My Opinion from reading)</h2><ol class="wp-block-list" start="1"><li><strong>Significance</strong>: An event represents a meaningful action or <span style="text-decoration: underline"><strong><em>state change</em></strong></span>, such as creating a new user account or updating inventory.<br/></li><li><strong>Immutability</strong>: Events are <span style="text-decoration: underline"><strong><em>immutable</em></strong></span> records. Once an event is published, it cannot be changed; instead, new events are created to reflect subsequent changes.<br/></li><li><strong>Lightweight</strong>: Events are designed to be <em><strong><span style="text-decoration: underline">lightweight</span></strong></em>, containing only the necessary information about the occurrence.<br/></li><li><strong>State Representation</strong>: Events often represent a change in the state of a system (e.g., “OrderPlaced” changes an order’s state from pending to placed).</li></ol><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">Components of an Event</h2><blockquote class="wp-block-quote is-layout-flow wp-block-quote-is-layout-flow"><p class="wp-block-paragraph"><em>My Opinion on Components, it can contain many. </em></p></blockquote><p class="wp-block-paragraph">Every event typically consists of the following components</p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"><strong><span style="text-decoration: underline">Event Type</span></strong></p><ol class="wp-block-list"><li>Describes the nature of the event (eg., OrderPlaced, UserRegistered).</li><li>Helps consumers to identify on processing the event. (Can also be redirected to individual queues)</li></ol><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"><strong><span style="text-decoration: underline">Event Metadata</span></strong></p><ol class="wp-block-list"><li>Contains contextual information such as <strong>Timestamp, Source, CorrelationID.</strong></li><li><strong>Timestamp: </strong>When the event occured.</li><li><strong>Source: </strong>Which system or component generated the event. </li><li><strong>Correlation ID: </strong>Links events related to the same workflow.</li></ol><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"><strong><span style="text-decoration: underline">Event Payload</span></strong></p><ol class="wp-block-list"><li>The actual data relevant to the event.</li><li>For example, an “OrderPlaced” event payload might include</li></ol><pre class="wp-block-syntaxhighlighter-code">{  "orderId": 12345,  "userId": 67890,  "items": [    { "productId": "A1", "quantity": 2 },    { "productId": "B2", "quantity": 1 }  ]}</pre><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">Types of Events</h2><p class="wp-block-paragraph">1. <strong>Discrete Events – </strong>These are one-time occurrences, such as a user clicking a button or a payment being processed.</p><p class="wp-block-paragraph">2. <strong>Streaming Events – </strong>These occur as a continuous flow, such as real-time data from IoT sensors or log streams from a web server.</p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">How Events are placed in Event-Driven Architecture ?</h2><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">In EDA, events are the primary mechanism through which components communicate. </p><p class="wp-block-paragraph">Here’s how events fit into the architecture,</p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"><strong><span style="text-decoration: underline">Event Producers</span></strong></p><ol class="wp-block-list"><li>Generate and publish events.</li><li>Example: An order service publishes an “OrderPlaced” event when an order is completed.</li></ol><figure class="wp-block-image size-large"><img alt="" class="wp-image-2826" data-recalc-dims="1" decoding="async" height="566" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2025/01/image-82.png?resize=1533%2C566&amp;ssl=1" width="1533"/></figure><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"><strong><span style="text-decoration: underline">Event Channels</span></strong></p><ol class="wp-block-list"><li>Transmit events from producers to consumers.</li><li>Examples: Message brokers like Apache Kafka, RabbitMQ, or Amazon SNS.</li></ol><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"><strong><span style="text-decoration: underline">Event Consumers</span></strong></p><ol class="wp-block-list"><li>Listen to and process events.</li><li>Example: An inventory service updates stock levels upon receiving an “OrderPlaced” event.</li></ol><p class="wp-block-paragraph"></p><figure class="wp-block-image size-large"><img alt="" class="wp-image-2829" data-recalc-dims="1" decoding="async" height="566" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2025/01/image-83.png?resize=1533%2C566&amp;ssl=1" width="1533"/></figure><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"><strong><span style="text-decoration: underline">Event Processors</span></strong></p><ol class="wp-block-list"><li>Intermediate components that transform, filter, or aggregate events.</li><li>Example: Enriching an event with additional user data before forwarding it to consumers.</li></ol><figure class="wp-block-image size-large"><img alt="" class="wp-image-2831" data-recalc-dims="1" decoding="async" height="566" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2025/01/image-84.png?resize=1533%2C566&amp;ssl=1" width="1533"/></figure><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"><span style="text-decoration: underline"><strong>Event Stores</strong> (Optional)</span></p><p class="wp-block-paragraph">Persist events for historical analysis, debugging, or rehydrating system state.</p><figure class="wp-block-image size-large"><img alt="" class="wp-image-2833" data-recalc-dims="1" decoding="async" height="546" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2025/01/image-85.png?resize=1782%2C546&amp;ssl=1" width="1782"/></figure><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">So is it same as a TASK ?</h2><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">While events and tasks are closely related, they serve distinct purposes in a system, </p><p class="wp-block-paragraph"></p><figure class="wp-block-table"><table class="has-fixed-layout"><tbody><tr><th><strong>Aspect</strong></th><th><strong>Event</strong></th><th><strong>Task</strong></th></tr><tr><td><strong>Content</strong></td><td>Describes something that happened.</td><td>Provides input or instructions for work.</td></tr><tr><td><strong>Purpose</strong></td><td>Notify consumers of a state change.</td><td>Define actionable work to be done.</td></tr><tr><td><strong>Consumer Behavior</strong></td><td>Decides independently how to react.</td><td>Executes the specific action described.</td></tr><tr><td><strong>Communication Pattern</strong></td><td>Often many-to-many.</td><td>Typically one-to-one or one-to-few.</td></tr></tbody></table></figure><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"><p><span><strong>Event Example</strong>:</span></p></p><ol class="wp-block-list"><li><p><span><strong>Message</strong>: </span><code><span>{"type": "OrderPlaced", "orderId": 12345, "timestamp": "2025-01-18T12:00:00Z"}</span></code></p></li><li><p><span><strong>Purpose</strong>: Notify all interested services (inventory, analytics, notifications) that an order was placed. Each service decides its action.</span></p></li></ol><p class="wp-block-paragraph"><p><span><strong>Task Example</strong>:</span></p></p><ol class="wp-block-list"><li><p><span><strong>Message</strong>: </span><code><span>{"action": "GenerateReport", "userId": 123, "startDate": "2025-01-01", "endDate": "2025-01-10"}</span></code></p></li><li><p><span><strong>Purpose</strong>: Pass specific instructions to a report generation service to execute this action.</span></p></li><li><ol start="1"></ol></li></ol><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"><ol start="1"></ol></p><h2 class="wp-block-heading">How Event and Task are related with each other ?</h2><ol class="wp-block-list"><li><strong>Event Occurs</strong>: An event is published when something meaningful happens in the system. For example, an order is placed.</li><li><strong>Task Triggered</strong>: The event triggers one or more tasks based on predefined business logic. For instance, the <code>"OrderPlaced"</code> event might trigger tasks such as:<ol class="wp-block-list"><li>Deducting inventory.Notifying the warehouse.Sending a confirmation email to the customer.</li><li><strong>Task Execution</strong>: Tasks are executed asynchronously or synchronously, depending on the system’s design.</li></ol></li></ol><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">In the upcoming blogs, we will dive much deeper into EDA.</p><p class="wp-block-paragraph"></p>
