<p class="wp-block-paragraph">Meet Jafer, a backend engineer tasked with ensuring the new microservice they are building can handle high traffic smoothly. The microservice is a Flask application that needs to be accessed over TCP, and Jafer decided to use <strong>HAProxy</strong> to act as a <strong>TCP proxy</strong> to manage incoming traffic.</p><p class="wp-block-paragraph">This guide will walk you through how Jafer sets up HAProxy to work as a TCP proxy for a sample Flask application.</p><h3 class="wp-block-heading">Why Use HAProxy as a TCP Proxy?</h3><figure class="wp-block-image size-large"><img alt="" class="wp-image-1395" data-recalc-dims="1" decoding="async" height="456" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/09/image-4.png?resize=560%2C456&amp;ssl=1" width="560"/></figure><p class="wp-block-paragraph">HAProxy as a <strong>TCP proxy</strong> operates at Layer 4 (Transport Layer) of the OSI model. It forwards raw TCP connections from clients to backend servers without inspecting the contents of the packets. This is ideal for scenarios where:</p><ul class="wp-block-list"><li>You need to handle non-HTTP traffic, such as databases or other TCP-based applications.</li><li>You want to perform load balancing without application-level inspection.</li><li>Your services are using protocols other than HTTP/HTTPS.</li></ul><figure class="wp-block-image size-large"><img alt="" class="wp-image-1399" data-recalc-dims="1" decoding="async" height="619" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/09/image-5.png?resize=1177%2C619&amp;ssl=1" width="1177"/></figure><p class="wp-block-paragraph">In this layer, it can’t read the packets but can identify the ip address of the client.</p><h3 class="wp-block-heading">Step 1: Set Up a Sample Flask Application</h3><p class="wp-block-paragraph">First, Jafer created a simple Flask application that listens on a TCP port. Let’s create a file named <code>app.py</code></p><pre class="wp-block-syntaxhighlighter-code">from flask import Flask, requestapp = Flask(__name__)@app.route('/', methods=['GET'])def home():    return "Hello from Flask over TCP!"if __name__ == "__main__":    app.run(host='0.0.0.0', port=5000)  # Run the app on port 5000</pre><h3 class="wp-block-heading">Step 2: Dockerize the Flask Application</h3><p class="wp-block-paragraph">To make the Flask app easy to deploy, Jafer decided to containerize it using Docker.</p><p class="wp-block-paragraph">Create a <code>Dockerfile</code></p><pre class="wp-block-syntaxhighlighter-code"># Use an official Python runtime as a parent imageFROM python:3.9-slim# Set the working directoryWORKDIR /app# Copy the current directory contents into the container at /appCOPY . /app# Install any needed packages specified in requirements.txtRUN pip install flask# Make port 5000 available to the world outside this containerEXPOSE 5000# Run app.py when the container launchesCMD ["python", "app.py"]</pre><p class="wp-block-paragraph">To build and run the Docker container, use the following commands</p><pre class="wp-block-syntaxhighlighter-code">docker build -t flask-app .docker run -d -p 5000:5000 flask-app</pre><p class="wp-block-paragraph">This will start the Flask application on port <code>5000</code>.</p><h3 class="wp-block-heading">Step 3: Configure HAProxy as a TCP Proxy</h3><p class="wp-block-paragraph">Now, Jafer needs to configure HAProxy to act as a TCP proxy for the Flask application.</p><p class="wp-block-paragraph">Create an HAProxy configuration file named <code>haproxy.cfg</code></p><pre class="wp-block-syntaxhighlighter-code">global    log stdout format raw local0    maxconn 4096defaults    mode tcp  # Operating in TCP mode    log global    option tcplog    timeout connect 5000ms    timeout client  50000ms    timeout server  50000msfrontend tcp_front    bind *:4000  # Bind to port 4000 for incoming TCP traffic    default_backend flask_backendbackend flask_backend    balance roundrobin  # Use round-robin load balancing    server flask1 127.0.0.1:5000 check  # Proxy to Flask app running on port 5000</pre><p class="wp-block-paragraph">In this configuration:</p><ul class="wp-block-list"><li><strong>Mode TCP</strong>: HAProxy is set to work in TCP mode.</li><li><strong>Frontend</strong>: Listens on port <code>4000</code> and forwards incoming TCP traffic to the backend.</li><li><strong>Backend</strong>: Contains a single server (<code>flask1</code>) where the Flask app is running.</li></ul><h3 class="wp-block-heading">Step 4: Run HAProxy with the Configuration</h3><p class="wp-block-paragraph">To start HAProxy with the above configuration, you can use Docker to run HAProxy in a container.</p><p class="wp-block-paragraph">Create a <code>Dockerfile</code> for HAProxy</p><pre class="wp-block-syntaxhighlighter-code">FROM haproxy:2.4# Copy the HAProxy configuration file to the containerCOPY haproxy.cfg /usr/local/etc/haproxy/haproxy.cfg</pre><p class="wp-block-paragraph">Build and run the HAProxy Docker container</p><pre class="wp-block-syntaxhighlighter-code">docker build -t haproxy-tcp .docker run -d -p 4000:4000 haproxy-tcp</pre><p class="wp-block-paragraph">This will start HAProxy on port <code>4000</code>, which is configured to proxy TCP traffic to the Flask application running on port <code>5000</code>.</p><h3 class="wp-block-heading">Step 5: Test the TCP Proxy Setup</h3><p class="wp-block-paragraph">To test the setup, open a web browser or use <code>curl</code> to send a request to the HAProxy server</p><pre class="wp-block-syntaxhighlighter-code">curl http://localhost:4000/</pre><p class="wp-block-paragraph">You should see the response</p><pre class="wp-block-syntaxhighlighter-code">Hello from Flask over TCP!</pre><p class="wp-block-paragraph">This confirms that HAProxy is successfully proxying TCP traffic to the Flask application.</p><h3 class="wp-block-heading">Step 6: Scaling Up</h3><p class="wp-block-paragraph">If Jafer wants to scale the application to handle more traffic, he can add more backend servers to the <code>haproxy.cfg</code> file</p><pre class="wp-block-syntaxhighlighter-code">backend flask_backend    balance roundrobin    server flask1 127.0.0.1:5000 check    server flask2 127.0.0.1:5001 check</pre><p class="wp-block-paragraph">Jafer could run another instance of the Flask application on a different port (<code>5001</code>), and HAProxy would balance the TCP traffic between the two instances.</p><h3 class="wp-block-heading">Conclusion</h3><p class="wp-block-paragraph">By configuring HAProxy as a TCP proxy, Jafer could efficiently manage and balance incoming traffic to their Flask application. This setup ensures scalability and reliability for any TCP-based service, not just HTTP-based ones.</p>
