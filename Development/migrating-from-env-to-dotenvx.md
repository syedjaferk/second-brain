<blockquote class="wp-block-quote is-layout-flow wp-block-quote-is-layout-flow"><p class="wp-block-paragraph">Official Link: <a href="https://github.com/motdotla/dotenv">https://github.com/motdotla/dotenv</a></p></blockquote><p class="wp-block-paragraph">As a developer, we used .env file where we used to store environmental variables. </p><p class="wp-block-paragraph">As stated from founder, </p><blockquote class="wp-block-quote is-layout-flow wp-block-quote-is-layout-flow"><p class="wp-block-paragraph">Dotenv is a zero-dependency module that loads environment variables from a <code>.env</code> file into <a href="https://nodejs.org/docs/latest/api/process.html#process_process_env"><code>process.env</code></a>. Storing configuration in the environment separate from code is based on <a href="https://12factor.net/config">The Twelve-Factor App</a> methodology.</p></blockquote><p class="wp-block-paragraph">During software development, we use environment variables to access the secret values, segregation based on env and other details required for development. </p><p class="wp-block-paragraph">Dotenv is a small software library that helps manage environment variables in applications. Environment variables are like little pieces of information your application needs to run, such as database passwords, API keys, and other configuration details.</p><h3 class="wp-block-heading">Why is Dotenv Useful?</h3><p class="wp-block-paragraph">Imagine you have an app that needs to connect to a database. You don’t want to hard-code your database password directly into your app’s code because:</p><ol class="wp-block-list"><li><strong>Security:</strong> If someone gets access to your code, they’ll also get your password.</li><li><strong>Flexibility:</strong> If you ever need to change the password, you’d have to go through your code and update it everywhere.</li></ol><p class="wp-block-paragraph">Dotenv allows you to store these important pieces of information in a separate file, usually named <code>.env</code>. This file is kept out of the main codebase, making it easier to manage and more secure.</p><h3 class="wp-block-heading">How Does Dotenv Work?</h3><p class="wp-block-paragraph">Here’s a step-by-step on how you might use dotenv:</p><ol class="wp-block-list"><li><strong>Create a .env File:</strong> In the root directory of your project, create a file named <code>.env</code>.</li><li><strong>Add Variables:</strong> Inside this file, you add your environment variables. It might look something like this:</li></ol><pre class="wp-block-syntaxhighlighter-code">DATABASE_URL=your-database-urlAPI_KEY=your-api-key</pre><p class="wp-block-paragraph">3. <strong>Load Variables in Your Code:</strong> In your application code, use dotenv to load these variables. Here’s a quick example in JavaScript using Node.js:</p><pre class="wp-block-syntaxhighlighter-code">require('dotenv').config();const dbUrl = process.env.DATABASE_URL;const apiKey = process.env.API_KEY;</pre><h3 class="wp-block-heading">Benefits of Using Dotenv</h3><ul class="wp-block-list"><li><strong>Security:</strong> Sensitive information is not directly embedded in your code.</li><li><strong>Ease of Use:</strong> It’s straightforward to update configuration settings without digging through the code.</li><li><strong>Portability:</strong> You can easily share your project with others. They can create their own <code>.env</code> file with their settings without changing the code.</li></ul><h3 class="wp-block-heading">So no problems right ?</h3><p class="wp-block-paragraph">Not really, there are some problems within itself, </p><ol class="wp-block-list"><li>If not handled properly, the <code>.env</code> file can be accidentally committed to version control systems like Git. This exposes sensitive information to anyone with access to the repository.</li><li>The contents of a <code>.env</code> file are stored in plain text. If unauthorized users gain access to the server or development environment, they can easily read sensitive information.</li><li>Managing multiple <code>.env</code> files for different environments (development, testing, staging, production) can become cumbersome and error-prone.</li><li>Each time the application starts, dotenv has to read and parse the <code>.env</code> file. While this overhead is generally minimal, it can become noticeable in very large applications or performance-critical environments.</li><li>Using dotenv adds an additional dependency to your project. While it’s a relatively small and stable library, it’s still something that needs to be maintained and kept up-to-date. ( &lt;- This is my main concern )</li></ol><h3 class="wp-block-heading">What to do ?</h3><p class="wp-block-paragraph">The dotenv founder itself brought a upgraded version of dotenv; <strong>dotenvx</strong>. </p><blockquote class="wp-block-quote is-layout-flow wp-block-quote-is-layout-flow"><p class="wp-block-paragraph">dotenvx works the same across every language, framework, and platform – inject your env at runtime with <code>dotenvx run -- your-cmd</code>.</p></blockquote><h3 class="wp-block-heading">Installing dotenvx</h3><p class="wp-block-paragraph"><a href="https://dotenvx.com/docs#getting-started" rel="nofollow">https://dotenvx.com/docs#getting-started</a></p><pre class="wp-block-syntaxhighlighter-code"># download it directly as a standalone binarycurl -sfS https://dotenvx.sh/install.sh | shdotenvx help</pre><h3 class="wp-block-heading">Run Anywhere</h3><p class="wp-block-paragraph">This is one of my main concern, that i need to install one extra package to my codebase and i need to do some code changes while deploying to different deployment environments.</p><p class="wp-block-paragraph">With dotenvx, I can simply run my application without installing additional packages.</p><pre class="wp-block-syntaxhighlighter-code">$ echo "HELLO=World" &gt; .env $ echo 'import os;print("Hello " + os.getenv("HELLO", ""))' &gt; index.py$ dotenvx run -- python3 index.pyHello World</pre><figure class="wp-block-image size-large"><img alt="" class="wp-image-374" data-recalc-dims="1" decoding="async" height="234" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/06/image-47.png?resize=1590%2C234&amp;ssl=1" width="1590"/></figure><p class="wp-block-paragraph">Even for different environments, </p><pre class="wp-block-syntaxhighlighter-code">$ echo "HELLO=production" &gt; .env.production$ echo 'import os;print("Hello " + os.getenv("HELLO", ""))' &gt; index.py$ dotenvx run -f .env.production -- python3 index.pyHello production</pre><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">So for me, now it more handy to use .env</p><p class="wp-block-paragraph"></p>
