Github Actions</h3><p class="wp-block-paragraph">Github Actions is a managed CI/CD pipeline offering. It provides free runners for running the code. </p><p class="wp-block-paragraph"></p><h3 class="wp-block-heading">1. <strong>Workflow, Jobs, Steps</strong></h3><p class="wp-block-paragraph">A <strong>workflow</strong> is a collection of jobs defined in a <code>.yml</code> file inside <code>.github/workflows</code>. Each workflow consists of <strong>jobs</strong>, and jobs have <strong>steps</strong>. </p><pre class="wp-block-syntaxhighlighter-code">name: My First Workflowon: pushjobs:  example-job:    runs-on: ubuntu-latest    steps:      - name: Print a message        run: echo "Hello, GitHub Actions!"</pre><p class="wp-block-paragraph"></p><h3 class="wp-block-heading">2. Availability and Pricing</h3><p class="wp-block-paragraph">GitHub Actions is free for public repositories and has free usage limits for private repositories, depending on the plan. Paid plans increase these limits. For detailed pricing, visit the <a href="https://github.com/features/actions#pricing">GitHub Actions pricing page</a>.</p><p class="wp-block-paragraph"></p><h3 class="wp-block-heading">3. First workflow with basic echo commands</h3><p class="wp-block-paragraph">Start with a workflow triggered by any push event. Here’s a simple example,</p><pre class="wp-block-syntaxhighlighter-code">name: Echo Workflowon: pushjobs:  echo-job:    runs-on: ubuntu-latest    steps:      - name: Say Hello        run: echo "Hello from my first workflow!"</pre><p class="wp-block-paragraph"></p><h3 class="wp-block-heading">4. Multiline Shell Commands</h3><p class="wp-block-paragraph">You can use the <code>|</code> symbol to write multiline shell commands.</p><pre class="wp-block-syntaxhighlighter-code">name: Push Event Workflowon:  push:    branches:      - mainjobs:  push-job:    runs-on: ubuntu-latest    steps:      - name: On Push        run: echo "Code pushed to main branch!"</pre><p class="wp-block-paragraph"></p><h3 class="wp-block-heading">5. A new workflow with push events</h3><p class="wp-block-paragraph">Workflows can be triggered by specific events like <code>push</code>. This example triggers only on <code>push</code> to the <code>main</code> branch.</p><pre class="wp-block-syntaxhighlighter-code">name: Push Event Workflowon:  push:    branches:      - mainjobs:  push-job:    runs-on: ubuntu-latest    steps:      - name: On Push        run: echo "Code pushed to main branch!"</pre><p class="wp-block-paragraph"></p><h3 class="wp-block-heading">6. Using actions in workflow (Marketplace and Open Source)</h3><p class="wp-block-paragraph">GitHub Actions Marketplace offers reusable actions. For example, using the <code>actions/checkout</code> action.</p><pre class="wp-block-syntaxhighlighter-code">steps:  - name: Checkout Code    uses: actions/checkout@v3</pre><p class="wp-block-paragraph"></p><h3 class="wp-block-heading">7. Checkout in code</h3><p class="wp-block-paragraph">Checking out your code is essential to access the repository content. Use <code>actions/checkout</code></p><pre class="wp-block-syntaxhighlighter-code">steps:  - name: Checkout Code    uses: actions/checkout@v3</pre><p class="wp-block-paragraph"></p><h3 class="wp-block-heading">8. Adding workflow job steps</h3><p class="wp-block-paragraph">Each job can have multiple steps.</p><pre class="wp-block-syntaxhighlighter-code">jobs:  build:    runs-on: ubuntu-latest    steps:      - name: Step 1 - Checkout Code        uses: actions/checkout@v3      - name: Step 2 - Run a Script        run: echo "Script running in step 2."</pre><p class="wp-block-paragraph"></p><h3 class="wp-block-heading">9. Jobs in Parallel and Sequential</h3><p class="wp-block-paragraph">To run jobs in parallel, define them without dependencies. For sequential jobs, use <code>needs</code>.</p><h4 class="wp-block-heading">Parallel Jobs:</h4><pre class="wp-block-syntaxhighlighter-code">jobs:  job1:    runs-on: ubuntu-latest    steps:      - run: echo "Job 1"  job2:    runs-on: ubuntu-latest    steps:      - run: echo "Job 2"</pre><p class="wp-block-paragraph"></p><h4 class="wp-block-heading">Sequential Jobs:</h4><pre class="wp-block-syntaxhighlighter-code">jobs:  job1:    runs-on: ubuntu-latest    steps:      - run: echo "Job 1"  job2:    runs-on: ubuntu-latest    needs: job1    steps:      - run: echo "Job 2 after Job 1"</pre><p class="wp-block-paragraph"></p><h3 class="wp-block-heading">10. Using Multiple Triggers</h3><p class="wp-block-paragraph">A workflow can be triggered by multiple events.</p><pre class="wp-block-syntaxhighlighter-code">on:  push:    branches:      - main  pull_request:    branches:      - main</pre><p class="wp-block-paragraph"></p><h3 class="wp-block-heading">11. Expressions and Context Objects</h3><p class="wp-block-paragraph">Expressions are used to access variables and contexts like <code>github</code> or <code>env</code>.</p><pre class="wp-block-syntaxhighlighter-code">steps:  - name: Use an Expression    run: echo "Triggered by ${{ github.event_name }}"</pre>
