<h3 class="wp-block-heading">Prerequisite:</h3><ol class="wp-block-list"><li><a href="https://parottasalna.com/2024/06/12/contents-of-package-json-package-lock-json/">https://parottasalna.com/2024/06/12/contents-of-package-json-package-lock-json/</a></li></ol><h3 class="wp-block-heading">How does npm install work?</h3><p class="wp-block-paragraph">So far we have seen the functionalities of two files <code>package.json</code> and <code>package-lock.json</code>, and also what each of those files contains. Now let’s see how this files is been used with npm install.</p><figure class="wp-block-image aligncenter size-large"><img alt="" class="wp-image-188" data-recalc-dims="1" decoding="async" height="386" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/06/image-23.png?resize=489%2C386&amp;ssl=1" width="489"/></figure><p class="wp-block-paragraph">Whenever someone clones a repository and does the <code>npm install</code> command and if your project has both a <code>package.json</code> and a <code>package-lock.json</code> and you run <code>npm install</code> then the dependencies would get installed using <code>package-lock.json</code> and not <code>package.json</code>.</p><p class="wp-block-paragraph">but if there are some discrepancies (which will discuss below) between the <code>package-lock.json</code> and the <code>package.json</code> and you run <code>npm install</code>, then npm would use the <code>package.json</code> file to update the <code>package-lock.json</code> and you might end up having a different version than what you initially installed.</p><p class="wp-block-paragraph"><strong>Let’s look at an example:</strong></p><p class="wp-block-paragraph">Let’s consider a package called ‘express’ and we can install it like <code>npm install express</code>. So in your folder, you can see those 2 files package.json and package-lock.json.</p><figure class="wp-block-image aligncenter size-large"><img alt="" class="wp-image-190" data-recalc-dims="1" decoding="async" height="566" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/06/image-24.png?resize=550%2C566&amp;ssl=1" width="550"/></figure><p class="wp-block-paragraph">Let’s see the versions of express in both the files,</p><figure class="wp-block-image size-large"><img alt="" class="wp-image-191" data-recalc-dims="1" decoding="async" height="283" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/06/image-25.png?resize=1277%2C283&amp;ssl=1" width="1277"/></figure><p class="wp-block-paragraph">It’s 4.18.1, Now we can change the minor version in the <code>package.json</code> file from 18 to 17.</p><figure class="wp-block-image size-large"><img alt="" class="wp-image-192" data-recalc-dims="1" decoding="async" height="261" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/06/image-26.png?resize=1228%2C261&amp;ssl=1" width="1228"/></figure><p class="wp-block-paragraph">Then we can delete the <strong>node_modules</strong> folder.</p><figure class="wp-block-image size-large"><img alt="" class="wp-image-193" data-recalc-dims="1" decoding="async" height="132" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/06/image-27.png?resize=599%2C132&amp;ssl=1" width="599"/></figure><p class="wp-block-paragraph">So now, we can install the packages using <code>npm install</code>. Let’s see whether we are having the version mentioned in <strong>package-lock.json</strong> or <strong>package.json</strong>.</p><figure class="wp-block-image size-large"><img alt="" class="wp-image-195" data-recalc-dims="1" decoding="async" height="305" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/06/image-28.png?resize=776%2C305&amp;ssl=1" width="776"/></figure><pre class="wp-block-syntaxhighlighter-code">npm install</pre><figure class="wp-block-image size-large"><img alt="" class="wp-image-196" data-recalc-dims="1" decoding="async" height="357" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/06/image-29.png?resize=1261%2C357&amp;ssl=1" width="1261"/></figure><p class="wp-block-paragraph">From the above image, we can see that the version value in <code>package-lock.json</code> is maintained. So <code>package-lock.json</code> is having higher precedence.</p><p class="wp-block-paragraph">But, we can see another scenario, We can change the version value in <code>package-lock.json</code> from 4.18.1 to 5.0.0 and follow the same process again.</p><figure class="wp-block-image size-large"><img alt="" class="wp-image-197" data-recalc-dims="1" decoding="async" height="293" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/06/image-30.png?resize=1226%2C293&amp;ssl=1" width="1226"/></figure><p class="wp-block-paragraph">Let’s delete the <strong>node_modules</strong> and reinstall using <code>npm install</code>.</p><figure class="wp-block-image size-large"><img alt="" class="wp-image-199" data-recalc-dims="1" decoding="async" height="297" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/06/image-31.png?resize=626%2C297&amp;ssl=1" width="626"/></figure><p class="wp-block-paragraph">Now if we are checking those files,</p><figure class="wp-block-image size-large"><img alt="" class="wp-image-200" data-recalc-dims="1" decoding="async" height="298" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/06/image-32.png?resize=1233%2C298&amp;ssl=1" width="1233"/></figure><p class="wp-block-paragraph">Now we can see the precedence is been moved to <code>package.json</code>.</p><p class="wp-block-paragraph">To know more about the working of <code>npm install</code>, please refer to their github code, <a href="https://github.com/npm/cli/blob/latest/lib/commands/install.js" rel="noreferrer noopener" target="_blank">https://github.com/npm/cli/blob/latest/lib/commands/install.js</a></p><h3 class="wp-block-heading">How does npm ci work?<br/></h3><figure class="wp-block-image size-large"><img alt="" class="wp-image-205" data-recalc-dims="1" decoding="async" height="387" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/06/image-33.png?resize=489%2C387&amp;ssl=1" width="489"/></figure><h3 class="wp-block-heading"></h3><pre class="wp-block-preformatted"><code>npm ci</code> (or clean install) runs only if the project has a lock file (package-lock.json) and if there's some discrepancy between the lock file (package-lock.json) and <code>package.json</code>, then <code>npm ci</code> errors out, so it doesn't update the lock file like <code>npm install</code>.</pre><figure class="wp-block-image size-large"><img alt="" class="wp-image-206" data-recalc-dims="1" decoding="async" height="213" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/06/image-34.png?resize=828%2C213&amp;ssl=1" width="828"/></figure><p class="wp-block-paragraph"><code>npm ci</code> simply removes the <code>node_modules</code> directory and then installs the dependencies and hence the name clean install.</p><p class="wp-block-paragraph">So, <code>npm ci</code> is no different than <code>npm i</code> if there’s no <code>node_modules</code> directory present and there are no discrepancies between <code>package-lock.json</code> and <code>package.json</code>.</p><p class="wp-block-paragraph">So, using <code>npm install</code> is okay if you’ve cloned a repo because it respects the lock file, however, in CI environments you should consider using <code>npm ci</code> because it does a clean install.</p><p class="wp-block-paragraph"></p>
