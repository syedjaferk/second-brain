<p class="wp-block-paragraph">Today, i enrolled in to a udemy course on cloud design pattern. This is the first pattern that they had in the list of patterns. In this blog i curate the notes i got from the video.  Also i tried to implement the same using HA Proxy.</p><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">Gatekeeper Cloud Pattern</h2><p class="wp-block-paragraph">The <strong>Gatekeeper Design Pattern</strong> is a way to control access to resources or operations in your application. It acts as a mediator to ensure that only authorized or validated requests can proceed to the next stage of execution. Implementing this pattern locally could involve various use cases like authentication, rate limiting, or feature gating.</p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"><strong>Analogy</strong>: Gatekeeper is like a security guard standing at our main door in day-to-day life. If it helps, we can imagine a Gatekeeper as a firewall in a typical network topography.</p><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">Things to consider while using gatekeeper pattern:</h2><ol class="wp-block-list"><li>GK should have only minimal access. (No Access keys or Tokens)</li><li>GK should not do any application related operations. It just need to validate and filter the requests. </li><li>Adding an extra layer for the gatekeeper can slow things down a bit because it requires extra work, like checking rules and handling network traffic.</li><li>Also, if the gatekeeper itself stops working, it could block everything since it controls access. Single Point of Failure. To avoid this, you can set up backup gatekeepers (redundant instances) and use systems that automatically add more gatekeepers when needed (autoscaling). This way, the system stays reliable and can handle more users without problems.</li></ol><p class="wp-block-paragraph">Again , this is a concept. Which means we can achieve the same with different processes, like, </p><ul class="wp-block-list"><li>Application Gateway </li><li>API Management  </li><li>Web Application Firewall</li><li>OAuth</li><li>Reverse Proxies</li><li>Custom Gatekeeper Services (Customizing AWS Lambda for this approach.)</li></ul><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">Local Implementation </h2><p class="wp-block-paragraph">Implementing a rate limiter using haproxy. Here HAProxy will act as a gatekeeper. </p><blockquote class="wp-block-quote is-layout-flow wp-block-quote-is-layout-flow"><p class="wp-block-paragraph">Github: <a href="https://github.com/syedjaferk/gatekeeper_cloud_design_pattern_ha_proxy">https://github.com/syedjaferk/gatekeeper_cloud_design_pattern_ha_proxy</a></p></blockquote><p class="wp-block-paragraph">HAProxy’s stick-table allows tracking client IPs and request rates. Here’s a minimal configuration,</p><p class="wp-block-paragraph"><strong>haproxy.cfg</strong></p><pre class="wp-block-syntaxhighlighter-code">global    log /dev/log local0    log /dev/log local1 notice    maxconn 2000    user haproxy    group haproxy    daemondefaults    log     global    mode  http    option  httplog    option  dontlognull    timeout connect 5000ms    timeout client  50000ms    timeout server  50000msfrontend http_front    mode http    bind *:8090    stick-table  type ipv6  size 100k  expire 30s  store http_req_rate(10s)    http-request track-sc0 src    http-request deny deny_status 429 if { sc_http_req_rate(0) gt 2 }    default_backend http_backbackend http_back    mode http    server app1 flask_app:5000 check</pre><p class="wp-block-paragraph"></p><h3 class="wp-block-heading">Explanation:</h3><ul class="wp-block-list"><li><strong>Stick Table</strong>: Tracks unique client IPs and their request rates over 10 seconds.</li><li><strong>ACL</strong>: Checks if the request rate exceeds 5 requests per 10 seconds.</li><li><strong>Deny Rule</strong>: Blocks requests when the ACL condition is met.</li></ul><h2 class="wp-block-heading">Testing Rate Limiting</h2><p class="wp-block-paragraph">Use a tool like Apache Benchmark (<code>ab</code>) to simulate traffic:</p><pre class="wp-block-syntaxhighlighter-code">ab -n 20 -c 1 http://localhost:8080/</pre><ul class="wp-block-list"><li><code>-n 20</code>: Total number of requests.</li><li><code>-c 1</code>: Sends requests sequentially from a single client.</li></ul><p class="wp-block-paragraph">If rate limiting is configured correctly, requests exceeding the limit should be denied.</p><figure class="wp-block-image size-large"><img alt="" class="wp-image-1665"
