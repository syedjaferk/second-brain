<p class="wp-block-paragraph"></p><p class="wp-block-paragraph">Today, i learned about bulk head pattern and how it makes the system resilient to failure, resource exhaustion. In this blog i jot down notes on this pattern for better understanding. </p><p class="wp-block-paragraph">In today’s world of distributed systems and microservices, resiliency is key to ensuring applications are robust and can withstand failures. </p><p class="wp-block-paragraph">The <strong>Bulkhead Pattern</strong> is a design principle used to improve system resilience by <strong>isolating</strong> different parts of a system to prevent failure in one component from cascading to others. </p><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">What is the Bulkhead Pattern?</h2><p class="wp-block-paragraph">The term “bulkhead” originates from shipbuilding, where bulkheads are partitions that divide a ship into separate compartments. If one compartment is breached, the others remain intact, preventing the entire ship from sinking. Similarly, in software design, the Bulkhead Pattern isolates components or services so that a failure in one part does not bring down the entire system.</p><figure class="wp-block-image aligncenter size-large"><img alt="" class="wp-image-1994" data-recalc-dims="1" decoding="async" height="426" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/12/image-34.png?resize=487%2C426&amp;ssl=1" width="487"/></figure><p class="wp-block-paragraph">In software systems, bulkheads:</p><ul class="wp-block-list"><li><strong>Isolate resources</strong> (e.g., threads, database connections, or network calls) for different components.</li><li>Limit the scope of failures.</li><li>Allow other parts of the system to continue functioning even if one part is degraded or completely unavailable.</li></ul><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">Example</h2><p class="wp-block-paragraph">Consider an e-commerce application with a <strong>product-service</strong> that has two endpoints</p><ol class="wp-block-list" start="1"><li><code>/product/{id}</code> – This endpoint gives detailed information about a specific product, including ratings and reviews. It depends on the <strong>rating-service</strong>.</li><li><code>/products</code> – This endpoint provides a catalog of products based on search criteria. It does not depend on any external services.</li></ol><figure class="wp-block-image aligncenter size-large"><img alt="" class="wp-image-2000" data-recalc-dims="1" decoding="async" height="275" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/12/image-35.png?resize=966%2C275&amp;ssl=1" width="966"/></figure><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">Consider, with a fixed amount of resource allocated to <strong>product-service </strong> is loaded with<code> /product/{id}</code> calls, then they can monopolize the thread pool. This delays <code>/products</code> requests, causing users to experience slowness even though these requests are independent. Which leads to resource exhaustion and failures. </p><p class="wp-block-paragraph"></p><figure class="wp-block-image aligncenter size-large"><img alt="" class="wp-image-2001" data-recalc-dims="1" decoding="async" height="279" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/12/image-36.png?resize=576%2C279&amp;ssl=1" width="576"/></figure><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">With bulkhead pattern, we can allocate separate client, connection pools to isolate the service interaction. we can implement bulkhead by allocating some connection pool (10) to  <code>/product/{id}</code> requests and <code>/products</code> requests have a different connection pool (5) . </p><figure class="wp-block-image aligncenter size-large"><img alt="" class="wp-image-2004" data-recalc-dims="1" decoding="async" height="443" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/12/image-37.png?resize=729%2C443&amp;ssl=1" width="729"/></figure><p class="wp-block-paragraph">Even if <code>/product/{id}</code> requests are slow or encounter high traffic, <code>/products</code> requests remain unaffected.</p><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">Scenarios Where the Bulkhead Pattern is Needed</h2><ol class="wp-block-list" start="1"><li><strong>Microservices with Shared Resources –</strong> In a microservices architecture, multiple services might share limited resources such as database connections or threads. If one service experiences a surge in traffic or a failure, it can exhaust these shared resources, impacting all other services. Bulkheading ensures each service gets a dedicated pool of resources, isolating the impact of failures.</li><li><strong>Prioritizing Critical Workloads</strong> – In systems with mixed workloads (e.g., processing user transactions and generating reports), critical operations like transaction processing must not be delayed or blocked by less critical tasks. Bulkheading allocates separate resources to ensure critical tasks have priority.</li><li><strong>Third-Party API Integration</strong> – When an application depends on multiple external APIs, one slow or failing API can delay the entire application if not isolated. Using bulkheads ensures that issues with one API do not affect interactions with others.</li><li><strong>Multi-Tenant Systems</strong> – In SaaS applications serving multiple tenants, a single tenant’s high resource consumption or failure should not degrade the experience for others. Bulkheads can segregate resources per tenant to maintain service quality.</li><li><strong>Cloud-Native Applications</strong> – In cloud environments, services often scale independently. A spike in one service’s load should not overwhelm shared backend systems. Bulkheads help isolate and manage these spikes.</li><li><strong>Event-Driven Systems</strong> – In event-driven architectures with message queues, processing backlogs for one type of event can delay others. By applying the Bulkhead Pattern, separate processing pipelines can handle different event types independently.</li></ol><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">What are the Key Points of the Bulkhead Pattern? (Simplified)</h2><ul class="wp-block-list"><li><strong>Define Partitions</strong> – (Think of a ship) it’s divided into compartments (partitions) to keep water from flooding the whole ship if one section gets damaged. In software, these partitions are designed around how the application works and its technical needs.</li><li><strong>Designing with Context </strong>– If you’re using a design approach like DDD (Domain-Driven Design), make sure your bulkheads (partitions) match the business logic boundaries.</li><li><strong>Choosing Isolation Levels</strong> – Decide how much isolation is needed. For example: Threads for lightweight tasks. Separate containers or virtual machines for more critical separations. Balance between keeping things separate and the costs or extra effort involved.</li><li><strong>Combining Other Techniques</strong> – Bulkheads work even better with patterns like Retry, <a href="https://parottasalna.com/2024/12/29/learning-notes-17-circuit-breaker-pattern-cloud-pattern/">Circuit Breaker</a>, Throttling.</li><li><strong>Monitoring</strong> – Keep an eye on each partition’s performance. If one starts getting overloaded, you can adjust resources or change limits.</li></ul><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">When Should You Use the Bulkhead Pattern?</h2><ul class="wp-block-list"><li><strong>To Isolate Critical Resources</strong> – If one part of your system fails, other parts can keep working. For example, you don’t want search functionality to stop working because the reviews section is down.</li></ul><ul class="wp-block-list"><li><strong>To Prioritize Important Work </strong>– For example, make sure payment processing (critical) is separate from background tasks like sending emails.</li><li><strong>To Avoid Cascading Failures</strong> – If one part of the system gets overwhelmed, it won’t drag down everything else.</li></ul><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">When Should You Avoid It?</h2><ul class="wp-block-list"><li><strong>Complexity Isn’t Needed</strong> – If your system is simple, adding bulkheads might just make it harder to manage.</li></ul><ul class="wp-block-list"><li><strong>Resource Efficiency is Critical</strong> – Sometimes, splitting resources into separate pools can mean less efficient use of those resources. If every thread, connection, or container is underutilized, this might not be the best approach.</li></ul><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">Challenges and Best Practices</h2><ol class="wp-block-list" start="1"><li><strong>Overhead:</strong> Maintaining separate resource pools can increase system complexity and resource utilization.</li><li><strong>Resource Sizing:</strong> Properly sizing the pools is critical to ensure resources are efficiently utilized without bottlenecks.</li><li><strong>Monitoring:</strong> Use tools to monitor the health and performance of each resource pool to detect bottlenecks or saturation.</li></ol><h2 class="wp-block-heading">References: </h2><ol class="wp-block-list"><li>AWS <a href="https://aws.amazon.com/blogs/containers/building-a-fault-tolerant-architecture-with-a-bulkhead-pattern-on-aws-app-mesh/">https://aws.amazon.com/blogs/containers/building-a-fault-tolerant-architecture-with-a-bulkhead-pattern-on-aws-app-mesh/</a></li><li>Resilience <a href="https://resilience4j.readme.io/docs/bulkhead">https://resilience4j.readme.io/docs/bulkhead</a></li><li><a href="https://medium.com/nerd-for-tech/bulkhead-pattern-distributed-design-pattern-c673d5e81523">https://medium.com/nerd-for-tech/bulkhead-pattern-distributed-design-pattern-c673d5e81523</a></li><li>Microsoft <a href="https://learn.microsoft.com/en-us/azure/architecture/patterns/bulkhead">https://learn.microsoft.com/en-us/azure/architecture/patterns/bulkhead</a></li></ol>
