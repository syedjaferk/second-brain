<p class="wp-block-paragraph"></p><p class="wp-block-paragraph">Today, i learnt about how idempotent post api can prevent us from processing duplicate request. In this blog i jot down notes on how to handle Idempotent Post Requests for future reference. </p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">Building an <strong>idempotent POST API</strong> ensures that making the same request multiple times produces the same outcome, without unintended side effects. This behavior is not default for POST requests, which are designed to create resources. However, idempotence can be achieved through careful design.</p><figure class="wp-block-image size-large"><img alt="" class="wp-image-2544" data-recalc-dims="1" decoding="async" height="920" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2025/01/image-72.png?resize=1854%2C920&amp;ssl=1" width="1854"/></figure><h2 class="wp-block-heading">What is Idempotency?</h2><p class="wp-block-paragraph">Idempotency means that a request can be made multiple times, and the result will remain consistent. For example:</p><ul class="wp-block-list"><li>A POST request to create a resource should not create duplicate entries when retried.</li><li>The response for a repeated request should be identical to the first response.</li></ul><p class="wp-block-paragraph">Idempotent POST APIs are crucial in scenarios like</p><ul class="wp-block-list"><li>Payment processing (to avoid duplicate charges).</li><li>Retry mechanisms for unreliable networks.</li><li>APIs handling asynchronous operations.</li></ul><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">Steps to Build an Idempotent POST API</h2><h3 class="wp-block-heading">Step 1: Include an Idempotency Key</h3><ul class="wp-block-list"><li>The <strong>idempotency key</strong> is a unique identifier for the request, typically generated by the client (e.g., a UUID or unique transaction ID).</li><li>The server uses this key to determine whether the request has already been processed.</li></ul><pre class="wp-block-syntaxhighlighter-code">{    "idempotencyKey": "123e4567-e89b-12d3-a456-426614174000",    "data": {        "name": "Alice",        "email": "alice@example.com"    }}</pre><p class="wp-block-paragraph"></p><h3 class="wp-block-heading"><span style="text-decoration: underline">Step 2: Store and Manage Idempotency Keys</span></h3><p class="wp-block-paragraph">The server must store the <code>idempotency key</code> and associate it with the request’s outcome to ensure consistency across retries.</p><p class="wp-block-paragraph"><strong>Check for Existing Key</strong></p><ul class="wp-block-list"><li>When a request is received, check if the <code>idempotency key</code> exists in the database or cache.</li><li>If the key exists, return the stored response.</li></ul><p class="wp-block-paragraph"><strong>Process New Requests</strong></p><ul class="wp-block-list"><li>If the key is not found, process the request and store the key with the response.</li></ul><p class="wp-block-paragraph"><strong>Ensure Atomicity</strong></p><ul class="wp-block-list"><li>Use transactions to atomically process the request and store the idempotency key.</li></ul><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"></p><h3 class="wp-block-heading"><span style="text-decoration: underline">Step 3: Database Design for Idempotency</span></h3><p class="wp-block-paragraph">The database should store idempotency keys along with their associated responses and metadata.</p><pre class="wp-block-syntaxhighlighter-code">CREATE TABLE idempotency_keys (    idempotency_key UUID PRIMARY KEY,    response_data JSONB,    created_at TIMESTAMP DEFAULT NOW());</pre><ul class="wp-block-list"><li><code><strong>idempotency_key</strong></code>: A unique identifier for the request.</li><li><code><strong>response_data</strong></code>: The stored response.</li><li><code><strong>created_at</strong></code>: A timestamp to manage expiry.</li></ul><p class="wp-block-paragraph"></p><h3 class="wp-block-heading"><span style="text-decoration: underline">Step 4: Implement Expiry for Idempotency Keys</span></h3><ul class="wp-block-list"><li>Define how long idempotency keys should be stored (e.g., 24 hours).</li><li>Use a background job to delete expired keys to avoid excessive storage.</li></ul><pre class="wp-block-syntaxhighlighter-code">DELETE FROM idempotency_keys WHERE created_at &lt; NOW() - INTERVAL '24 hours';</pre><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"></p><h3 class="wp-block-heading"><span style="text-decoration: underline">Step 5: Handle Consistent Responses</span></h3><p class="wp-block-paragraph">Ensure that the response for a repeated request with the same <code>idempotency key</code> is identical to the first response.</p><p class="wp-block-paragraph"></p><h3 class="wp-block-heading"><span style="text-decoration: underline">Step 6: Handle Edge Cases</span></h3><ul class="wp-block-list"><li><strong>Duplicate Resource Creation</strong>: Use unique constraints in the database to prevent duplicates.</li><li><strong>External Side Effects</strong>: For example, if the API sends emails or triggers external services, ensure these operations are also idempotent.</li></ul><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">Sample Flask App</h2><pre class="wp-block-syntaxhighlighter-code">from flask import Flask, request, jsonifyimport uuidapp = Flask(__name__)# In-memory storage for simplicityidempotency_store = {}@app.route('/create', methods=['POST'])def create_resource():    idempotency_key = request.json.get('idempotencyKey')    data = request.json.get('data')    if not idempotency_key:        return jsonify({"error": "Idempotency key is required"}), 400    # Check if the key already exists    if idempotency_key in idempotency_store:        return jsonify(idempotency_store[idempotency_key]), 200    # Process the request    resource_id = str(uuid.uuid4())    response_data = {"id": resource_id, "data": data}    # Store the key and response    idempotency_store[idempotency_key] = response_data    return jsonify(response_data), 201if __name__ == '__main__':    app.run(debug=True)</pre><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">Enhancements for Production</h2><ul class="wp-block-list"><li><strong>Persistent Storage</strong>: Use a database like PostgreSQL or Redis for storing idempotency keys .</li><li><strong>Concurrency Handling</strong>: Use locks or unique constraints to handle concurrent requests with the same key.</li><li><strong>Scalability</strong>: Distribute idempotency key storage across multiple nodes using a shared cache or distributed database.</li><li><strong>Security</strong>: Validate and sanitize the idempotency key to prevent injection attacks.</li></ul><p class="wp-block-paragraph"></p>
