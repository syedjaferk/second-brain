<p class="wp-block-paragraph">Load balancing helps distribute client requests across multiple servers to ensure high availability, performance, and reliability. <strong>Weighted Round Robin Load Balancing</strong> is an extension of the round-robin algorithm, where each server is assigned a weight based on its capacity or performance capabilities. This approach ensures that more powerful servers handle more traffic, resulting in a more efficient distribution of the load.</p><h3 class="wp-block-heading">What is Weighted Round Robin Load Balancing?</h3><p class="wp-block-paragraph"><strong>Weighted Round Robin Load Balancing</strong> assigns a weight to each server. The weight determines how many requests each server should handle relative to the others. Servers with higher weights receive more requests compared to those with lower weights. This method is useful when backend servers have different processing capabilities or resources.</p><h3 class="wp-block-heading">Step-by-Step Implementation with Docker</h3><h4 class="wp-block-heading">Step 1: Create Dockerfiles for Each Flask Application</h4><p class="wp-block-paragraph">We’ll use the same three Flask applications (<code>app1.py</code>, <code>app2.py</code>, and <code>app3.py</code>) as in previous examples.</p><ul class="wp-block-list"><li><strong>Flask App 1 (<code>app1.py</code>):</strong></li></ul><pre class="wp-block-syntaxhighlighter-code">from flask import Flaskapp = Flask(__name__)@app.route("/")def home():    return "Hello from Flask App 1!"@app.route("/data")def data():    return "Data from Flask App 1!"if __name__ == "__main__":    app.run(host="0.0.0.0", port=5001)</pre><ul class="wp-block-list"><li><strong>Flask App 2 </strong>(<code>app2.py</code>):</li></ul><pre class="wp-block-syntaxhighlighter-code">from flask import Flaskapp = Flask(__name__)@app.route("/")def home():    return "Hello from Flask App 2!"@app.route("/data")def data():    return "Data from Flask App 2!"if __name__ == "__main__":    app.run(host="0.0.0.0", port=5002)</pre><ul class="wp-block-list"><li>Flask App 3 (<code>app3.py</code>):</li></ul><pre class="wp-block-syntaxhighlighter-code">from flask import Flaskapp = Flask(__name__)@app.route("/")def home():    return "Hello from Flask App 3!"@app.route("/data")def data():    return "Data from Flask App 3!"if __name__ == "__main__":    app.run(host="0.0.0.0", port=5003)</pre><h4 class="wp-block-heading">Step 2: Create Dockerfiles for Each Flask Application</h4><p class="wp-block-paragraph">Create Dockerfiles for each of the Flask applications:</p><ul class="wp-block-list"><li><strong>Dockerfile for Flask App 1 (<code>Dockerfile.app1</code>)</strong>:</li></ul><pre class="wp-block-syntaxhighlighter-code"># Use the official Python image from Docker HubFROM python:3.9-slim# Set the working directory inside the containerWORKDIR /app# Copy the application file into the containerCOPY app1.py .# Install Flask inside the containerRUN pip install Flask# Expose the port the app runs onEXPOSE 5001# Run the applicationCMD ["python", "app1.py"]</pre><ul class="wp-block-list"><li><strong>Dockerfile for Flask App 2 (<code>Dockerfile.app2</code>)</strong>:</li></ul><pre class="wp-block-syntaxhighlighter-code">FROM python:3.9-slimWORKDIR /appCOPY app2.py .RUN pip install FlaskEXPOSE 5002CMD ["python", "app2.py"]</pre><ul class="wp-block-list"><li><strong>Dockerfile for Flask App 3 (<code>Dockerfile.app3</code>)</strong>:</li></ul><pre class="wp-block-syntaxhighlighter-code">FROM python:3.9-slimWORKDIR /appCOPY app3.py .RUN pip install FlaskEXPOSE 5003CMD ["python", "app3.py"]</pre><p class="wp-block-paragraph"></p><h4 class="wp-block-heading">Step 3: Create the HAProxy Configuration File</h4><p class="wp-block-paragraph">Create an HAProxy configuration file (<code>haproxy.cfg</code>) to implement Weighted Round Robin Load Balancing</p><pre class="wp-block-syntaxhighlighter-code">global    log stdout format raw local0    daemondefaults    log     global    mode    http    option  httplog    option  dontlognull    timeout connect 5000ms    timeout client  50000ms    timeout server  50000msfrontend http_front    bind *:80    default_backend serversbackend servers    balance roundrobin    server server1 app1:5001 weight 2 check    server server2 app2:5002 weight 1 check    server server3 app3:5003 weight 3 check</pre><p class="wp-block-paragraph"><strong>Explanation:</strong></p><ul class="wp-block-list"><li>The <code>balance roundrobin</code> directive tells HAProxy to use the Round Robin load balancing algorithm.</li><li>The <code>weight</code> option for each server specifies the weight associated with each server:<ul class="wp-block-list"><li><strong><code>server1</code></strong> (App 1) has a weight of <strong>2</strong>.</li><li><strong><code>server2</code></strong> (App 2) has a weight of <strong>1</strong>.</li><li><strong><code>server3</code></strong> (App 3) has a weight of <strong>3</strong>.</li></ul></li><li>Requests will be distributed based on these weights: App 3 will receive the most requests, App 2 the least, and App 1 will be in between.</li></ul><h4 class="wp-block-heading">Step 4: Create a Dockerfile for HAProxy</h4><p class="wp-block-paragraph">Create a Dockerfile for HAProxy (<code>Dockerfile.haproxy</code>):</p><pre class="wp-block-syntaxhighlighter-code"># Use the official HAProxy image from Docker HubFROM haproxy:latest# Copy the custom HAProxy configuration file into the containerCOPY haproxy.cfg /usr/local/etc/haproxy/haproxy.cfg# Expose the port for HAProxyEXPOSE 80</pre><h4 class="wp-block-heading">Step 5: Create a <code>docker-compose.yml</code> File</h4><p class="wp-block-paragraph">To manage all the containers together, create a <code>docker-compose.yml</code> file</p><pre class="wp-block-syntaxhighlighter-code">version: '3'services:  app1:    build:      context: .      dockerfile: Dockerfile.app1    container_name: flask_app1    ports:      - "5001:5001"  app2:    build:      context: .      dockerfile: Dockerfile.app2    container_name: flask_app2    ports:      - "5002:5002"  app3:    build:      context: .      dockerfile: Dockerfile.app3    container_name: flask_app3    ports:      - "5003:5003"  haproxy:    build:      context: .      dockerfile: Dockerfile.haproxy    container_name: haproxy    ports:      - "80:80"    depends_on:      - app1      - app2      - app3</pre><p class="wp-block-paragraph"><strong>Explanation:</strong></p><ul class="wp-block-list"><li>The <code>docker-compose.yml</code> file defines the services (<code>app1</code>, <code>app2</code>, <code>app3</code>, and <code>haproxy</code>) and their respective configurations.</li><li>HAProxy depends on the three Flask applications to be up and running before it starts.</li></ul><h4 class="wp-block-heading">Step 6: Build and Run the Docker Containers</h4><p class="wp-block-paragraph">Run the following command to build and start all the containers</p><pre class="wp-block-syntaxhighlighter-code">docker-compose up --build</pre><p class="wp-block-paragraph">This command builds Docker images for all three Flask apps and HAProxy, then starts them.</p><h4 class="wp-block-heading">Step 7: Test the Load Balancer</h4><p class="wp-block-paragraph">Open your browser or use <code>curl</code> to make requests to the HAProxy server</p><pre class="wp-block-syntaxhighlighter-code">curl http://localhost/curl http://localhost/data</pre><p class="wp-block-paragraph"><strong>Observation:</strong></p><ul class="wp-block-list"><li>With Weighted Round Robin Load Balancing, you should see that requests are distributed according to the weights specified in the HAProxy configuration.</li><li>For example, <strong>App 3</strong> should receive three times more requests than <strong>App 2</strong>, and <strong>App 1</strong> should receive twice as many as <strong>App 2</strong>.</li></ul><h4 class="wp-block-heading">Conclusion</h4><p class="wp-block-paragraph">By implementing Weighted Round Robin Load Balancing with HAProxy, you can distribute traffic more effectively according to the capacity or performance of each backend server. This approach helps optimize resource utilization and ensures a balanced load across servers.</p>
