<p class="wp-block-paragraph"></p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">When we talk about databases, we usually think of inserting, updating, or deleting data. But before doing any of that, we must first <strong>define the structure</strong> the <em>blueprint</em> of how data will be stored.</p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">That’s where <strong>DDL (Data Definition Language)</strong> comes in.</p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">What is DDL?</h2><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"><strong>DDL stands for Data Definition Language.</strong><br/>It is a subset of SQL used to <strong>define, modify, or remove database structures</strong> such as tables, schemas, indexes, and views.</p><p class="wp-block-paragraph">In short DDL defines the <strong>structure</strong> of your database.</p><figure class="wp-block-table"><table class="has-fixed-layout"><thead><tr><th>Command</th><th>Description</th></tr></thead><tbody><tr><td><strong>CREATE</strong></td><td>Used to create database objects like tables, views, or schemas</td></tr><tr><td><strong>ALTER</strong></td><td>Used to modify the structure of existing objects</td></tr><tr><td><strong>DROP</strong></td><td>Used to delete database objects</td></tr><tr><td><strong>TRUNCATE</strong></td><td>Used to remove all rows from a table instantly</td></tr><tr><td><strong>RENAME</strong></td><td>Used to rename database objects</td></tr></tbody></table></figure><p class="wp-block-paragraph"></p><pre class="wp-block-syntaxhighlighter-code">CREATE TABLE customers ( customer_id SERIAL PRIMARY KEY,name VARCHAR(100) NOT NULL,email VARCHAR(100) UNIQUE,age INT CHECK ( age &gt;= 18 ),created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP);ALTER TABLE customers ADD COLUMN phone VARCHAR(15);DROP TABLE customers;TRUNCATE TABLE customers;</pre><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">The <code>CREATE TABLE</code> Command</h2><p class="wp-block-paragraph">The most frequently used DDL command is <code>CREATE TABLE</code>.<br/>It defines the <strong>structure of a table</strong> the columns, their data types, and constraints.</p><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">Example 1: Basic Table Creation</h2><pre class="wp-block-syntaxhighlighter-code">CREATE TABLE employees (    emp_id SERIAL,    emp_name VARCHAR(100),    salary NUMERIC(10,2),    joining_date DATE);</pre><p class="wp-block-paragraph">Here we created an <code>employees</code> table with 4 columns.<br/>But there are <strong>no rules</strong> yet meaning duplicates or NULLs are allowed.</p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"><strong>Adding Constraints</strong></p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">Constraints help <strong>maintain data integrity</strong> and <strong>define rules</strong> for your data.</p><p class="wp-block-paragraph">Let’s understand all of them with examples.</p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"><strong>PRIMARY KEY</strong></p><p class="wp-block-paragraph">A <code>PRIMARY KEY</code> uniquely identifies each record in the table and doesn’t allow NULL values.</p><p class="wp-block-paragraph"></p><pre class="wp-block-syntaxhighlighter-code">CREATE TABLE employees (    emp_id SERIAL PRIMARY KEY,    emp_name VARCHAR(100),    salary NUMERIC(10,2),    joining_date DATE);</pre><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"><strong>NOT NULL</strong></p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">Ensures a column cannot have <code>NULL</code> values.</p><pre class="wp-block-syntaxhighlighter-code">CREATE TABLE employees (    emp_id SERIAL PRIMARY KEY,    emp_name VARCHAR(100) NOT NULL,    salary NUMERIC(10,2),    joining_date DATE NOT NULL);</pre><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"><strong>UNIQUE</strong></p><p class="wp-block-paragraph">Ensures all values in a column are different (can allow a single NULL).</p><pre class="wp-block-syntaxhighlighter-code">CREATE TABLE employees (    emp_id SERIAL PRIMARY KEY,    email VARCHAR(255) UNIQUE,    emp_name VARCHAR(100) NOT NULL);</pre><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"><strong>CHECK</strong></p><p class="wp-block-paragraph">Adds a condition that must be satisfied for every row.</p><pre class="wp-block-syntaxhighlighter-code">CREATE TABLE employees (    emp_id SERIAL PRIMARY KEY,    emp_name VARCHAR(100) NOT NULL,    salary NUMERIC(10,2) CHECK (salary &gt; 0),    joining_date DATE);</pre><p class="wp-block-paragraph">If anyone tries to insert a negative salary ❌ the database will reject it.</p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"><strong>DEFAULT</strong></p><p class="wp-block-paragraph">Assigns a default value if no value is provided.</p><pre class="wp-block-syntaxhighlighter-code">CREATE TABLE employees (    emp_id SERIAL PRIMARY KEY,    emp_name VARCHAR(100) NOT NULL,    salary NUMERIC(10,2) DEFAULT 30000,    joining_date DATE DEFAULT CURRENT_DATE);</pre><p class="wp-block-paragraph">If <code>salary</code> or <code>joining_date</code> isn’t given, PostgreSQL fills them automatically.</p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"><strong>FOREIGN KEY</strong></p><p class="wp-block-paragraph">Creates a link between two tables ensuring referential integrity.</p><pre class="wp-block-syntaxhighlighter-code">CREATE TABLE departments (    dept_id SERIAL PRIMARY KEY,    dept_name VARCHAR(50) NOT NULL);CREATE TABLE employees (    emp_id SERIAL PRIMARY KEY,    emp_name VARCHAR(100) NOT NULL,    dept_id INT REFERENCES departments(dept_id) ON DELETE CASCADE);</pre><ol class="wp-block-list"><li><code>dept_id</code> in <code>employees</code> refers to <code>departments(dept_id)</code></li></ol><p class="wp-block-paragraph"><code>2. ON DELETE CASCADE</code> ensures if a department is deleted, all its employees are deleted too.</p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">Example 2: Combining All Constraints</h2><p class="wp-block-paragraph">Let’s bring everything together.</p><p class="wp-block-paragraph"></p><pre class="wp-block-syntaxhighlighter-code">CREATE TABLE employees (    emp_id SERIAL PRIMARY KEY,    emp_name VARCHAR(100) NOT NULL,    email VARCHAR(100) UNIQUE,    salary NUMERIC(10,2) CHECK (salary &gt; 0),    dept_id INT REFERENCES departments(dept_id) ON DELETE SET NULL,    joining_date DATE DEFAULT CURRENT_DATE);</pre><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">Modifying the Table (ALTER)</h2><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">Once created, you can change your table using <code>ALTER TABLE</code>.</p><figure class="wp-block-table"><table class="has-fixed-layout"><thead><tr><th>Operation</th><th>Example</th></tr></thead><tbody><tr><td>Add a column</td><td><code>ALTER TABLE employees ADD COLUMN phone VARCHAR(15);</code></td></tr><tr><td>Modify data type</td><td><code>ALTER TABLE employees ALTER COLUMN salary TYPE NUMERIC(12,2);</code></td></tr><tr><td>Drop a column</td><td><code>ALTER TABLE employees DROP COLUMN phone;</code></td></tr><tr><td>Add constraint</td><td><code>ALTER TABLE employees ADD CONSTRAINT unique_email UNIQUE(email);</code><br/><br/></td></tr></tbody></table></figure><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">Understanding DDL and mastering <code>CREATE TABLE</code> with constraints is <strong>the foundation of database design</strong>.</p><p class="wp-block-paragraph"><br/>A well-defined schema ensures <strong>data consistency, integrity, and performance</strong> from the very beginning.</p>
