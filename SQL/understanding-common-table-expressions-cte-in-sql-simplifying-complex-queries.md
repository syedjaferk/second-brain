<p class="wp-block-paragraph"></p><p class="wp-block-paragraph">In SQL, we often deal with queries that involve multiple subqueries, aggregations, or recursive lookups.</p><p class="wp-block-paragraph"><br/>When these start to get long and unreadable, that’s where <strong>CTE (Common Table Expressions)</strong> come in.</p><p class="wp-block-paragraph">Let’s break it down from the basics, </p><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">What is a CTE?</h2><p class="wp-block-paragraph">A <strong>Common Table Expression (CTE)</strong> is a <strong>temporary named result set</strong> that exists only within the scope of a single SQL statement.<br/>It’s defined using the <code>WITH</code> keyword, and acts much like a temporary view.</p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">Think of a CTE as a way to <strong>store the result of a subquery</strong> and reuse it in your main query — while keeping your SQL <strong>clean, readable, and modular</strong>.</p><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">Why Do We Need a CTE?</h2><p class="wp-block-paragraph">Without a CTE, you might end up writing deeply nested subqueries that are hard to read or debug.</p><p class="wp-block-paragraph">Here’s what CTEs help with,</p><figure class="wp-block-table"><table class="has-fixed-layout"><thead><tr><th>Need</th><th>Description</th></tr></thead><tbody><tr><td><strong>Readability</strong></td><td>Break down a complex query into smaller, understandable chunks.</td></tr><tr><td><strong>Reusability</strong></td><td>Reference the same derived dataset multiple times in one query.</td></tr><tr><td><strong>Recursive Operations</strong></td><td>Ideal for hierarchical or tree-structured data (like org charts).</td></tr><tr><td><strong>Debuggability</strong></td><td>Easier to test each CTE individually for correctness.</td></tr></tbody></table></figure><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">Basic Syntax of CTE</h2><pre class="wp-block-syntaxhighlighter-code">WITH cte_name AS (    SELECT column1, column2    FROM table_name    WHERE condition)SELECT *FROM cte_nameWHERE column1 &gt; 10;</pre><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">The CTE is created <strong>before</strong> the main <code>SELECT</code> (or <code>UPDATE</code>, <code>DELETE</code>, etc.) query, and can be referenced <strong>like a temporary table</strong>.</p><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">Example 1: Simplifying a Subquery</h2><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"><strong>Without CTE</strong></p><pre class="wp-block-syntaxhighlighter-code">SELECT department_id, COUNT(*)FROM employeesWHERE department_id IN (    SELECT department_id    FROM departments    WHERE location = 'Chennai')GROUP BY department_id;</pre><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"><strong>With CTE</strong></p><pre class="wp-block-syntaxhighlighter-code">WITH chennai_departments AS (    SELECT department_id    FROM departments    WHERE location = 'Chennai')SELECT department_id, COUNT(*)FROM employeesWHERE department_id IN (SELECT department_id FROM chennai_departments)GROUP BY department_id;</pre><p class="wp-block-paragraph"></p><p class="wp-block-paragraph"><strong>Easier to read</strong>, and we can reuse <code>chennai_departments</code> elsewhere.</p><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">Example 2: Multiple CTEs in a Single Query</h2><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">You can chain multiple CTEs by separating them with commas.</p><pre class="wp-block-syntaxhighlighter-code">WITH sales_cte AS (    SELECT salesperson_id, SUM(amount) AS total_sales    FROM sales    GROUP BY salesperson_id),top_sales_cte AS (    SELECT salesperson_id    FROM sales_cte    WHERE total_sales &gt; 50000)SELECT e.name, s.total_salesFROM employees eJOIN sales_cte s ON e.id = s.salesperson_idWHERE e.id IN (SELECT salesperson_id FROM top_sales_cte);</pre><p class="wp-block-paragraph"> </p><h2 class="wp-block-heading">Example 3: Using CTE with UPDATE</h2><p class="wp-block-paragraph">CTEs can also be used with <code>UPDATE</code>, <code>DELETE</code>, or <code>INSERT</code> statements.</p><p class="wp-block-paragraph"></p><pre class="wp-block-syntaxhighlighter-code">WITH outdated_products AS (    SELECT id    FROM products    WHERE last_updated &lt; NOW() - INTERVAL '1 year')UPDATE productsSET is_active = FALSEWHERE id IN (SELECT id FROM outdated_products);</pre><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">This approach makes bulk updates <strong>cleaner and more readable</strong>.</p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">CTEs are one of those SQL features that greatly improve query clarity without affecting logic or performance negatively.</p><p class="wp-block-paragraph"><br/>If your query feels too long or nested it’s time to introduce a <strong>CTE</strong>.</p><p class="wp-block-paragraph">They not only make queries more modular and maintainable, but also empower you to handle recursive patterns elegantly.</p>
