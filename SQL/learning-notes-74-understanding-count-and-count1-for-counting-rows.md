<p class="wp-block-paragraph"></p><p class="wp-block-paragraph">When working with SQL, counting rows in a table is a common task. Two widely used methods for this are COUNT(*) and COUNT(1). While both seem similar, they often spark debates among developers regarding performance, clarity, and best practices. </p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">In this blog, i jot down details on what these functions do, their performance implications, and which one to use.</p><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">COUNT(*)</h2><p class="wp-block-paragraph">COUNT(*) counts all the rows in a table, regardless of whether the columns contain NULL values or not. It does not focus on any particular column; instead, it considers every row present in the table.</p><p class="wp-block-paragraph">It is straightforward and does exactly what you’d expect—count the total number of rows in the result set.</p><pre class="wp-block-syntaxhighlighter-code">SELECT COUNT(*) FROM employees;</pre><p class="wp-block-paragraph">This query returns the total number of rows in the <code>employees</code> table.</p><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">COUNT(1)</h2><p class="wp-block-paragraph">COUNT(1) also counts all the rows in a table. However, instead of counting actual rows, it evaluates the constant <code>1</code> for each row. The <code>1</code> here is a placeholder and doesn’t refer to any specific column.</p><p class="wp-block-paragraph">The database engine treats COUNT(1) similarly to COUNT(*), making it another way to count rows.</p><pre class="wp-block-syntaxhighlighter-code">SELECT COUNT(1) FROM employees;</pre><p class="wp-block-paragraph">This query performs the same function as COUNT(*), counting all rows in the <code>employees</code> table.</p><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">Key Differences Between COUNT(*) and COUNT(1)</h2><h3 class="wp-block-heading has-medium-font-size">Scope of Counting</h3><ul class="wp-block-list"><li><strong>COUNT(*)</strong> includes every row in the table, as it doesn’t rely on specific columns or values.</li><li><strong>COUNT(1)</strong> evaluates the constant <code>1</code> for each row, effectively counting the rows.<br/></li></ul><h3 class="wp-block-heading has-medium-font-size">Handling NULL Values</h3><p class="wp-block-paragraph">Both functions ignore NULL values because they don’t depend on column-specific data. This is particularly useful when working with tables that contain missing or undefined data.</p><p class="wp-block-paragraph"></p><h3 class="wp-block-heading has-medium-font-size">Syntax and Readability</h3><ul class="wp-block-list"><li><strong>COUNT(*)</strong> is often more immediately understandable since the asterisk (<code>*</code>) clearly signifies “count everything.”</li><li><strong>COUNT(1)</strong> can be slightly less intuitive at first glance, as it might make someone wonder why the constant <code>1</code> is used.</li></ul><p class="wp-block-paragraph"></p><h2 class="wp-block-heading">Readability and Best Practices</h2><h3 class="wp-block-heading has-medium-font-size">Why Readability Matters</h3><p class="wp-block-paragraph">Code readability is crucial, especially in collaborative environments where multiple developers work on the same codebase.<br/></p><h3 class="wp-block-heading">COUNT(*)</h3><p class="wp-block-paragraph">✅ Clearly conveys the intent to count all rows in a table. ✅ Easy for both beginners and experienced developers to understand at first glance.</p><p class="wp-block-paragraph"></p><h3 class="wp-block-heading">COUNT(1)</h3><p class="wp-block-paragraph">❌ While it works the same as COUNT(*), it may confuse someone unfamiliar with its behavior. ❌ It doesn’t explicitly signify “count everything,” making it slightly less intuitive.</p><h2 class="wp-block-heading"></h2><figure class="wp-block-table"><table class="has-fixed-layout"><tbody><tr><th>Feature</th><th>COUNT(*)</th><th>COUNT(1)</th></tr><tr><td><strong>Counts all rows</strong></td><td>✅ Yes</td><td>✅ Yes</td></tr><tr><td><strong>Uses a placeholder</strong></td><td>❌ No</td><td>✅ Yes</td></tr><tr><td><strong>More readable</strong></td><td>✅ Yes</td><td>❌ Less intuitive</td></tr><tr><td><strong>Performance difference</strong></td><td>❌ Negligible</td><td>❌ Negligible</td></tr><tr><td><strong>Recommended</strong></td><td>✅ Yes</td><td>⚠️ Only if team prefers</td></tr></tbody></table></figure><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">In most scenarios, <strong>COUNT(*) is the preferred choice</strong> because it clearly communicates its purpose. While COUNT(1) is equally valid, its slightly ambiguous syntax may cause confusion. Ultimately, the best option is the one that aligns with your <strong>team’s practices</strong> and ensures your code is <strong>easy to understand</strong>.</p>
