<blockquote class="wp-block-quote is-layout-flow wp-block-quote-is-layout-flow"><p class="wp-block-paragraph">Note: Its same as <a href="https://parottasalna.com/2024/06/15/redis-write-through-cache/">write through cache</a>. Only difference is its asynchronous in inserting the values to mongodb. </p></blockquote><p class="wp-block-paragraph">Its an Application level caching, where the application writes the data directly to the redis; and redis will write to the primary db (mongodb in our example). </p><figure class="wp-block-image size-large"><img alt="" class="wp-image-251" data-recalc-dims="1" decoding="async" height="743" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/06/image-38.png?resize=1247%2C743&amp;ssl=1" width="1247"/></figure><h3 class="wp-block-heading" id="heading-steps">Steps:</h3><ol class="wp-block-list"><li>The Application (Fast API), writes the data to the redis.</li><li>Redis will write the data to mongodb. </li><li>The application reads the data in redis, since it’s already written to redis.</li></ol><h3 class="wp-block-heading">Implementation</h3><blockquote class="wp-block-quote is-layout-flow wp-block-quote-is-layout-flow"><p class="wp-block-paragraph">Github: <a href="https://github.com/syedjaferk/redis-cache" rel="noreferrer noopener" target="_blank">https://github.com/syedjaferk/redis-cache</a></p></blockquote><p class="wp-block-paragraph">We are going to create a mock todo application. Let’s run both redis and mongo via docker-compose</p><pre class="wp-block-syntaxhighlighter-code"># docker-compose.ymlversion: '3.8'services:  redisgears:    image: redislabs/redismod:latest    container_name: redis_gears_container    networks:      - my_network    ports:      - "6379:6379"    environment:      - MONGO_URI=mongodb://mongodb_container:27017  mongodb:    image: mongo    container_name: mongodb_container    networks:      - my_network    ports:      - "27017:27017"    command: --bind_ip_allnetworks:  my_network:    driver: bridge</pre><p class="wp-block-paragraph">Run the docker-compose.yml, </p><pre class="wp-block-syntaxhighlighter-code">docker compose up</pre><p class="wp-block-paragraph">Now we have to tell redis that whenever a data comes to it, send it to mongodb aswell. </p><p class="wp-block-paragraph">We can do this communication via <strong>redis-gears and rgsync</strong> packages. Below is the script to tell redis to write it to mongodb. [ Env variable are taken from docker-compose file]</p><pre class="wp-block-syntaxhighlighter-code">from rgsync import RGJSONWriteBehind, RGJSONWriteThroughfrom rgsync.Connectors import MongoConnector, MongoConnectionimport osmongoUrl = os.environ.get('MONGO_URI')connection = MongoConnection("", "", "", "", mongoUrl)db = "test"collection = "todos"movieConnector = MongoConnector(connection, db, collection, 'id')RGJSONWriteBehind(GB, keysPrefix='todos',connector=movieConnector, name='TodoWriteBehind',version='99.99.99')</pre><p class="wp-block-paragraph">Now we have the module to be executed when there is something written to redis. Now we have to send this piece of code inside redis. For that we can use either <strong>gears-cli</strong> tool or <strong>RG.PYEXECUTE </strong>functionality. </p><p class="wp-block-paragraph">In this post we use <strong>RG.PYEXECUTE</strong> via node js script, </p><pre class="wp-block-syntaxhighlighter-code"># script.jsimport fs from "fs";import { createClient } from "redis";const redisConnectionUrl = "redis://127.0.0.1:6379";const pythonFilePath = "app.py";const runWriteBehindRecipe = async () =&gt; {    const requirements = ["rgsync", "pymongo==3.12.0"];    const writeBehindCode = fs.readFileSync(pythonFilePath).toString();    const client = createClient({ url: redisConnectionUrl });    await client.connect();    const params = ["RG.PYEXECUTE", writeBehindCode,    "REQUIREMENTS", ...requirements];    try {        await client.sendCommand(params);        console.log("RedisGears WriteBehind set up completed.");    }    catch (err) {        console.error("RedisGears WriteBehind setup failed !");        console.error(JSON.stringify(err, Object.getOwnPropertyNames(err), 4));    }    process.exit();};runWriteBehindRecipe();</pre><p class="wp-block-paragraph"> Execute this, </p><pre class="wp-block-syntaxhighlighter-code">node script.js</pre><p class="wp-block-paragraph">On running this, packages will get installed inside redis and will be ready to perform <strong>writebehind</strong> caching approach.</p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">Now, everything is set, we can test this by writing a data to redis, and check whether the data is available in mongodb. </p><blockquote class="wp-block-quote is-layout-flow wp-block-quote-is-layout-flow"><p class="wp-block-paragraph">Note: Create a <strong>test</strong> database with <strong>todos</strong> collection in mongodb. </p></blockquote><figure class="wp-block-image size-large"><img alt="" class="wp-image-242" data-recalc-dims="1" decoding="async" height="733" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/06/image-36.png?resize=1127%2C733&amp;ssl=1" width="1127"/></figure><p class="wp-block-paragraph">Now lets test it, Run the below script which inserts the data to Redis. </p><pre class="wp-block-syntaxhighlighter-code">import redisfrom redis.commands.json.path import Pathfrom redis.commands.json import JSONr = redis.Redis(host='localhost', port=6379, decode_responses=True)user = {    "id":"test_id",    "name":"some todo",    "description": "some description"}JSON(r).set("todos:test_id", Path.root_path(), user)</pre><figure class="wp-block-image size-large"><img alt="" class="wp-image-245" data-recalc-dims="1" decoding="async" height="507" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/06/image-37.png?resize=1447%2C507&amp;ssl=1" width="1447"/></figure><p class="wp-block-paragraph">Awesome isn’t. Now we have acheived the write behind cache.</p><p class="wp-block-paragraph">Please try out the code: <a href="https://github.com/syedjaferk/redis-cache">https://github.com/syedjaferk/redis-cache</a></p><p class="wp-block-paragraph"></p><h4 class="wp-block-heading">Advantages:</h4><ol class="wp-block-list"><li><strong>Improved Write Performance</strong>: Writes are faster as they are initially done in the cache only, reducing write latency.</li><li><strong>Reduced Bandwidth Usage</strong>: Fewer write operations to the main memory or disk, as multiple updates to the same data can be coalesced.</li><li><strong>Better Utilization of Cache</strong>: More efficient use of cache space and reduced main storage access.</li></ol><h4 class="wp-block-heading">Disadvantages:</h4><ol class="wp-block-list"><li><strong>Data Inconsistency Risk</strong>: Risk of data loss or inconsistency if the cache is not properly synchronized with the main storage.</li><li><strong>Complex Recovery</strong>: Error recovery and maintaining cache coherence are more complex.</li><li><strong>Higher Complexity</strong>: Requires more sophisticated mechanisms to manage cache evictions and write-backs.</li></ol><h4 class="wp-block-heading">Scenarios to Use:</h4><ol class="wp-block-list"><li><strong>Performance-Critical Applications</strong>: Systems where write performance is critical, such as high-performance computing or real-time data processing.</li><li><strong>High Write-to-Read Ratio</strong>: Workloads with frequent write operations benefit from reduced write latency.</li><li><strong>Temporary Data</strong>: Applications where data integrity is less critical, or the data has a temporary nature, reducing the impact of potential data loss.</li></ol>
