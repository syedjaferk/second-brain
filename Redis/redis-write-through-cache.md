<p class="wp-block-paragraph">Its an Application level caching, where the application writes the data directly to the redis; and redis will write to the primary db (mongodb in our example). </p><figure class="wp-block-image size-large"><img alt="" class="wp-image-230" data-recalc-dims="1" decoding="async" height="733" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/06/image-35.png?resize=1127%2C733&amp;ssl=1" width="1127"/></figure><h3 class="wp-block-heading" id="heading-steps">Steps:</h3><ol class="wp-block-list"><li>The Application (Fast API), writes the data to the redis.</li><li>Redis will write the data to mongodb. </li><li>The application reads the data in redis, since it’s already written to redis.</li></ol><h3 class="wp-block-heading">Implementation</h3><blockquote class="wp-block-quote is-layout-flow wp-block-quote-is-layout-flow"><p class="wp-block-paragraph">Github: <a href="https://github.com/syedjaferk/redis-cache" rel="noreferrer noopener" target="_blank">https://github.com/syedjaferk/redis-cache</a></p></blockquote><p class="wp-block-paragraph">We are going to create a mock todo application. Let’s run both redis and mongo via docker-compose</p><pre class="wp-block-syntaxhighlighter-code"># docker-compose.ymlversion: '3.8'services:  redisgears:    image: redislabs/redismod:latest    container_name: redis_gears_container    networks:      - my_network    ports:      - "6379:6379"    environment:      - MONGO_URI=mongodb://mongodb_container:27017  mongodb:    image: mongo    container_name: mongodb_container    networks:      - my_network    ports:      - "27017:27017"    command: --bind_ip_allnetworks:  my_network:    driver: bridge</pre><p class="wp-block-paragraph">Run the docker-compose.yml, </p><pre class="wp-block-syntaxhighlighter-code">docker compose up</pre><p class="wp-block-paragraph">Now we have to tell redis that whenever a data comes to it, send it to mongodb aswell. </p><p class="wp-block-paragraph">We can do this communication via <strong>redis-gears and rgsync</strong> packages. Below is the script to tell redis to write it to mongodb. [ Env variable are taken from docker-compose file]</p><pre class="wp-block-syntaxhighlighter-code">from rgsync import RGJSONWriteBehind, RGJSONWriteThroughfrom rgsync.Connectors import MongoConnector, MongoConnectionimport osmongoUrl = os.environ.get('MONGO_URI')connection = MongoConnection("", "", "", "", mongoUrl)db = "test"collection = "todos"movieConnector = MongoConnector(connection, db, collection, 'id')RGJSONWriteThrough(GB, keysPrefix='todos',connector=movieConnector, name='TodoWriteThrough',version='99.99.99')</pre><p class="wp-block-paragraph">Now we have the module to be executed when there is something written to redis. Now we have to send this piece of code inside redis. For that we can use either <strong>gears-cli</strong> tool or <strong>RG.PYEXECUTE </strong>functionality. </p><p class="wp-block-paragraph">In this post we use <strong>RG.PYEXECUTE</strong> via node js script, </p><pre class="wp-block-syntaxhighlighter-code"># script.jsimport fs from "fs";import { createClient } from "redis";const redisConnectionUrl = "redis://127.0.0.1:6379";const pythonFilePath = "app.py";const runWriteBehindRecipe = async () =&gt;    }    catch (err) {        console.error("RedisGears WriteBehind setup failed !");        console.error(JSON.stringify(err, Object.getOwnPropertyNames(err), 4));    }    process.exit();};runWriteBehindRecipe();</pre><p class="wp-block-paragraph"> Execute this, </p><pre class="wp-block-syntaxhighlighter-code">node script.js</pre><p class="wp-block-paragraph">On running this, packages will get installed inside redis and will be ready to perform <strong>writethrough</strong> caching approach. </p><p class="wp-block-paragraph"></p><p class="wp-block-paragraph">Now, everything is set, we can test this by writing a data to redis, and check whether the data is available in mongodb. </p><blockquote class="wp-block-quote is-layout-flow wp-block-quote-is-layout-flow"><p class="wp-block-paragraph">Note: Create a <strong>test</strong> database with <strong>todos</strong> collection in mongodb. </p></blockquote><figure class="wp-block-image size-large"><img alt="" class="wp-image-242" data-recalc-dims="1" decoding="async" height="733" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/06/image-36.png?resize=1127%2C733&amp;ssl=1" width="1127"/></figure><p class="wp-block-paragraph">Now lets test it, Run the below script which inserts the data to Redis. </p><pre class="wp-block-syntaxhighlighter-code">import redisfrom redis.commands.json.path import Pathfrom redis.commands.json import JSONr = redis.Redis(host='localhost', port=6379, decode_responses=True)user = {    "id":"test_id",    "name":"some todo",    "description": "some description"}JSON(r).set("todos:test_id", Path.root_path(), user)</pre><figure class="wp-block-image size-large"><img alt="" class="wp-image-245" data-recalc-dims="1" decoding="async" height="507" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/06/image-37.png?resize=1447%2C507&amp;ssl=1" width="1447"/></figure><p class="wp-block-paragraph">Awesome isn’t. Now we have acheived the write through cache.</p><p class="wp-block-paragraph">Please try out the code: <a href="https://github.com/syedjaferk/redis-cache">https://github.com/syedjaferk/redis-cache</a></p><h4 class="wp-block-heading">Advantages:</h4><ol class="wp-block-list"><li><strong>Data Consistency</strong>: Data in the cache is always consistent with the data in the main memory or disk, reducing the risk of data loss.</li><li><strong>Simpler Design</strong>: Error recovery and cache coherence mechanisms are simpler since the data is always in sync.</li><li><strong>Predictable Latency</strong>: Since writes are immediately propagated to the main storage, the system’s behavior is more predictable.</li></ol><h4 class="wp-block-heading">Disadvantages:</h4><ol class="wp-block-list"><li><strong>Higher Latency for Writes</strong>: Each write operation has to wait until it is confirmed by the main memory or disk, leading to slower write performance.</li><li><strong>Increased Bandwidth Usage</strong>: Writing every update to both the cache and main storage can result in higher bandwidth usage.</li></ol><h4 class="wp-block-heading">Scenarios to Use:</h4><ol class="wp-block-list"><li><strong>Critical Data Integrity</strong>: Applications where data integrity is crucial, such as financial systems or database management systems.</li><li><strong>Simpler Consistency Management</strong>: Systems where simpler consistency models are preferred over performance.</li><li><strong>High Read-to-Write Ratio</strong>: Workloads where reads are much more frequent than writes, reducing the performance impact of write latency.</li></ol>
