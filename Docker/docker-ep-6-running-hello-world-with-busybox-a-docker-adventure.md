<p class="wp-block-paragraph">Once upon a time in the city of Athipati, there was a young coder named Arivanandham. Arivanandham had recently heard whispers of a magical tool called Docker, which promised to simplify the process of running applications. Eager to learn more, <strong>Arivanandham</strong> decided to embark on a quest—a quest to run the famous “Hello, World!” using the mysterious BusyBox Docker image.</p><p class="wp-block-paragraph">Today, we’re going to take our first step by creating and running a container. And what better way to start than with a tiny yet powerful image called BusyBox? Let’s dive in and explore how to run our first container using BusyBox.</p><h3 class="wp-block-heading"><strong>Step 1: Discovering BusyBox on Docker Hub</strong></h3><p class="wp-block-paragraph">Our journey begins at the Docker Hub, the vast library of images ready to be transformed into containers. Let’s search for “BusyBox” on Docker Hub.</p><p class="wp-block-paragraph">Upon searching, you’ll find the official BusyBox repository at the top. BusyBox is renowned for its compact size—about 1 megabyte—which makes it an excellent choice for quick downloads and speedy container spins.</p><figure class="wp-block-image size-large"><img alt="" class="wp-image-1067" data-recalc-dims="1" decoding="async" height="410" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/08/image-42.png?resize=1901%2C410&amp;ssl=1" width="1901"/></figure><h3 class="wp-block-heading"><strong>Step 2: Exploring BusyBox Tags</strong></h3><p class="wp-block-paragraph">Before we proceed, let’s check out the <strong>Tags</strong> tab on the BusyBox page. Tags represent different versions of the image. We’re going to pick <strong>tag 1.36</strong> for our container. This specific tag will be our guide in this Docker adventure.</p><figure class="wp-block-image size-large"><img alt="" class="wp-image-1069" data-recalc-dims="1" decoding="async" height="379" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/08/image-43.png?resize=1031%2C379&amp;ssl=1" width="1031"/></figure><h3 class="wp-block-heading"><strong>Step 3: Setting Up Your Docker Environment</strong></h3><p class="wp-block-paragraph">To start, we need to open a terminal. If you’re on Docker for Mac, Docker for Windows, or Linux, you can simply open your default terminal. If you’re using Docker Toolbox, open the Docker Quickstart Terminal.</p><h3 class="wp-block-heading"><strong>Step 4: Checking Local Images</strong></h3><p class="wp-block-paragraph">When you instruct Docker to create a container, it first checks your local system to see if the image is already available. Let’s verify what images we currently have:</p><pre class="wp-block-syntaxhighlighter-code">docker images</pre><p class="wp-block-paragraph">If this is your first time, you’ll see that there are no images available yet. But don’t worry; we’re about to change that.</p><figure class="wp-block-image size-large"><img alt="" class="wp-image-1075" data-recalc-dims="1" decoding="async" height="264" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/08/image-44.png?resize=1919%2C264&amp;ssl=1" width="1919"/></figure><h3 class="wp-block-heading"><strong>Step 5: Running Your First Container</strong></h3><p class="wp-block-paragraph">Now, let’s run our first container! We’ll use the <code>docker run</code> command, specifying the BusyBox image and tag 1.36. We’ll also tell Docker to execute a simple command: <code>echo "Hello, World!"</code>.</p><pre class="wp-block-syntaxhighlighter-code">docker run busybox:1.36 echo "Hello, World!"</pre><figure class="wp-block-image size-large"><img alt="" class="wp-image-1077" data-recalc-dims="1" decoding="async" height="264" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/08/image-45.png?resize=1919%2C264&amp;ssl=1" width="1919"/></figure><p class="wp-block-paragraph">Here’s what happens next:</p><ul class="wp-block-list"><li>Docker checks for the BusyBox 1.36 image locally.</li><li>If it’s not found, Docker will download the image from the remote repository.</li><li>Once the image is downloaded, Docker creates and runs the container.</li></ul><p class="wp-block-paragraph">And just like that, you should see the terminal output:</p><pre class="wp-block-syntaxhighlighter-code">Hello, World!</pre><p class="wp-block-paragraph">Congratulations! You’ve just run your first Docker container.</p><h3 class="wp-block-heading"><strong>Step 6: Verifying the Image Download</strong></h3><p class="wp-block-paragraph">Let’s run the <code>docker images</code> command again:</p><pre class="wp-block-syntaxhighlighter-code">docker images</pre><p class="wp-block-paragraph">You’ll now see the BusyBox 1.36 image listed. The image has a unique ID, confirming that it’s stored locally on your system.</p><figure class="wp-block-image size-large"><img alt="" class="wp-image-1079" data-recalc-dims="1" decoding="async" height="264" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/08/image-46.png?resize=1919%2C264&amp;ssl=1" width="1919"/></figure><h3 class="wp-block-heading"><strong>Step 7: Running the Container Again</strong></h3><p class="wp-block-paragraph">Now that we have the BusyBox image locally, let’s run the same container again:</p><pre class="wp-block-syntaxhighlighter-code">docker run busybox:1.36 echo "Hello, World!"</pre><p class="wp-block-paragraph">This time, notice how quickly the command executes. Docker uses the local image, skipping the download step, and instantly spins up the container.</p><figure class="wp-block-image size-large"><img alt="" class="wp-image-1081" data-recalc-dims="1" decoding="async" height="264" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/08/image-47.png?resize=1919%2C264&amp;ssl=1" width="1919"/></figure><h3 class="wp-block-heading"><strong>Step 8: Exploring the Container’s File System</strong></h3><p class="wp-block-paragraph">Let’s try something new. We’ll list all the contents in the root directory of the BusyBox container:</p><pre class="wp-block-syntaxhighlighter-code">docker run busybox:1.36 ls /</pre><p class="wp-block-paragraph">You’ll see Docker output the list of all directories and files at the root level of the container.</p><h3 class="wp-block-heading"><strong>Step 9: Running a Container in Interactive Mode</strong></h3><p class="wp-block-paragraph">To dive deeper, we can run the container in an interactive mode, which allows us to interact with the container as if it were a tiny, isolated Linux system. We’ll use the <code>-i</code> (interactive) and <code>-t</code> (pseudo-TTY) flags:</p><pre class="wp-block-syntaxhighlighter-code">docker run -it busybox:1.36</pre><p class="wp-block-paragraph">Now you’re inside the container! Try running commands like <code>ls</code> to see the contents. You can even create a new file:</p><pre class="wp-block-syntaxhighlighter-code">touch a.txtls</pre><p class="wp-block-paragraph">You’ll see <code>a.txt</code> listed in the output. To exit the container, simply type <code>exit</code>.</p><h3 class="wp-block-heading"><strong>Step 10: Understanding Container Lifecycle</strong></h3><p class="wp-block-paragraph">It’s important to note that once you exit a container, it shuts down. If you run the container again using the same command, Docker spins up a brand-new instance. The file you created earlier (<code>a.txt</code>) won’t be there because each container instance is ephemeral, meaning it doesn’t retain data from previous runs unless you explicitly save it.</p><p class="wp-block-paragraph">And there you have it! You’ve successfully created, explored, and understood your first Docker container using the BusyBox image. This is just the beginning of what you can achieve with Docker. As you continue your journey, you’ll discover how containers can simplify development, testing, and deployment, all while keeping your environment clean and isolated.</p>
