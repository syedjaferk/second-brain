<p class="wp-block-paragraph">In the bustling town of Tambaram, there was a famous factory known for its delicious cookies. This factory had a unique and modern way of making and distributing its cookies, using a system inspired by Docker’s architecture.</p><h4 class="wp-block-heading">The Recipe Registry</h4><p class="wp-block-paragraph">At the heart of the cookie-making process was the <strong>Recipe Registry</strong>, a giant digital library that stored all the cookie recipes. This registry was like a magical cookbook, holding secrets to every type of cookie imaginable: chocolate chip, oatmeal raisin, and even double fudge delight.</p><ul class="wp-block-list"><li><strong>Purpose</strong>: The Recipe Registry ensured that everyone had access to the latest and greatest recipes. Bakers from all around the world could upload new recipes or download existing ones to make their own cookies.</li></ul><figure class="wp-block-image size-large"><img alt="" class="wp-image-1057" data-recalc-dims="1" decoding="async" height="503" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/08/image-38.png?resize=772%2C503&amp;ssl=1" width="772"/></figure><h4 class="wp-block-heading">The Cookie Repository</h4><p class="wp-block-paragraph">Each type of cookie had its own <strong>Cookie Repository</strong> within the Recipe Registry. These repositories were specialized sections where all the different variations of a particular cookie recipe were stored.</p><ul class="wp-block-list"><li><strong>Example</strong>: The chocolate chip cookie repository contained recipes for classic, vegan, gluten-free, and extra gooey versions. Each version was labeled with a tag, like <code>classic</code>, <code>vegan</code>, or <code>gooey</code>.</li></ul><figure class="wp-block-image size-large"><img alt="" class="wp-image-1058" data-recalc-dims="1" decoding="async" height="503" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/08/image-39.png?resize=772%2C503&amp;ssl=1" width="772"/></figure><h4 class="wp-block-heading">The Image: A Perfect Cookie Dough</h4><p class="wp-block-paragraph">In the factory, the term “Image” referred to the perfect <strong>cookie dough</strong> that was ready to be baked into cookies. Each image was a complete package containing the recipe, ingredients, and instructions needed to make the cookies.</p><ul class="wp-block-list"><li><strong>Characteristics</strong>: Just like a Docker image, the cookie dough was consistent and repeatable. No matter how many times you used the recipe, you always got the same delicious dough, ready to be baked.</li></ul><figure class="wp-block-image size-large"><img alt="" class="wp-image-1060" data-recalc-dims="1" decoding="async" height="449" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/08/image-40.png?resize=739%2C449&amp;ssl=1" width="739"/></figure><h4 class="wp-block-heading">The Container: Freshly Baked Cookies</h4><p class="wp-block-paragraph">Once the cookie dough was prepared, it was placed into a <strong>Container</strong>, representing a batch of freshly baked cookies. Each container was like a magical oven that turned the dough into cookies.</p><ul class="wp-block-list"><li><strong>Isolation</strong>: Each container baked cookies independently, ensuring that the flavor and quality were perfect every time. Bakers could create multiple containers from the same dough image, producing countless batches of cookies.</li></ul><figure class="wp-block-image size-large"><img alt="" class="wp-image-1061" data-recalc-dims="1" decoding="async" height="449" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/08/image-41.png?resize=739%2C449&amp;ssl=1" width="739"/></figure><h4 class="wp-block-heading">The Cookie Delivery System</h4><p class="wp-block-paragraph">With the help of the Recipe Registry, Cookie Repository, Images, and Containers, the factory had an efficient <strong>Cookie Delivery System</strong>. This system allowed the factory to distribute its cookies all over Tambaram and beyond.</p><ul class="wp-block-list"><li><strong>Scalability</strong>: If a bakery needed more cookies, they simply created more containers using the same dough image, ensuring everyone had enough cookies to enjoy.</li></ul><p class="wp-block-paragraph">Let’s try directly in to the concepts,</p><h3 class="wp-block-heading">Registry</h3><ul class="wp-block-list"><li><strong>Definition</strong>: A Docker Registry is a storage and content delivery system that holds Docker images.</li><li><strong>Purpose</strong>: It is used to manage where Docker images are stored and distributed from.</li><li><strong>Examples</strong>: Docker Hub (the default public registry), Amazon ECR, Google Container Registry, and Azure Container Registry.</li><li><strong>Functionality</strong>: Registries can be public or private. They store Docker images and provide an interface to push (upload) or pull (download) these images to and from repositories.</li></ul><figure class="wp-block-image size-large"><img alt="" class="wp-image-1042" data-recalc-dims="1" decoding="async" height="843" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/08/image-35.png?resize=1919%2C843&amp;ssl=1" width="1919"/></figure><p class="wp-block-paragraph">Docker Hub is the default public registry used by Docker. Here are examples of Docker Hub registry links:</p><ul class="wp-block-list"><li><strong>Official Image</strong>: <code>docker pull nginx</code></li></ul><ul class="wp-block-list"><li>Link: <a data-proofer-ignore="" href="#">https://hub.docker.com/_/nginx</a></li></ul><p class="wp-block-paragraph"><strong>Community Image</strong>: <code>docker pull username/repository:tag</code></p><ul class="wp-block-list"><li>Link: <a data-proofer-ignore="" href="#">https://hub.docker.com/r/username/repository</a> (replace <code>username/repository</code> with the actual user and repository name)</li></ul><h3 class="wp-block-heading">Repository</h3><ul class="wp-block-list"><li><strong>Definition</strong>: A Docker Repository is a collection of related Docker images, usually providing different versions of the same application or service.</li><li><strong>Purpose</strong>: Repositories organize and manage multiple images of an application or service.</li><li><strong>Structure</strong>: A repository may contain multiple tagged versions of an image. For example, <code>myapp:latest</code> and <code>myapp:v1.0</code> might be two tags in the same repository.</li><li><strong>Functionality</strong>: Users can push images to a repository and pull images from a repository. Tags are used to differentiate between different versions of an image.</li></ul><p class="wp-block-paragraph"><strong>Official Repositories</strong></p><ul class="wp-block-list"><li><strong>Nginx</strong>:<ul class="wp-block-list"><li>Command: <code>docker pull nginx:latest</code></li><li>Repository Link: <a data-proofer-ignore="" href="#">https://hub.docker.com/_/nginx</a></li></ul></li><li><strong>Ubuntu</strong>:<ul class="wp-block-list"><li>Command: <code>docker pull ubuntu:latest</code></li><li>Repository Link: <a data-proofer-ignore="" href="#">https://hub.docker.com/_/ubuntu</a></li></ul></li></ul><p class="wp-block-paragraph"><strong>Community Repositories</strong></p><ul class="wp-block-list"><li><strong>Node.js (Official Node.js Images)</strong>:<ul class="wp-block-list"><li>Command: <code>docker pull node:latest</code></li><li>Repository Link: <a data-proofer-ignore="" href="#">https://hub.docker.com/_/node</a></li></ul></li><li><strong>Jenkins (Community Image)</strong>:<ul class="wp-block-list"><li>Command: <code>docker pull jenkins/jenkins:lts</code></li><li>Repository Link: <a data-proofer-ignore="" href="#">https://hub.docker.com/r/jenkins/jenkins</a></li></ul></li></ul><p pull username/repository:tag</code></li><li>Repository Link: <a data-proofer-ignore="" href="#">https://hub.docker.com/r/username/repository</a> (replace <code>username/repository</code> with the actual user and repository name)</li></ul></li></ul><figure class="wp-block-image size-large"><img alt="" class="wp-image-1041" data-recalc-dims="1" decoding="async" height="540" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/08/image-34.png?resize=1913%2C540&amp;ssl=1" width="1913"/></figure><h3 class="wp-block-heading">Images</h3><ul class="wp-block-list"><li><strong>Definition</strong>: A Docker Image is a lightweight, standalone, executable package that includes everything needed to run a piece of software: code, runtime, libraries, environment variables, and configuration files.</li><li><strong>Purpose</strong>: Images are used to create containers. They provide a portable and consistent runtime environment.</li><li><strong>Immutability</strong>: Images are immutable; once created, they do not change. If updates are needed, a new image version is created.</li><li><strong>Layers</strong>: Images are built up from a series of layers, where each layer represents an instruction in the image’s Dockerfile.</li></ul><p class="wp-block-paragraph">For example, Dockerfile will comprises of the layers of instructions. <a href="https://hub.docker.com/layers/library/postgres/12.20-bullseye/images/sha256-2092f4af9ad9fff76e8d0b7c04d8c62b561e44c21a850d4a028124426046f6fa?context=explore">https://hub.docker.com/layers/library/postgres/12.20-bullseye/images/sha256-2092f4af9ad9fff76e8d0b7c04d8c62b561e44c21a850d4a028124426046f6fa?context=explore</a></p><p class="wp-block-paragraph">Sample dockerfile for postgres, <a href="https://github.com/docker-library/postgres/blob/805329e7a64fad212a5d4b07abd11238a9beab75/17/bookworm/Dockerfile">https://github.com/docker-library/postgres/blob/805329e7a64fad212a5d4b07abd11238a9beab75/17/bookworm/Dockerfile</a></p><figure class="wp-block-image size-large"><img alt="" class="wp-image-1046" data-recalc-dims="1" decoding="async" height="364" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/08/image-36.png?resize=1895%2C364&amp;ssl=1" width="1895"/></figure><h3 class="wp-block-heading">Containers</h3><ul class="wp-block-list"><li><strong>Definition</strong>: A Docker Container is a runnable instance of a Docker image. It is a lightweight, standalone, and executable package of software that includes everything needed to run it.</li><li><strong>Purpose</strong>: Containers provide a consistent environment for applications, allowing them to run reliably regardless of where they are deployed.</li><li><strong>Isolation</strong>: Containers are isolated from each other and the host system, but they can communicate with each other through well-defined channels.</li><li><strong>Lifecycle</strong>: Containers can be created, started, stopped, moved, or deleted using Docker commands.</li></ul><figure class="wp-block-image size-large"><img alt="" class="wp-image-1053" data-recalc-dims="1" decoding="async" height="249" loading="lazy" src="https://i0.wp.com/parottasalna.com/wp-content/uploads/2024/08/image-37.png?resize=1867%2C249&amp;ssl=1" width="1867"/></figure><h3 class="wp-block-heading">Relationship Between Concepts</h3><ul class="wp-block-list"><li><strong>Registry and Repository</strong>: A Docker registry can host multiple repositories. Each repository can contain multiple images with different tags.</li><li><strong>Repository and Images</strong>: A repository serves as a namespace for images. For example, <code>myrepo/myapp</code> can contain different image tags like <code>v1.0</code>, <code>v2.0</code>, etc.</li><li><strong>Images and Containers</strong>: Containers are running instances of images. You can run multiple containers from the same image.</li></ul><p class="wp-block-paragraph"></p>
