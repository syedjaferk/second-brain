<p class="wp-block-paragraph">Alex now knows the basics, but it’s time to get their hands dirty by writing an actual Dockerfile.</p><h4 class="wp-block-heading">The <code>FROM</code> Instruction: Choosing the Foundation</h4><p class="wp-block-paragraph">The first thing Alex learns is the <code>FROM</code> instruction, which sets the base image for their container. It’s like choosing the foundation for a house.</p><ul class="wp-block-list"><li><strong>Purpose:</strong><ul class="wp-block-list"><li>The <code>FROM</code> instruction initializes a new build stage and sets the Base Image for subsequent instructions.</li></ul></li><li><strong>Choosing a Base Image:</strong><ul class="wp-block-list"><li>Alex decides to use a Python base image for their application. They learn that <code>python:3.9-slim</code> is a lightweight version, saving space and reducing the size of the final image.</li></ul></li></ul><pre class="wp-block-syntaxhighlighter-code">FROM python:3.9-slim</pre><p class="wp-block-paragraph"><em>Example</em>: Think of <code>FROM</code> as picking the type of bread for your sandwich. Do you want white, whole wheat, or maybe something gluten-free? Your choice sets the tone for the rest of the recipe.</p><p class="wp-block-paragraph"></p><h4 class="wp-block-heading">The <code>LABEL</code> Instruction: Adding Metadata (Optional)</h4><p class="wp-block-paragraph">Next, Alex discovers the <code>LABEL</code> instruction. While optional, it’s a good practice to include metadata about the image.</p><ul class="wp-block-list"><li><strong>Purpose:</strong><ul class="wp-block-list"><li>The <code>LABEL</code> instruction adds metadata like version, description, or maintainer information to the image.</li></ul></li><li><strong>Example:</strong><ul class="wp-block-list"><li>Alex decides to add a maintainer label:</li></ul></li></ul><pre class="wp-block-syntaxhighlighter-code">LABEL maintainer="alex@example.com"</pre><p class="wp-block-paragraph"><em>Story Note</em>: This is like writing your name on a sandwich wrapper, so everyone knows who made it and what’s inside.</p><h4 class="wp-block-heading">The <code>RUN</code> Instruction: Building the Layers</h4><p class="wp-block-paragraph">The <code>RUN</code> instruction is where Alex can execute commands inside the image, such as installing dependencies.</p><ul class="wp-block-list"><li><strong>Purpose:</strong><ul class="wp-block-list"><li>The <code>RUN</code> instruction runs any commands in a new layer on top of the current image and commits the results.</li></ul></li><li><strong>Example:</strong><ul class="wp-block-list"><li>To install the Flask framework, Alex writes:</li></ul></li></ul><pre class="wp-block-syntaxhighlighter-code">RUN pip install flask</pre><p class="wp-block-paragraph">They also learn to combine commands to reduce layers:</p><pre class="wp-block-syntaxhighlighter-code">RUN apt-get update &amp;&amp; apt-get install -y curl</pre><p class="wp-block-paragraph"><em>Story Note</em>: Imagine slicing tomatoes and cheese for your sandwich and placing them carefully on top. Each ingredient (command) adds a layer of flavor.</p><h4 class="wp-block-heading">The <code>COPY</code> and <code>ADD</code> Instructions: Bringing in Ingredients</h4><p class="wp-block-paragraph">Now, Alex needs to bring their application code into the container, which is where the <code>COPY</code> and <code>ADD</code> instructions come into play.</p><ul class="wp-block-list"><li><strong>COPY:</strong><ul class="wp-block-list"><li>The <code>COPY</code> instruction copies files or directories from the host filesystem into the container’s filesystem.</li></ul></li><li><strong>ADD:</strong><ul class="wp-block-list"><li>The <code>ADD</code> instruction is similar to <code>COPY</code> but with additional features, like extracting compressed files.</li></ul></li><li><strong>Example:</strong><ul class="wp-block-list"><li>Alex copies their application code into the container:</li></ul></li></ul><pre class="wp-block-syntaxhighlighter-code">COPY . /app</pre><p class="wp-block-paragraph"><em>Story Note</em>: This is like moving ingredients from your fridge (host) to the counter (container) where you’re preparing the sandwich.</p><h4 class="wp-block-heading">The <code>WORKDIR</code> Instruction: Setting the Workspace</h4><p class="wp-block-paragraph">Alex learns that setting a working directory makes it easier to manage paths within the container.</p><ul class="wp-block-list"><li><strong>Purpose:</strong><ul class="wp-block-list"><li>The <code>WORKDIR</code> instruction sets the working directory for subsequent instructions.</li></ul></li><li><strong>Example:</strong><ul class="wp-block-list"><li>Alex sets the working directory to <code>/app</code>:</li></ul></li></ul><pre class="wp-block-syntaxhighlighter-code">WORKDIR /app</pre><p class="wp-block-paragraph"><em>Story Note</em>: This is like setting up a designated area on your counter where you’ll assemble your sandwich—keeping everything organized.</p><h4 class="wp-block-heading">The <code>CMD</code> and <code>ENTRYPOINT</code> Instructions: The Final Touch</h4><p class="wp-block-paragraph">Finally, Alex learns how to define the default command that will run when the container starts.</p><ul class="wp-block-list"><li><strong>CMD:</strong><ul class="wp-block-list"><li>Provides defaults for an executing container, but can be overridden.</li></ul></li><li><strong>ENTRYPOINT:</strong><ul class="wp-block-list"><li>Configures a container that will run as an executable, making it difficult to override.</li></ul></li><li><strong>Example:</strong><ul class="wp-block-list"><li>Alex uses <code>CMD</code> to specify the command to start their Flask app:</li></ul></li></ul><pre class="wp-block-syntaxhighlighter-code">CMD ["python", "app.py"]</pre><p class="wp-block-paragraph"><em>Story Note</em>: Think of <code>CMD</code> as the final step in making your sandwich—like deciding to add a toothpick to hold everything together before serving.</p><p class="wp-block-paragraph">Below is an example Dockerfile of a flask application, </p><pre class="wp-block-syntaxhighlighter-code"># Use an official Python runtime as a parent imageFROM python:3.9-slim# Set the working directory in the containerWORKDIR /app# Copy the current directory contents into the container at /appCOPY . /app# Install any needed packages specified in requirements.txtRUN pip install --no-cache-dir -r requirements.txt# Make port 80 available to the world outside this containerEXPOSE 80# Define environment variableENV NAME World# Run app.py when the container launchesCMD ["python", "app.py"]</pre><h3 class="wp-block-heading">Breakdown of the Dockerfile:</h3><ol class="wp-block-list"><li><strong>FROM python:3.9-slim</strong>:<ul class="wp-block-list"><li>This line specifies the base image. In this case, it uses a slim version of Python 3.9, which is lightweight and sufficient for a simple Flask application.</li></ul></li><li><strong>WORKDIR /app</strong>:<ul class="wp-block-list"><li>This sets the working directory inside the container to <code>/app</code>. All subsequent commands will be run inside this directory.</li></ul></li><li><strong>COPY . /app</strong>:<ul class="wp-block-list"><li>This copies everything from your current directory on the host machine into the <code>/app</code> directory inside the container.</li></ul></li><li><strong>RUN pip install –no-cache-dir -r requirements.txt</strong>:<ul class="wp-block-list"><li>This installs the necessary Python packages listed in the <code>requirements.txt</code> file. The <code>--no-cache-dir</code> option reduces the image size by not caching the downloaded packages.</li></ul></li><li><strong>EXPOSE 80</strong>:<ul class="wp-block-list"><li>This makes port 80 available for external access. It’s where the Flask application will listen for incoming requests.</li></ul></li><li><strong>ENV NAME World</strong>:<ul class="wp-block-list"><li>This sets an environment variable <code>NAME</code> to “World”. You can access this variable in your Python code.</li></ul></li><li><strong>CMD [“python”, “app.py”]</strong>:<ul class="wp-block-list"><li>This tells the container to run the <code>app.py</code> file using Python when it starts.</li></ul></li></ol><h3 class="wp-block-heading">Example Flask Application (<code>app.py</code>):</h3><p class="wp-block-paragraph">To complete the example, here’s a simple Flask application you can use:</p><pre class="wp-block-syntaxhighlighter-code">from flask import Flaskimport osapp = Flask(__name__)@app.route('/')def hello():    name = os.getenv('NAME', 'World')    return f'Hello, {name}!'if __name__ == "__main__":    app.run(host='0.0.0.0', port=80)</pre><h3 class="wp-block-heading">Example <code>requirements.txt</code>:</h3><p class="wp-block-paragraph">And here’s the <code>requirements.txt</code> file listing the dependencies for the Flask app:</p><pre class="wp-block-syntaxhighlighter-code">Flask==2.0.3</pre><h3 class="wp-block-heading">Building and Running the Docker Image:</h3><ol class="wp-block-list"><li>Build the Docker image using the Dockerfile:</li></ol><pre class="wp-block-syntaxhighlighter-code">docker build -t my-flask-app .</pre><p class="wp-block-paragraph">2. Run the Docker container:</p><pre class="wp-block-syntaxhighlighter-code">docker run -p 4000:80 my-flask-app</pre><ul class="wp-block-list"><li>This maps port 4000 on your host machine to port 80 in the container.</li></ul><p class="wp-block-paragraph">Open your browser and go to <code>http://localhost:4000</code>, and you should see “Hello, World!” displayed on the page.</p><p class="wp-block-paragraph">You can customize the <code>ENV NAME</code> in the Dockerfile or by passing it as an argument when running the container:</p><pre class="wp-block-syntaxhighlighter-code">docker run -p 4000:80 -e NAME=Alex my-flask-app</pre><p class="wp-block-paragraph">This will display “Hello, Alex!” instead.</p>
